# cro-experiment-design

그루밍이 끝난 가설의 **노션 실험설계서를 실험 세팅이 가능한 수준으로 구체화하는** 실험 설계 플러그인입니다. CRO 코칭에서 그루밍이 끝나고 실험 설계에 착수하는 시점에 사용합니다. 런칭 후 모니터링·종료 판정·결과 보고서까지 동봉 스킬로 이어집니다.

> **실험설계서 구체화란** — 그루밍 계약(`hg-output-contract.md`)이 명시적으로 범위 밖에 남긴 빈칸을 채우는 작업입니다. Variant 최종 문구·시안, 지표 3층, 측정 가능성, 타겟·트리거, 샘플사이즈·실험 기간, 분배·종료 기준 — 그루밍이 "무엇을 실험할지"를 정했다면, 이 플러그인은 "어떻게 세팅할지"를 정합니다.

## 무엇을 하나요

**수행 모드** (참가자용) — 가설(실험) 1건씩:

1. **인테이크 정규화 + 그루밍 완료 게이트** — 입력을 정규화하고, 그루밍이 실제로 끝났는지 7항목으로 점검합니다. 결손이 있으면 이 스킬이 채우지 않고 **해당 항목만 hg 스킬의 대응 STEP으로 라우팅**합니다 (재그루밍 전체 재수행이 아닙니다)
2. **Variant 구체화** — 대조군·실험군 **2개 이상**을 변경 화면 명세 4슬롯(헤드라인/이미지/CTA/노출 위치)으로 구체화하고, 시안 제작 요청과 착지를 돕습니다
3. **지표 3층 확정** — Primary **정확히 1개** + Secondary + Guardrail **1~2개**
4. **측정 가능성 점검** — 미태깅 지표는 태깅 요청 명세 4항목 + 조치 기한으로 명시합니다
5. **타겟·트리거** — Trigger Point(노출 정의)가 지표 분모와 일치하는지 확인합니다
6. **샘플사이즈·실험 기간 계산** — 입력값 표 → 공식 대입 → 결과 → **28일 실현성 판정**까지. 28일을 넘으면 MDE 상향을 포함한 조정 순서를 적용합니다
7. **분배·종료 기준** — 분배 비율(합 100%)·조기 종료 조건·최소 관찰 기간·병행 릴리즈 확인
8. **노션 + repo 착지** — 노션 실험설계서 페이지 갱신 블록과 git 저장소의 EXP 파일 블록, 속성 변경 안내를 출력합니다

**(선택) variant 시안 AI 초안 생성** — E2에서 시안이 없을 때, 참가자 본인 API key와 대조군 스크린샷이 있으면 페어 스킬 `cro-variant-mockup`으로 라우팅해 AI 초안(목업)을 만들 수 있습니다. key가 없으면 종전대로 제작 요청 명세 경로로 진행하며, 세션을 막지 않습니다. 자세한 내용은 아래 절을 참고하세요.

**리뷰 모드** (코치용) — "실험설계 리뷰"라고 말하면 진입: 판정 표(A군 + B군 항목) + 샘플사이즈 검산 재현 + 보완 가이드.

## 시작하기

클로드에게 "실험설계서 구체화 시작"이라 말하고 **노션 실험설계서 페이지 본문을 붙여넣으면** 됩니다.

## 데이터 파일 규약

`skills/cro-experiment-design/data/goal-tree-nodes.json`은 **가상 데모 서비스의 샘플**입니다 — 실제 프로젝트는 같은 스키마로 자기 골트리 파일을 만들어 그 경로를 알려주시면 이 스킬이 그것을 씁니다. 동봉 샘플은 형식 참고용일 뿐이며, 샘플 수치를 실제 판단(Baseline·Target·R 노드 선택)에 쓰지 않습니다 — 실측값은 Amplitude 실쿼리 또는 사용자 입력으로만 채웁니다.

## 이 플러그인이 하지 않는 것

- 그루밍 재수행·ICE 재산정·Uplift 재계산·PSR/Baseline/Target 수정 → **`cro-hypothesis-grooming` 소관**
- 런칭 후 모니터링·종료 판정 → 동봉 스킬 `cro-experiment-monitoring` 소관
- 종료 결정·So Next 확정·기록 블록 → 동봉 스킬 `cro-experiment-decision` 소관 / why·배운 것·가설 검증 여부·후속 반영 → 동봉 스킬 `cro-experiment-report`가 채웁니다
- **디자이너 최종 시안** 제작 대행 → 여전히 하지 않습니다. 명세 작성·제작 요청·받은 것의 착지까지만 합니다. **AI 초안(목업) 생성 보조**는 페어 스킬 `cro-variant-mockup`이 하며 — 참가자 본인 API key가 있어야 하는 **선택 기능**이고, 산출물은 항상 `AI 초안 — 검토 필요`로만 착지합니다
- 노션 자동 기입(붙여넣기 왕복) → 갱신 블록을 출력할 뿐, 노션 페이지를 직접 쓰지 않습니다

## (선택) variant 시안 AI 초안 생성

E2(Variant 구체화)에서 시안이 없을 때, 참가자 본인 이미지 생성 API key와 대조군(control) 화면 스크린샷이 있으면 페어 스킬 `cro-variant-mockup`으로 AI 초안(목업)을 만들어 볼 수 있습니다. **key가 없어도 본체 기능은 전부 동작**하며, 이 경로는 세션을 막는 조건이 아닙니다.

1. **key 발급** — Gemini(권장, 무료 티어 있음): https://aistudio.google.com/apikey / OpenAI(대안, 결제수단 필요): https://platform.openai.com/api-keys
2. **`.env` 세팅** — `skills/cro-variant-mockup/scripts/.env.example`을 **작업 폴더**(클로드를 실행하는 폴더)에 `.env`로 복사한 뒤 발급받은 key를 채웁니다. `scripts/.env`에 둬도 찾지만, 플러그인을 업데이트하면 옛 버전 폴더에 남으므로 작업 폴더를 권장합니다. `.env`는 저장소에 커밋하지 않습니다.
3. **비용** — 장당 대략 몇 센트 수준 (제공자·모델·해상도에 따라 변동)
4. **게이트 5종** — ① PII 마스킹(실고객 정보가 보이는 스크린샷은 마스킹 전 외부 API로 보내지 않음) ② 한글 문구 검수(생성 이미지 문구를 확정 문구와 글자 단위로 대조) ③ 대조군 보존(명세가 지정하지 않은 영역 — 상태바·숫자·통계·CTA 등 — 이 조용히 바뀌지 않았는지 control과 나란히 대조) ④ AI 초안 표기(파일명·노션 캡션·E2 시안 행 세 곳 모두에 `AI 초안`과 provider/model 병기) ⑤ 디자인 절대 규칙(사용자가 지정한 디자인 가이드의 "예외 없이 금지" 규칙을 위반하면 착지 불가 — 2회 재생성 뒤에도 남으면 위반 영역 비움 초안, 명세가 지정한 위반은 표기 후 면제)
5. **디자인 가이드** — 자기 프로젝트의 디자인 가이드 문서 경로를 `.env`의 `DESIGN_GUIDE_PATH`에 적으면 거기 적힌 색·서체·절대 규칙을 그대로 적용합니다. 지정하지 않아도 중립 기본값(단색 강조색 1개·무채색 텍스트 3단계·카드 둥근 모서리 등)으로 동작합니다.
6. **동작 증명 원칙** — 가짜 키는 인증 오류까지만 확인해 줍니다. **준비 점검에서는 반드시 실키로 이미지 1장을 실제로 생성해 눈으로 확인**하세요 — "오류 없이 끝났다"는 "이미지를 받았다"를 의미하지 않습니다.

## 실험 모니터링·종료 판정 (`cro-experiment-monitoring`)

실험을 **런칭한 직후부터 종료 판정까지** 담당하는 동봉 스킬입니다. "실험 모니터링", "런칭했어요 확인해줘", "SRM 봐줘", "샘플 찼나요", "이겼나요", "실험 종료해도 되나요", "연장할까요" 같은 요청에 이 스킬이 나섭니다.

**입력** — 필수 2개 + 보조 1개: **노션 실험설계서 URL**, **Amplitude 대시보드 URL 또는 Experiment 설정 URL**, (보조) **런칭일**. 런칭일이 없으면 경과일·최소 관찰 기간·요일 주기 판정이 `확인 불가`로 남습니다.

**담당자가 세팅한 화면이 정본입니다** — 대시보드·실험 분석 화면의 지표 정의를 그대로 따르고, 설계서와 다른 점(전환창·군 수·배분·배타 조건 등)은 게이트로 막지 않고 리포트 끝 「참고」 1줄로만 남깁니다.

**기본 출력은 5블록 리포트입니다** — ① variant별 트래픽 ② 지표별 전환율·Amplitude 표시값(Primary·Guardrail·**Secondary 전부**, 화면에 없는 Secondary는 variant별 실쿼리로 채웁니다) ③ 유의성 ④ 진행률·종료 판단 ⑤ 이상 징후, 그리고 설계서↔세팅 차이가 있을 때만 마지막에 「참고」 1줄. **전체 표(상세)는 "상세로 보여줘"라고 요청할 때만** 냅니다.

**2모드** — 모드는 스킬이 정하지 않고 진행률 표의 숫자가 정합니다.
- **헬스**: 건수·전환율·SRM만 봅니다. 샘플 도달 전에는 리프트·p·승패 어휘를 **절대 보여주지 않습니다.**
- **판정**: 전 variant가 필요 n에 도달하고 최소 관찰 기간·요일 주기·SRM 정상 조건을 모두 채운 뒤에만 stat-sig 판정(`WIN`/`LOSE`/`INCONCLUSIVE`/`지속`/`실험 설계 잘못됨`)을 냅니다.

**하드 게이트 6종** — ① 접근 경로 확정(노션·Amplitude 각각 실제로 시도한 경로를 남기고, 실측 수치마다 출처를 붙인다) ② 화면 정본·매핑 기록(담당자가 세팅한 화면의 지표 정의를 그대로 기록하고, 설계서와 다른 점이 있어도 판정을 막지 않는다) ③ 피킹 게이트(스킬 자체가 계산하는 고정표본 통계는 필요 n 도달 전에는 쓰지 않되, Amplitude 화면이 표시하는 값은 도달 전에도 항상 인용한다) ④ SRM 우선(SRM 경보가 뜨면 판정 필드를 출력하지 않고 「실험 설계 잘못됨」으로 종착한다) ⑤ 램프업 구간 제외(램프업·설정 변경 구간의 관측치는 누적 n과 원표에서 뺀다) ⑥ PII 집계만(원천 PII는 어떤 표에도 옮기지 않고 위치만 말한다).

**산출물** — 인테이크·접근 경로 → 설계서 추출 → 대시보드 지표 매핑 → 헬스(variant 누적·헬스 체크·표시값) → 진행률·모드 확정 → 판정(판정 모드에서만) → 이상 징후 체크리스트. **기록물은 만들지 않습니다** — 화면에 리포트를 내고 끝냅니다. 어디에 남길지는 결과 보고서 단계가 정합니다.

**코치 리뷰 모드** — "모니터링 리뷰"라고 말하면 진입: 판정 항목 표 + 통계 검산 재현 결과. 채점 방식은 실험설계 리뷰와 동일합니다(Warning은 Pass로 카운트, 품질 점수 = Pass ÷ 판정 대상).

**이 스킬이 하지 않는 것**
- 기록물 생성 — 노션·EXP 파일 기입은 물론 붙여넣기 블록·기록 위치 안내도 만들지 않습니다
- Amplitude 실험 설정 변경(배분·variant·플래그·on/off)
- 조기 종료 결정 확정 (조건 도달 사실만 보고, 판단은 코치)
- 실험 설계값 수정·재계산(필요 n·MDE·Target·Baseline·종료 기준 → 본체 `cro-experiment-design`의 STEP 4/5로 라우팅)
- 결과 보고서 서술(why 3관점·So Next 확정) → 범위 밖
- Amplitude·노션 화면에서 버튼 클릭·설정 변경(읽기만)

**Amplitude MCP 연결** — 공식 MCP 서버를 등록합니다.

```
claude mcp add --transport http amplitude https://mcp.amplitude.com/mcp
```

등록 후 OAuth 인증 흐름을 따르고, **세션을 재시작**해야 새 MCP 서버의 도구가 인식됩니다. 연결이 안 돼 있어도 세션이 막히지 않고, Chrome으로 대시보드를 열어 읽는 경로로 동작합니다.

**시작 문구 예**
```
실험 모니터링 시작 — 노션 설계서 URL https://notion.so/... 대시보드 URL https://analytics.amplitude.com/...
```

## 실험 종료 의사결정 (`cro-experiment-decision`)

판정이 나온 실험을 **끝내도 되는지 확인하고, 끝났다는 사실을 어디에 남길지**까지 담당하는 동봉 스킬입니다. "실험 종료해도 되나요", "연장할까요", "끝내자", "결과 기록해줘", "C variant 내릴까요", "롤아웃 갈까요" 같은 요청에 이 스킬이 나섭니다.

**시작 문구 예**

```
실험 종료 판단해줘 — 노션 설계서 URL https://notion.so/... 앰플리튜드 화면값은 아래 붙여넣습니다
```

**준비물 3가지** — ① **노션 실험설계서 URL**(또는 본문 붙여넣기) ② **Amplitude Experiment 화면값**(방금 모니터링을 돌렸으면 그 리포트를 그대로 붙이면 됩니다) ③ **런칭일·종료 예정일**. 셋째가 없으면 예상 도달일과 연장 종료일 제안이 `확인 불가`로 남습니다.

**이럴 때 이렇게 됩니다**

| 지금 상태 | 스킬이 내는 것 |
|---|---|
| 필요 인원이 아직 안 모였다 | `지속` — 지금 몇 %인지, 지금 속도면 며칠 뒤 채워지는지. **이 상태에서는 「종료」로 넘어가지 않습니다** |
| 군별 인원 배분이 설계와 어긋나 있다 | 「실험 설계 잘못됨」 — 숫자가 예뻐도 결과를 쓰지 않고, 결과 칸은 `결과 불사용`입니다 |
| 필요 인원을 채웠고 유의성이 기준을 넘었다 | `WIN`/`LOSE`/`INCONCLUSIVE` 중 하나 + 어느 갈림길을 어떤 값으로 지났는지 |
| 판정 기준은 못 넘겼는데 지속 판단 기준은 넘었다 | 연장을 물어볼 두 가지 질문과, 늘린다면 새 종료일 후보 |
| 세 군 이상인데 한 군만 성적이 나쁘다 | 그 군만 내려도 되는지 확인할 세 가지 질문 |
| 결정을 이미 내렸다 | 붙여넣을 블록 세 개 (노션 · EXP 파일 · 상태 변경 안내) |

**결정은 여러분이 합니다** — 스킬이 채우는 것은 판정과 권고까지이고, `종료`/`연장`/`지속` 칸과 다음 갈래(`전면 반영`/`수정 후 재실험`/`폐기`/`연장`)를 고르는 칸은 **빈칸으로 나옵니다.** 어느 쪽인지 한 마디 주시면 그때 기록 블록이 만들어집니다. 늘릴지 말지는 지면이 며칠 더 묶이는지와 다음 실험 일정이 걸린 문제라, 그 비용은 팀만 압니다. **Primary에서 진 군은 반영 후보가 되지 않습니다** — 그 군의 가드레일 승은 다음 실험의 힌트로만 씁니다. 진 실험의 연장 기준은 유의성 충족이 아니라 「왜 졌는지 힌트」입니다.

**붙이는 곳 3군데** — ① **노션 실험설계서 4장** 「결과」·「후속 액션」 ② **repo EXP 파일**의 실행 기록·결과·다음 액션 줄 ③ **상태 값**(EXP `status`, 노션 진행상태, 실험 대장 README). 셋 다 **붙여넣기와 커밋은 직접** 하시면 됩니다.

**하지 않는 것**
- 노션·파일에 직접 쓰기, git commit — 블록만 만듭니다
- 피처 플래그 조작·배분 변경·variant 끄기·실험 종료 버튼 — 할 일 목록만 냅니다
- 필요 인원·MDE·종료 기준 고치기 → 본체 `cro-experiment-design`의 STEP 4/5
- 「왜 이겼나」·「배운 것」 서술 → 동봉 스킬 `cro-experiment-report`가 채웁니다
- 유의성 계산기 링크를 지어내는 것 — Amplitude 화면값이 먼저이고, 검산은 동봉 스크립트로 합니다

**코치 리뷰 모드** — 「종료 의사결정 리뷰」라고 말하면 판정 항목 표와 판정 재현 결과를 냅니다(채점 방식은 실험설계 리뷰와 같습니다).

## 실험 결과 보고서 (`cro-experiment-report`)

종료 의사결정이 끝난 뒤(또는 아직 끝나지 않았어도) **실험 1건의 결과 보고서 초안을 만들고, 받은 피드백을 반영해 다시 내는** 동봉 스킬입니다. "실험 결과 보고서 초안", "결과 보고서 써줘", "실험 결과 분석", "4장 채워줘", "왜 졌는지 정리해줘", "보고서 피드백 반영", "결과 리포트 v2", "노션 4장에 붙일 블록 만들어줘" 같은 요청에 이 스킬이 나섭니다.

**판정은 이 스킬이 만들지 않고 종료 의사결정에서 승계합니다.** 보고서가 하는 일은 그 판정 위에 **「왜」와 「다음」을 얹는 것**이고, 숫자가 마음에 들지 않는다고 판정을 다시 부르면 그 문서는 보고서가 아니라 사후 합리화가 됩니다.

**입력** — 필수 2개 + 보조 4개: **노션 실험설계서 URL**(또는 본문 붙여넣기), **Amplitude Experiment 설정 URL 또는 대시보드 URL**(또는 화면 값 붙여넣기). 보조는 종료 의사결정 기록 블록 · 재계산 구간 · 정성 자료 · 사전 조사 노트입니다. **설계서가 없으면 해석하지 않고 종료 경로로 닫습니다.**

**출력** — **붙여넣기 코드블록 2개 + 로컬 초안 파일 안내 1개**입니다.

| 무엇 | 어디에 붙나 | 형태 |
|---|---|---|
| 노션 실험설계서 4장 전문 | 참가자 정본 | 코드블록 1개 |
| repo EXP 파일의 **결과 보고서 소유 칸** | 실험 1건의 SSOT | 코드블록 1개 |
| 로컬 초안 파일 | 부록(표·출처·변경 이력)이 남는 자리 | 안내 표 — **파일을 쓰는 것은 사람입니다** |

**하드 게이트 7종** — ① 종료 확인(종료·결정이 확인되지 않으면 전 출력 상단에 `중간 리포트 — 판정 잠정` 라벨을 고정한다) ② 판정 정본 우선순위(종료 의사결정 확정 기록 > 계산값 > 화면 표시값) ③ 근거 태그 필수(`[실측]`·`[계산]`·`[해석]`·`[가정]`, 태그 없는 해석 문장은 출력하지 않는다) ④ 사전 선언 세그만 판정 ⑤ PII 집계만 ⑥ 배포 반영 ≠ 승(「Primary 승 AND Guardrail·Secondary 불하락」) ⑦ 읽기 전용.

**산출물** — 인테이크·접근 경로·보고서 라벨 → 설계값 전사 → 설계↔화면 매핑 → 실측·판정 수령 → 결과 유형 분류 → 유형별 분석 → 세그먼트·정성 → 조립 → 피드백 반영. 결과 유형은 판정에서 기계적으로 나옵니다 — `WIN`→**T1**, `LOSE`→**T2**, `INCONCLUSIVE`→**T3**, `실험 설계 잘못됨`→**T4**, `지속`이면 분류하지 않고 「중간 리포트」로 닫습니다. Primary와 Guardrail·Secondary의 방향이 어긋나면 유형 뒤에 혼합 플래그 **`M`**이 붙습니다.

**세그먼트 축은 스킬이 고정하지 않고 매번 묻습니다** — 후보는 설계서 사전 선언 구간 · 디바이스 · 신규/재방문 · 연령대 · 유입 경로 · 후속 퍼널 단계 여섯이고, **사전 선언 구간은 항상 포함**됩니다.

**코치 리뷰 모드** — 「결과 보고서 리뷰」라고 말하면 판정 항목 표와 리뷰 리포트 6구성을 냅니다(채점 방식은 실험설계 리뷰와 같습니다). **Critical이 하나라도 `Fail`이면 품질 등급과 무관하게 「이 보고서는 다시 봐야 한다」로 닫습니다.**

**이 스킬이 하지 않는 것**
- 종료·연장·지속 결정과 So Next 확정 — 종료 의사결정 소관이라 승계하거나 빈칸으로 둡니다
- 판정 흐름도의 재정의 — 인용만 하고 다시 그리지 않습니다
- 노션·EXP 파일 직접 기입과 git commit — 붙여넣을 블록을 만드는 데까지입니다
- 설계값 수정·재계산(필요 n·MDE·Target·Baseline·종료 기준) → 본체 `cro-experiment-design`
- 담당자 세팅 재감사 — 설계서와 화면의 차이는 기록만 합니다
- 정성조사의 실행 — 필요 여부 판정과 질문 후보까지이고, 조사는 범위 밖입니다
- 유의성 계산기 URL을 지어내는 것 — 값은 직접 돌려서 주시면 스크립트 계산값과 병기·검산해 드립니다

**시작 문구 예**

```
실험 결과 보고서 초안 — 노션 설계서 URL https://notion.so/... 앰플리튜드 실험 URL https://app.amplitude.com/experiment/...
```

**피드백 주는 법 — 코멘트는 5형으로 처리됩니다**

| 이렇게 주시면 | 이렇게 처리됩니다 |
|---|---|
| **숫자 정정** — "이 전환율이 다릅니다" | 출처를 다시 조회해 고칩니다. 재조회가 안 되면 붙여넣기 일시를 출처로 적고 고칩니다 |
| **해석 추가·수정** — "이 부분은 이렇게 보입니다" | **근거를 함께 주시면** `[해석]` + 행 번호, 근거가 없으면 `[가정]`으로 적습니다 |
| **분류 이의** — "이건 T2가 아니라 T3 아닌가요" | 판정과 유형은 유지하고, 대안 질문 세트로 **부록에 다시 실행**한 뒤 `[가정] 코치 확인 필요`를 붙입니다 |
| **구조** — "부록 순서를 바꿔주세요" | 부록은 자유롭게 바꾸고, **4장 구조는 바꾸지 않습니다** |
| **판정·결정 어휘 변경** — "p가 높으니 INCONCLUSIVE로 바꿔주세요" | **거부합니다** — 종료 의사결정과 계산값 소관입니다. 변경 이력에 `거부 — 판정은 dc 소관`으로 남깁니다 |

반영하면 **다음 버전 전문을 다시 냅니다** — 바뀐 부분만 내지 않습니다. 거부한 코멘트도 변경 이력에서 지우지 않습니다.

**사전 준비** — 모니터링·종료 의사결정 스킬과 같습니다. Amplitude MCP 연결은 선택이고, 연결이 안 돼 있어도 Chrome으로 화면을 열어 읽거나 값을 붙여넣는 경로로 동작합니다. 통계 계산은 모니터링 스킬의 `statsig.py`를 **경로로 호출**합니다(복사하지 않습니다) — 보정 옵션은 붙이지 않고 대조군 vs 각 실험군 1:1 비교를 p ≤ 0.05로 읽습니다.
