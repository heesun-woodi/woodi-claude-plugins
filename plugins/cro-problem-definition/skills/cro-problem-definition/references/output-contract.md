# 사용자 문제정의 — 출력 계약 (Output Contract)

> **용도**: 문제영역 선정 워크숍 직후 진행하는 **사용자 문제정의 라이브 세션(60~90분)**의 산출물 규격.
> **범위 주의**: 합성 인터뷰는 별도 스프린트로 이연 — 이 계약에 합성 인터뷰 섹션은 없습니다.

## 1. 산출물 구조 — 표 4종

라이브 세션에서 스킬이 대화에 출력하는 표는 아래 4종입니다. 참가자는 이 표를 복사해 워크숍 시트의 같은 이름 섹션에 붙입니다.

| 표 | 이름 | 언제 | 시트 이식 |
|---|---|---|---|
| **T1** | 워크스루 Fact 로그 | STEP 1 (전사 확인 후) | ✗ 대화에만 (진단 근거) |
| **T2** | BIAS 27항목 판정 | STEP 2 | ✗ 대화에만 (판정 과정) |
| **T3** | CRO 체크리스트 판정 | STEP 3 (구간 B는 생략 가능) | ✗ 대화에만 (판정 과정) |
| **T4** | **문제정의 리스트** | STEP 5 | **✅ 유일한 시트 산출물** |

**T1~T3는 시트에 옮기지 않습니다.** 진단 과정은 대화에 남고, 그 결과로 나온 문제만 T4로 시트에 착지합니다. T4의 `BIAS 항목`·`CRO 항목` 열이 "이 문제가 어느 체크에 걸렸는가"를 담으므로 판정 표 자체는 시트에 없어도 추적이 됩니다.

**시트 탭 구성** (권장 워크숍 시트 구성):

| 탭 | 내용 |
|---|---|
| `구간A_문제정의` / `구간B_문제정의` | 기본 정보 몇 줄 + **T4 문제정의 리스트** |
| `구간A_문제정의_예시` | 채워진 작성 예시 |
| `참고_BIAS_CRO_체크리스트` | BIAS 27항목 + 구간별 CRO 항목 문구 (**판정란 없음 — 읽기용**) |

## 2. 표별 열 정의 (이름·순서 고정)

**표의 열 이름과 순서는 계약·시트 템플릿·스킬 출력 예시에서 문자 단위로 동일해야 합니다.** 이것이 이 계약의 유일한 정합 조건입니다.

### T1. 워크스루 Fact 로그 — 6열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | Fact ID | `F-01`, `F-02`, … (화면 1개 = 1회 실행 단위로 연번) |
| 2 | 스크린샷 | 파일명 또는 "1번/2번/3번" |
| 3 | 위치·요소 | 예: 상단 헤드라인, 하단 CTA |
| 4 | 관측 사실 | 문구 전사 또는 "○○ 요소 없음" — **없음도 Fact** |
| 5 | 요소 상태 | `있음` / `없음` / `판독불확실❓` |
| 6 | 안 함 vs 못 함 | `클릭하지 않았다` / `클릭할 수 없었다` / `-` |

### T2. BIAS 27항목 판정 — 6열 (27행 고정)

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 항목ID | `B1`~`B9`, `I1`~`I7`, `A1`~`A7`, `S1`~`S4` (정본 `references/bias-27-items.md` 순서 고정) |
| 2 | 단계 | Block / Interpret / Act / Store |
| 3 | 판정 | `O`(Pass) / `△`(부분·판단 보류) / `X`(Fail) |
| 4 | 근거 Fact ID | T1 인용, 콤마 구분 — **X 판정은 필수** |
| 5 | 근거 요약 | 관측 사실 한 줄 |
| 6 | 문제 문장 초안 | X·△만. 고객 주어 형식(4절) |

체크 항목 문구는 시트 템플릿에 미리 적혀 있으므로 표에 넣지 않습니다(항목ID로 대응).

### T3. CRO 체크리스트 판정 — 5열

| # | 열 이름 | 내용 |
|---|---|---|
| 1 | 항목ID | `LP-S#`·`LP-C#`·`PP-C#`·`PP-P#`(구간 A) / `CO-F#`·`CA-T#`(구간 B) — 5절 |
| 2 | 체크 항목 | 스킬 data JSON의 `item_ko` 요지 |
| 3 | 판정 | `Pass` / `Fail` / `N/A` |
| 4 | 근거 Fact ID | Fail은 필수 |
| 5 | BIAS 단계 | 체크리스트 JSON의 `bias_stage` 값 그대로 |

표 아래 본문에 2줄을 함께 냅니다: **지배 병목 단계** 1문장(동률이면 Block > Interpret > Act > Store 우선), **Fail율** = Fail ÷ (Fail + Pass), N/A는 분모 제외.

### T4. 문제정의 리스트 — 15열 ★ 유일한 시트 산출물

| # | 열 이름 | 시트 셀 | 내용 |
|---|---|---|---|
| 1 | 문제ID | A | `PR-01`, … |
| 2 | 화면 | B | 이 문제가 관측된 화면명 (메타카드의 화면명) |
| 3 | 고객 문제 | C | 고객 주어 문장(4절) — **솔루션 역기술 금지 규율이 그대로 적용되는 칸**(4절) |
| 4 | **솔루션 아이디어** | D | 형식: `[적용 전술] 솔루션 한 줄`. **아이데이션 씨앗이며 문제 문장이 아닙니다.** 없으면 공란 |
| 5 | BIAS 단계 | E | Block / Interpret / Act / Store |
| 6 | BIAS 항목 | F | **항목ID + 체크 항목 요약** — 예: `B1 1초 직관성`. 해당 없으면 `-`, 복수면 콤마 |
| 7 | CRO 항목 | G | **항목ID + 체크 항목 요약** — 예: `LP-S5 메인 CTA가 가장 눈에 띈다`. 해당 없으면 `-`, 복수면 콤마 |
| 8 | 근거유형 | H | `관측` / `정성(VOC·인터뷰)` / `관측+정성` |
| 9 | 트래픽 점수 | I | 1~10 (참가자가 준 트래픽 값 기반) |
| 10 | 트래픽 근거 | J | 한 줄 — **워크숍 시트에서 확인한 트래픽 값 인용** |
| 11 | Gap 점수 | K | 1~10 (참가자가 준 Gap 배수 기반) |
| 12 | Gap 근거 | L | 한 줄 — **벤치마크 Gap 배수 인용** |
| 13 | 심각도(가중) | M | 원점수에 BIAS 가중치를 적용한 값(6절) |
| 14 | 심각도 근거 | N | 한 줄 — 원점수·Fail율·가중치 적용 내역 |
| 15 | **Impact** | O | 스킬 계산값, 소수 1자리 |

**행 추가 규칙**: 문제 1개당 솔루션이 여러 개면 **행을 추가**합니다. 추가 행은 `문제ID`와 `솔루션 아이디어`만 채우고 나머지 열은 공란으로 둡니다(점수·근거를 복제하지 않습니다).

**방어 문구** (계약·시트 메모에 필수로 붙입니다): *"솔루션 아이디어 열은 아이데이션 씨앗입니다. 고객 문제 문장(3열)에 솔루션을 섞지 마세요 — 문장에서 솔루션이 자동으로 따라 나오면 그 문장은 문제가 아닙니다."*

`BIAS 항목`·`CRO 항목`이 이 문제의 **근거 기록**입니다. Fact ID는 대화의 T1에만 남고 시트에는 옮기지 않습니다.

Impact 내림차순으로 정렬합니다. 점수 3개 중 하나라도 못 구하면 그 칸과 Impact를 공란으로 두고 근거 칸에 `코치 확인 필요`라고 씁니다.

### T4-repo. 저장소 착지 형식 — 8열 (읽기용 요약)

위 15열은 **시트/CSV 스냅샷의 형식**입니다. 프로젝트 저장소에 결과를 보존할 때는 읽기 편하도록
**8열 요약**으로 착지하는 것을 권장합니다(예: `{프로젝트 저장소}/problem-definitions-{A|B}.md`) — 두 형식의 관계는 다음과 같습니다:

- 8열: `문제ID | 구간(화면) | 고객 문제 | BIAS(단계+항목) | 트래픽 | Gap | 심각도 | Impact`
- 근거 3열(10·12·14열)은 표에서 빼고 문서 하단 **「근거 상세」 섹션**에 항목별 산문으로 적습니다
- CRO 항목(7열)은 근거 상세에 포함합니다
- **`솔루션 아이디어`(4열)는 repo md 표에 넣지 않습니다** — 솔루션의 정본은 가설 백로그(`cro-hypothesis-backlog`)의 H5b 솔루션 카드입니다
- **15열 전체 원본은 프로젝트 저장소의 CSV 스냅샷**에 보존하는 것을 권장합니다 — 열 단위 확인이 필요하면 CSV를 보세요

즉 md 표를 15열로 넓히거나, 계약이 8열이라고 오해해 시트를 8열로 줄이면 안 됩니다.

## 3. 표 출력 규칙 (스킬·프롬프트 카드 공통)

1. 표는 **마크다운 표**로 대화에 출력합니다. 코드블록에 넣지 않습니다 — 렌더된 표라야 복사해서 시트에 붙일 때 셀로 갈라집니다.
2. 표 바로 위 또는 아래에 **어느 시트 섹션에 붙이는지** 한 줄로 안내합니다. 예: "이 표를 시트 `구간A_문제정의` 탭의 **BIAS 27항목 판정** 섹션에 붙여 넣으세요."
3. 열 이름·순서는 2절과 문자 단위로 동일해야 합니다. 임의로 열을 추가·삭제·재배열하지 않습니다.
4. 셀 안에서 줄바꿈하지 않습니다(시트 붙여넣기가 깨집니다). 콤마·슬래시로 구분합니다.
5. **표가 시트에 한 셀로 붙는 경우**: 렌더된 표를 드래그해 복사했는지 확인하고, 그래도 안 되면 열별로 나눠 옮깁니다.

## 4. 고객 문제 문장 형식 (정본)

이 절은 T4의 **3열 `고객 문제`** 에만 적용됩니다. 4열 `솔루션 아이디어`는 솔루션을 적는 칸이므로 이 형식 규율의 대상이 아닙니다 — **4열이 생겼다고 3열의 규율이 완화되지 않습니다.**

```
고객은 이 [화면/상황]에서 이런 [문제]를 [못 한다 / 모른다 / 느낀다]
```

- 주어는 **사람(고객)** 입니다. 화면·버튼이 주어면 그건 Fact지 문제가 아닙니다.
- **솔루션 역기술 금지 (3열 한정)**: 문장에서 해결책이 자동으로 따라 나오면 아직 현상입니다. 판별 질문 — *"이 문장에서 솔루션이 자동으로 나오는가?"* 나오면 *"그래서 고객이 무엇을 못 하고 있나?"*로 한 번 더 내려가 다시 씁니다. 떠오른 해결책은 문제 문장에 섞지 말고 **4열에 따로 적습니다.**
- **근거 없는 추측 금지**: 확정 전사(T1)나 정성 근거에 없는 감정·수치·발화를 지어내지 않습니다. 모든 문장은 근거 ID를 답니다.

예시:
- 현상 ❌ "진행 단계 표시가 없다" (→ "표시를 넣자"가 바로 나옴)
- 문제 ✅ "고객은 이 정보 입력 대화에서 지금까지 몇 개를 답했고 앞으로 몇 개가 남았는지 알 수 없어, 언제 끝나는지 모른 채 대화를 이어가다가 중간에 포기한다"

## 5. ID 체계

| ID | 형식 | 부여 주체 |
|---|---|---|
| Fact ID | `F-01`~ (실행 단위 연번) | 스킬 STEP 1 |
| BIAS 항목ID | `B1`~`S4` 27항목 (`references/bias-27-items.md` 고정) | 스킬 설계 시 고정 |
| CRO 항목ID | 아래 표 | 체크리스트 제작 시 부여 |
| 문제ID | 시트·스킬 출력: `PR-01`~ / **저장소 착지 시 `PR-{A\|B}-{2자리}`로 구간 접두를 붙임** | 스킬 STEP 4 (구간 접두는 repo 반영 시) |
| 트리 노드ID | `N1-1-1` 형식 | 골트리 작성 시 |

| 접두사 | 섹션 | 구간 |
|---|---|---|
| `LP-S#` | Landing Page — Structure & CTA | A |
| `LP-C#` | Landing Page — Content & Urgency | A |
| `PP-C#` | Product Page — CTA Area | A |
| `PP-P#` | Product Page — Social Proof | A |
| `CO-F#` | Checkout Page — Form & Process | B |
| `CA-T#` | Cart Page — Trust & Clarity | B |

- 번호는 원본 `E-commerce CRO Checklist.MD`(175항목)의 섹션 내 등장 순서.
- 각 항목은 `{id, section, item_ko, bias_stage, screen_hint(구간 A) | chat_reinterpretation(구간 B), pass_criteria, fail_signal}` 필드를 가집니다. 체크리스트 문서와 스킬 JSON의 항목 수·ID·`item_ko`·힌트 문구는 **문자 단위로 동일**해야 합니다(`pass_criteria`·`fail_signal`은 JSON 전용 보조 필드).

## 6. Impact 공식 · BIAS 가중치 (정본)

```
문제 Impact 점수 = (트래픽 영향 + 벤치마크 Gap + 정성 심각도) / 3   (각 10점 만점)
```

- 정성 심각도 가중치: **Block 실패 항목이 있으면 +2, Interpret 실패 항목이 있으면 +1**을 원점수에 더한 뒤 **10점으로 캡**. Act/Store 실패는 가중치 없음.
- **계산 주체**: 스킬이 계산합니다. 가중치 적용과 평균을 **계산 과정과 함께** 보여주고(원점수 → 가중 → Impact), 담당자가 점수나 근거에 이견을 주면 **반영해 재계산**합니다.
- **입력값은 지어내지 않습니다**: 트래픽 값과 벤치마크 Gap 배수는 워크숍 시트의 해당 구간 탭에서 확인한 값을 참가자에게 물어서만 받습니다. 못 받으면 공란 + `코치 확인 필요`.
- 각 점수에 반드시 근거 한 줄 — **근거 없는 점수는 무효**입니다.
- **ICE는 이 단계에서 계산하지 않습니다** (별도 백로그 워크숍, **합산식 ICE = I+C+E**가 정본 — 곱셈식 금지). 이 세션의 Impact는 그 ICE의 **I 근거값**일 뿐입니다.

## 8. 완료 판정 체크 (7항목)

1. 스크린샷 전사가 "전사 확인"으로 승인되었는가
2. BIAS 27항목 전부 판정되었는가 (빈 판정 없음)
3. X·△ 항목마다 문제 문장 초안이 있는가
4. 문제 문장에서 솔루션이 자동으로 따라 나오지 않는가 (현상 아님)
5. 문제 문장이 전부 **고객 주어** 형식인가
6. 모든 점수(트래픽·Gap·심각도)에 근거 한 줄이 붙어 있는가
7. T4 문제정의 리스트가 시트에 옮겨졌는가
