# 온보딩 질문 은행 (원문)

`skills/blog-onboarding/SKILL.md`의 단계마다 사용자에게 보여 주는 **질문·옵션·안내 문구의 원문**입니다. 메인은 여기 문구를 그대로 쓰고, `<…>` 자리만 채웁니다. 이 파일의 문구를 바꾸면 SKILL.md의 질문 수 표와 맞는지 같이 확인합니다.

표기:
- **AUQ** = AskUserQuestion 질문 1개. `header`는 12자 이내, 옵션은 2~4개. 모든 AUQ에는 도구가 「기타(Other)」 자유 입력을 자동으로 붙입니다 — "기타에 적어 주세요"는 그 칸을 뜻합니다.
- **(기본)** = 유형별 기본값(SKILL.md 「유형별 기본값」 표)에 해당하는 옵션. 라벨 끝에 붙여 보여 줍니다. 기본 옵션을 첫 번째에 둡니다.
- **자유 입력** = AUQ가 아니라 메인이 채팅으로 한 번 묻고 답을 기다리는 프롬프트. 답을 받으면 「되돌림 확인 표」로 돌려 보여 줍니다.

---

## 1. 단계별 질문·옵션

### O0 재실행 (질문 수에서 제외)

AUQ — header `온보딩 재실행`
- 질문: "이미 채워진 프로필이 있습니다. 어떻게 할까요?"
- 옵션:
  - `그대로` — 아무것도 바꾸지 않고 현재 상태 보고만 합니다.
  - `항목만 고르기` — 바꿀 묶음만 골라 그 단계만 다시 묻습니다.
  - `전부 다시` — 모든 단계를 처음부터 묻습니다. 지금 값은 기본값으로 보여 줍니다.

`항목만 고르기`면 AUQ(multiSelect) — header `다시 맞추기`
- 질문: "다시 맞출 묶음을 고르세요. 여러 개 고를 수 있습니다."
- 옵션:
  - `기본 정보·글 모양` — 블로그 유형·업체 정보·말투·글 끝 구성·금칙어(O1·O2·O5·O6·O10)
  - `레퍼런스·디자인 시스템` — 블로그 ID·기준 글·레퍼런스·디자인 시스템(O3·O4·O7a·O12)
  - `주제 키워드·공신 출처` — 주제 키워드·연관 검색어·주제 소스·공신 출처(O7b·O8)
  - `이미지 소스` — AI 키·스톡 사진 키·내 사진 폴더(O9)

### O1 블로그 유형 — Q1

AUQ — header `블로그 유형`
- 질문: "이 블로그는 어떤 블로그인가요? 고른 유형에 맞춰 말투·글 끝 구성·이미지의 기본값을 잡아 드립니다."
- 옵션:
  - `업체` — 매장·사무실이 있는 가게·회사입니다(예: 수리점·식당·병원). 글 끝에 문의 안내·소개 이미지·지도까지 넣습니다.
  - `전문가` — 상담·강의·프리랜서처럼 사람이 곧 서비스입니다. 문의 안내는 넣고 지도·소개 이미지는 뺍니다.
  - `개인` — 취미·정보·일상 블로그입니다. 연락처·지도 없이 해요체로 씁니다.
  - `브랜드` — 온라인 판매·제품 브랜드입니다. 매장 지도 없이 문의 안내·소개 이미지를 넣습니다.

### O2 기본 정보 — 자유 입력 1회

유형별 템플릿은 아래 3절. 받은 뒤 「되돌림 확인 표」 → AUQ `맞아요` / `고칠게요`(재확인 — 질문 수에서 제외).

### O3 블로그 ID — Q2 (`.env NAVER_BLOG_ID`가 없을 때만)

AUQ — header `블로그 ID`
- 질문: "글을 올릴 네이버 블로그 주소의 ID(blog.naver.com/<여기>)를 알려 주세요"
- 옵션(blog-setup 3-2와 같음): (`own_blog.blogId`가 형식에 맞으면 첫 옵션으로) `<그 값> 쓰기` / `기타에 직접 적기` / `나중에`
- `MISMATCH`(두 값이 다름)면 같은 질문에 옵션 `.env 값 <값>` / `own_blog.blogId 값 <값>` / `기타에 직접 적기`.
- 받은 값이 블로그 ID 형식(영문·숫자·`_`·`-`)이 아니면 한 번 더 묻습니다(재확인).

### O4 정보성 카테고리·기준 글 — Q3 (자기 글이 1편 이상일 때만)

먼저 표 두 개를 보여 줍니다.

```
내 블로그 카테고리 (최근 RSS 기준)
| 카테고리 | 글 수 |
|---|---|
| <카테고리> | <n> |

<추천 카테고리>의 최근 글
| 번호 | 날짜 | 제목 |
|---|---|---|
| 1 | <YYYY-MM-DD> | <제목> |
```

AUQ — header `기준 글`
- 질문: "정보성 글 카테고리와 기준 글(레퍼런스 0)을 이렇게 잡을까요? 기준 글은 앞으로 쓸 글의 모양·분량의 기준이 됩니다."
- 옵션:
  - `이대로 — <카테고리> · 「<제목>」`
  - `카테고리 바꾸기` — 기타에 위 표의 카테고리 이름을 그대로 적어 주세요.
  - `기준 글 바꾸기` — 기타에 위 표의 번호를 적어 주세요.
  - `기준 글 없이` — 「레퍼런스 0 없음」 경로로 진행합니다.

### O5 말투 — Q4

AUQ — header `말투`
- 질문: "글 말투를 고르세요."
- 옵션(유형 기본값에 (기본)):
  - `합니다체(격식)` — 「~합니다·~입니다」로 끝냅니다.
  - `해요체(친근)` — 「~해요·~이에요」로 끝냅니다.
  - `내 글 기준: <합니다체|해요체>` — 기준 글을 재 보니 합니다체 <n>문장 · 해요체 <n>문장입니다. 많은 쪽을 씁니다. (기준 글이 있을 때만 보임)

### O6 글 끝 구성 — Q5 (개인 유형은 묻지 않음)

업체 — AUQ(multiSelect) — header `글 끝 구성`
- 질문: "글 끝 마무리에 무엇을 넣을까요? 해시태그 줄은 항상 들어갑니다."
- 옵션:
  - `문의 헤딩 (기본)` — 마지막 소제목 「📞 <문의 헤딩 문구>: <연락처>」를 넣습니다.
  - `소개 이미지 (기본)` — 업체 소개 이미지(photos/business-intro.png)를 넣습니다.
  - `장소 카드 (기본)` — 네이버 지도 장소 카드를 넣습니다.

브랜드 — 같은 질문, 옵션 `문의 헤딩 (기본)` / `소개 이미지 (기본)`.

전문가 — AUQ — header `문의 헤딩`
- 질문: "글 끝에 문의 헤딩(📞 <문의 헤딩 문구>: <연락처>)을 넣을까요? 해시태그 줄은 항상 들어갑니다."
- 옵션: `넣기 (기본)` / `넣지 않기`

### O7a 레퍼런스 — 안내 → 자유 입력 1회 → Q6

안내문은 2절, 자유 입력 템플릿은 3절. `verify_blogs.py` 검증 표를 보여 준 뒤:

```
| 번호 | 블로그 ID | 응답 | 월 발행(추정) | 카테고리 상위 3 | 최근 제목 |
|---|---|---|---|---|---|
| 1 | <blogId> | OK | <n>편 | <a>, <b>, <c> | <제목> |
```

AUQ — header `레퍼런스`
- 질문: "레퍼런스로 쓸 글을 고르세요(3~5개 권장, 응답 OK만 쓸 수 있습니다)."
- 옵션:
  - `OK인 것 전부 쓰기` — 이유(why)는 측정 요약에서 읽은 특징(소제목 구성·사진 비율·FAQ)으로 자동 기입합니다(5개가 넘으면 앞 5개). 직접 적은 이유가 규칙을 더 정확하게 만듭니다.
  - `번호로 고르기` — 기타에 「1, 3, 4」처럼 적어 주세요. 이유를 직접 쓰려면 「1: 목차가 깔끔함」처럼 번호 옆에 적습니다.
  - `레퍼런스 없이 진행` — 디자인 시스템은 기준 글(없으면 기본값)만으로 만듭니다.

측정 뒤 보여 주는 표(질문 아님):

```
| 번호 | 글 | 글자수 | 소제목 | 이미지 | FAQ | 이유(why) |
|---|---|---|---|---|---|---|
| 1 | <blogId>/<logNo> | <n> | <n>개 | <n>장 | 있음/없음 | <직접 적은 이유 또는 「(자동) 소제목으로 나눠 읽기 쉬움(소제목 n개) · 사진과 글 비율(이미지 n장 — 약 n자당 1장) · FAQ로 마무리」> |
```

### O7b 주제 키워드 — 자유 입력 1회 (템플릿 3절)

### O7b·O8 연관 검색어·주제 소스·공신 출처 — Q7

표 세 개(연관 검색어 · 주제 소스 추천 · 공신 출처 후보)를 번호와 함께 보여 준 뒤:

AUQ — header `주제·출처`
- 질문: "위 세 표(연관 검색어 · 주제 소스 · 공신 출처)를 이대로 저장할까요?"
- 옵션:
  - `전부 이대로 저장`
  - `고칠 것 있음` — 기타에 적어 주세요(예: 「연관 검색어 3, 7 빼기」, 「주제 소스 빼기」, 「출처 2 빼기」, 「출처 추가: 기관명 URL」).
  - `출처 표는 비워 두기` — (개인 유형에만) 공신 출처 표 없이, 수치를 쓸 때마다 출처 URL을 붙이는 규칙만 둡니다.

### O9 이미지 소스 — Q8 · Q9 · Q10

Q8 — AUQ(multiSelect) — header `이미지 소스`
- 질문: "글에 넣을 이미지를 어디서 가져올까요? 여러 개 고를 수 있습니다."
- 옵션(유형 기본값에 (기본)):
  - `AI 생성(Gemini 또는 OpenAI)` — 유료 키가 필요합니다(1장 약 $0.04 추정).
  - `무료 스톡 사진(Pexels)` — 무료 키가 필요합니다.
  - `내 사진 폴더` — photos/ 폴더에 직접 찍은 사진을 넣습니다.

Q9 — AUQ — header `AI 제공자` (AI를 골랐고 키 확인이 OK가 아닐 때만)
- 질문: "글에 넣을 이미지를 만들 AI 키를 고르세요. 이미 쓰고 계신 키가 있으면 그것을 고르세요."
- 옵션: `Gemini(Google AI Studio)` / `OpenAI(GPT 이미지)` / `아직 없음 — 나중에`

Q10 — AUQ — header `키 확인` (안내를 보여 준 소스가 하나라도 있을 때 한 번 — AI·Pexels 함께)
- 질문: "안내대로 .env에 키를 넣으셨나요? 키는 채팅에 붙여넣지 말고 .env 파일에 직접 넣어 주세요."
- 옵션: `넣었어요 — 확인해 주세요` / `나중에 넣을게요`
- 확인이 OK가 아니면 원인 안내 뒤 한 번만 다시(재확인 — 질문 수에서 제외): 옵션 `다시 넣었어요 — 한 번 더 확인` / `나중에 넣을게요`

### O10 금칙어·기타 — 자유 입력 1회 (템플릿 3절)

### O11 저장 전 확인 (재확인 — 질문 수에서 제외)

「되돌림 확인 표」 전체(4절)를 보여 준 뒤 AUQ — header `저장 확인`
- 질문: "아래 값으로 knowledge/의 파일을 씁니다. 이미 채워진 다른 값은 그대로 둡니다. 이대로 저장할까요?"
- 옵션: `이대로 저장` / `고칠 것 있음` — 기타에 「항목: 새 값」으로 적어 주세요.

`check_profile.py`가 OK가 아니면 그 행만 다시 묻는 자유 입력(재확인):
- "`<행>` 값이 비어 있거나 올바르지 않습니다(<check_profile 출력>). 이 칸에 넣을 값을 적어 주세요."

## 2. 「레퍼런스 찾는 법」 안내문 (O7a — 자유 입력보다 먼저)

업체·전문가·브랜드:

```
레퍼런스는 "이런 모양으로 쓰고 싶다" 싶은 네이버 블로그 글입니다. 글의 내용이 아니라 모양
(소제목 수·사진 수·분량·FAQ 유무)만 재서 규칙으로 바꿉니다. 찾는 법:

1. 네이버(https://search.naver.com)에서 이렇게 검색합니다.
   「<상품·서비스 첫 항목> <고객 지역 첫 항목>」  또는  「<상품·서비스 첫 항목> 후기」
2. 검색 결과의 「블로그」 탭에서 읽기 편하고 보기 좋은 글을 엽니다.
3. 주소창의 글 주소(https://blog.naver.com/아이디/숫자)를 복사합니다.
   휴대폰 앱이면 글 오른쪽 위 공유 → 「링크 복사」를 누릅니다.
4. 내 블로그에서 반응이 좋았던 글이 있으면 그 글 주소도 1편 넣어 주세요.

같은 업종 다른 블로그의 글도 괜찮습니다. 블로그 ID(blog.naver.com/<여기>)만 적으면 그 블로그의 최근 글 1편을 잽니다.
```

개인:

```

## 3. 자유 입력 프롬프트 템플릿

모든 템플릿 머리 문장: "아래 항목을 한 번에 적어 주세요. 모르는 칸은 비워 두셔도 됩니다(★는 꼭 필요합니다)."
O0에서 `전부 다시`·`항목만 고르기`로 들어온 경우 각 줄 끝에 `(지금: <현재 값>)`을 붙이고, "그대로 둘 칸은 비워 두세요"를 덧붙입니다.

### 3-1 O2 기본 정보

업체:
```
★업체명:
★상품·서비스(쉼표로 구분):
연락처(전화 또는 이메일 — 글 끝 📞 문의 헤딩에 들어갑니다):
주소:
고객 지역(고객이 많은 동네 순, 쉼표로 — 지역과 상관없으면 비워 두세요):

## 4. 되돌림 확인 표 양식

자유 입력을 받을 때마다(그리고 O11 저장 전에 전체를) 이 양식으로 돌려 보여 줍니다. 빈 칸은 `(비움)`, 묻지 않은 칸은 표에 넣지 않습니다.

```
| 항목 | 받은 값 | 저장할 곳 |
|---|---|---|
| 업체명 | <값> | knowledge/business-profile.md `업체명` 행 |
| 상품·서비스 | <값> | knowledge/business-profile.md `상품·서비스` 행 |
| 고객 지역 | (비움) | knowledge/business-profile.md `고객 지역` 행 — 비우면 지역 키워드·제목 지역 검사를 끕니다 |
```

이어서 AUQ — header `확인`
- 질문: "이렇게 받았습니다. 맞나요?"
- 옵션: `맞아요` / `고칠게요` — 기타에 「항목: 새 값」으로 적어 주세요.

`고칠게요`는 고친 줄만 반영하고 표를 한 번 더 보여 줍니다(재확인 — 질문 수에서 제외).
