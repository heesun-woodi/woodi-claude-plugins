# 주장 유형별 조회처·질의 방법

조회처·접근성의 정본은 작업 폴더 `knowledge/official-sources.md`다(업종별 공신 출처 — 법령 DB·공공기관·업체 프로필). 이 표는 주장 유형별로 어디를 어떻게 여는지 묶은 것이고, 둘이 다르면 `official-sources.md`를 따른다.
공통 명령: `curl -sL -A "Mozilla/5.0" --max-time 20 "<URL>"` (WebFetch 실패 시 curl 재시도). 응답은 `T=$(mktemp -d)` 임시 디렉터리에 저장해 grep한다.

## 1. 매핑표

| 주장 유형 | 대표 예 | 1차 조회처 (URL 템플릿 / 명령) | 2차 | 접근 불가 시 처리 (경우마다 판정 하나) |
|---|---|---|---|---|
| 법령·규정 | "<법령명> 제<n>조에 따라…" | law.go.kr DRF: `https://www.law.go.kr/DRF/lawSearch.do?OC=test&target=law&type=XML&query=<법령명>` → `<법령일련번호>`(MST) → `https://www.law.go.kr/DRF/lawService.do?OC=test&target=law&MST=<MST>&type=XML` | `korean-law` MCP(`search_law`/`get_law_text`, 도구 목록에 있을 때) | 열었는데 문구 없음 → 출처필요 / 열지 못함(DRF 오류·차단) → 출처필요 (법령은 추측 금지) |
| 자격·요건 (법정 요건) | "<자격>이 있어야 이용할 수 있다", "누구나 신청할 수 있다" | 근거 법령의 조문·별표(위 DRF) | `official-sources.md`의 기관 안내 페이지 | 열었는데 문구 없음 → 출처필요 / 열지 못함 → 출처필요 (법령) |
| 자격·요건 (기관 안내) | "온라인으로 신청할 수 있다", "신청 때 신분증이 필요하다" | `official-sources.md`에 등록한 기관 안내 페이지 | 기관 공지 | 열었는데 문구 없음 → 출처필요 (제안: "<기관>에서 요건 확인" 문구) / 열지 못함 → 시점확인 + 담당자 확인 |

| 가격·수수료 (지원 제도 언급) | "<제도>로 비용 일부를 지원받을 수 있다" | `official-sources.md`의 지원 제도 조회처 | 주관 부처 사이트 | 기관 상세가 접근성 기록에 「껍데기」(JavaScript가 채움)로 적혀 있으면 curl로 안 보이는 것이 정상이므로 "열지 못함"으로 본다 → **PASS 금지**, 시점확인 + 담당자 확인 |
| 가격·수수료 (지원 금액·비율 단정) | "자부담 0원", "최대 ○○만 원", "전액 무료" | 위 지원 제도와 같음 | 주관 부처 보도자료 | 출처 문구로 금액·비율을 확인하지 못하면 언제나 출처필요 (삭제 또는 "<기관>에서 확인" 문구 제안) |
| 통계·수치 | "이용자의 절반 정도가…", 연도별 건수·비율 | `official-sources.md`의 통계 조회처(공공 통계·기관 현황표) | 통계 보고서 원문 | 열었는데 문구 없음 → 출처필요 / 열지 못함 → 시점확인 + 담당자 확인 |
| 일정·기한 (기관 일정) | "이번 달 접수는 <M>월 <D>일부터" | `official-sources.md`의 일정 조회처(월간 일정·공고) | 기관 공지 | 열었는데 해당 날짜 없음(빈 일정 표 포함) → 출처필요 (제안: "<기관>에서 최신 일정 확인" 문구) / 열지 못함 → 시점확인 + 담당자 확인 |
| 일정·기한 (법정 기한·주기) | "<n>년마다 갱신해야 한다" | 근거 법령의 조문·별표(위 DRF) | — | 열었는데 문구 없음 → 출처필요 / 열지 못함 → 출처필요 (법령) |
| 업체 정보 | 주소·전화·상품·서비스·강점 | 작업 폴더 `knowledge/business-profile.md` | — | 프로필에 없음 → 출처필요 / 파일이 없음 → 출처필요 + `## 질문` |
| 기관 공지 | "<기관>이 ○월부터…" | `official-sources.md`에 등록한 기관 사이트(쿠키가 필요하면 `curl -c "$T/cj" -b "$T/cj"`) | 보도자료 원문 | 열었는데 문구 없음 → 출처필요 / 열지 못함(쿠키·차단) → 시점확인 + 담당자 확인 |

### 접근성 요약 (official-sources.md 기준)

- 본문 가능: law.go.kr DRF API(법·시행령·시행규칙). 그 밖의 조회처는 `official-sources.md` 접근성 기록에 「본문 가능」으로 적힌 곳.
- 껍데기만: law.go.kr 사람용 상세 `https://www.law.go.kr/법령/…`(독자용 링크로만), JavaScript가 내용을 채우는 기관 상세 페이지(접근성 기록에 조각 URL이 있으면 그것을 쓴다).
- 쿠키 필요: 루트 주소가 리다이렉트 루프를 도는 사이트 — 쿠키 파일을 주고받으며(`-c`/`-b`) 연다.

## 2. 법령 조문 찾는 요령 (DRF XML)

1. **현행 MST부터**: `lawSearch.do?…&query=<법령명>` 응답은 이름이 비슷한 법령(시행령·시행규칙)을 함께 돌려주므로, `<법령명한글>`이 찾는 이름과 **정확히 일치하는** `<law>` 항목을 골라 `<법령명한글>`·`<법령일련번호>`·`<시행일자>`·`<현행연혁코드>현행</현행연혁코드>`를 읽는다.
   MST는 개정되면 바뀌므로 매번 검색한다.
2. **`LM=` 호출 주의**: `lawService.do?…&LM=<법령명>`은 공포만 되고 **아직 시행 전**인 판본을 돌려줄 수 있다. 응답 `<기본정보>`의 `<시행일자>`가 오늘 이후면 그 판본으로 판정하지 말고 현행 MST로 다시 받는다. (요약: `LM=`은 시행 예정본을 반환할 수 있음 → `lawSearch.do`로 MST 확인 후 시행일자가 미래면 현행 MST로 재조회.)
3. **조문 찾기**: 조문은 `<조문단위>`마다 `<조문번호>`·`<조문가지번호>`(예: 제83조의2 → 83/2)·`<조문제목>`·`<조문내용>`·`<항>`/`<호>`가 있다. `<조문여부>조문</조문여부>`인 것만 본다(`전문`은 장·절 제목).
   ```bash
   T=$(mktemp -d)
   curl -sL -A "Mozilla/5.0" --max-time 40 "https://www.law.go.kr/DRF/lawService.do?OC=test&target=law&MST=<MST>&type=XML" -o "$T/rule.xml"
   grep -o '<조문제목><!\[CDATA\[[^]]*' "$T/rule.xml" | sed 's/.*CDATA\[//' | grep -n '<키워드1>\|<키워드2>'   # 제목·내용은 CDATA로 감싸져 있다
   python3 - "$T/rule.xml" <조문번호> <<'EOF'
   import sys, xml.etree.ElementTree as ET
   root = ET.parse(sys.argv[1]).getroot()
   for u in root.iter('조문단위'):
       if u.findtext('조문번호') == sys.argv[2] and u.findtext('조문여부') == '조문' and not u.findtext('조문가지번호'):
           print(' '.join(t.strip() for t in u.itertext() if t.strip()))
   EOF
   ```
4. **별표**: 수수료·기준·종류 같은 표는 조문이 아니라 `<별표단위>`(`<별표번호>00NN</별표번호>`, `<별표제목>`, `<별표내용>`)에 있다. `<별표내용>`은 괘선 문자 표라 grep으로 키워드 줄을 찾는다.
5. 인용 형식: `"<조문 원문 1~2줄>" — <법령명> 시행규칙 제<n>조제<n>항제<n>호(시행 <YYYY-MM-DD>) <MST URL>`.

## 3. 기관 페이지 읽는 요령 (official-sources.md 조회처)

- URL에 들어가는 항목 코드(종목·상품·지역 코드 등)는 `official-sources.md`에 적힌 값을 그대로 쓴다. 비슷한 코드가 많아 틀리기 쉬우니, 응답의 제목·항목명이 찾는 대상인지 먼저 확인한다.
- 응답 HTML에서 태그를 지우고 공백을 정리한 뒤 키워드 주변을 읽는다(응답이 euc-kr이면 `decode('euc-kr','replace')`로 바꾼다):
  ```bash
  curl -sL -A "Mozilla/5.0" --max-time 20 "<조회처 URL>" \
    | python3 -c "import sys,re;t=re.sub(r'<[^>]+>',' ',sys.stdin.buffer.read().decode('utf-8','replace'));t=re.sub(r'\s+',' ',t);i=t.find('<키워드>');print(t[i:i+120])"
  ```
- 상세 페이지가 껍데기(JavaScript가 채우는 빈 틀)면, 그 페이지가 불러오는 조각 URL(탭 내용 등)이 `official-sources.md`에 기록돼 있을 때 그것을 연다. 기록이 없으면 "열지 못함"으로 판정한다.
- 일정 표가 비어 있다는 응답(예: "일정이 없습니다")을 "상시 시행" 같은 뜻으로 단정하지 않는다.
- 숫자는 조회 일자를 같이 적고, 초안에 기준 시점이 없으면 시점확인으로 판정한다.

## 4. 자주 틀리는 포인트

아래는 업종과 무관하게 반복되는 판정 포인트다. 업종별로 자주 틀리는 포인트(근거 조문 포함)를 `official-sources.md`에 적어 두었다면 그것을 함께 본다. "확인 필요"로 표시한 부분은 단정하지 않는다.

1. **이름이 비슷한 자격·제도·상품을 섞어 쓴다.** 출처 원문의 정확한 명칭과 대상 범위를 대조한다 — 한쪽의 요건을 다른 쪽에 붙인 문장은 FAIL.
2. **기준 단위를 섞는다.** 무게·용량·기간의 기준이 출처마다 다를 수 있다(예: 자체 무게 기준과 적재 능력 기준). 출처의 「비고」·각주를 함께 읽는다 — 면제·감면·예외도 대개 거기 있다.
3. **조건이 붙은 내용을 단정한다.** "누구나", "바로", "하루 만에", "평생" 같은 단정은 출처에 나이·요건·결격사유·시간·유효기간이 있으면 FAIL — 조건을 붙인 문장을 제안한다.
4. **자격(또는 구매)과 실제 이용 허가가 다를 수 있다.** 등록·신고·면허처럼 별도 절차가 있으면 둘을 같은 것으로 쓴 문장은 FAIL 후보 — 근거 조문을 열어 판정한다.
5. **정기 갱신·교육·검사 주기.** 주기와 기산일(무엇의 다음 날부터 몇 년 등)은 조문 원문대로만 쓴다. "갱신 없음" 같은 단정은 근거 조문을 열어 판정한다.
6. **수수료·통계·일정은 해마다 바뀐다.** 기준 시점 없는 수치는 시점확인.
7. **지원 금액·자부담 비율은 curl로 확인되지 않는 경우가 많다.** 금액·비율·"전액 무료" 단정은 출처필요(매핑표 '가격·수수료 (지원 금액·비율 단정)' 행), 제도 언급만 있으면 시점확인 + 담당자 확인.
8. **열지 않은 하위 조문·별표의 수치는 "확인 필요".** 초안이 그 수치를 특정하면 그 조문·별표를 열어 판정한다.
9. **빈 일정 표는 "상시 시행"의 근거가 아니다.** 상시 시행 여부·회차 일정은 시점확인 + 담당자 확인.
10. **계약·브랜드 금칙어는 사실과 무관하게 금지.** 금칙어 목록은 `knowledge/business-profile.md`. fact-checker는 그 표현과 그것이 가리키는 사실의 암시를 FAIL로 표시하고 문장 삭제를 제안한다.
