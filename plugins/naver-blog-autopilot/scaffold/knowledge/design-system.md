<!-- blog-design-system 스킬이 `톤` 행 값에 맞는 판 하나만 남기고 다른 판은 지운다(채우기 전에는 두 판이 다 있다 — 글쓴이는 `톤` 행에 맞는 판만 본다). -->

**합니다체 판** (`톤` = 합니다체 — lint `tone` FAIL 규칙)

| 구분 | 허용 종결 | 금지 종결 |
|---|---|---|
| 평서 | `~입니다` `~합니다` `~됩니다` `~있습니다` | `~해요` `~예요` `~에요` `~죠` |
| 권유 | `~하세요` `~해 보세요` `~기억해 두세요` | `~볼게요` `~드릴게요` |
| 질문(절 예고·FAQ) | `~까요?` `~나요?` `~ㅂ니까?` `~인가요?` `~세요?` | `~죠?` `~해요?` |

- lint `tone`은 평서문 `요/죠` 종결과 위 목록 밖의 의문문을 센다(규칙 0건, 넘으면 FAIL).
- 예시 문장: [합니다체 예시 문장]
- 초기 예시(측정 전 — 첫 글 뒤 실제 문장으로 교체): "처음 알아보시는 분이라면 순서부터 확인하는 것이 좋습니다." / "결론부터 말씀드리면, 순서만 알면 어렵지 않습니다." / "그럼 다음 단계는 어떻게 준비할까요?"

**해요체 판** (`톤` = 해요체 — lint `tone` WARN만)

| 구분 | 허용 종결 | 피할 종결 |
|---|---|---|
| 평서 | `~해요` `~예요` `~이에요` `~있어요` `~돼요` `~죠` | `~습니다` `~입니다` `~됩니다` |
| 권유 | `~해 보세요` `~하세요` `~해 두세요` | `~하십시오` `~하기 바랍니다` |
| 질문(절 예고·FAQ) | `~할까요?` `~나요?` `~인가요?` `~세요?` | `~ㅂ니까?` `~습니까?` |

- lint `tone`은 합니다체 종결(`~습니다`·`~입니다`·`~됩니다`) 문장 수를 `WARN`으로만 알린다(pass 영향 없음, 의문문 규칙 미적용). 0에 가깝게 쓴다.
- 예시 문장: [해요체 예시 문장]
- 초기 예시(측정 전 — 첫 글 뒤 실제 문장으로 교체): "처음 알아보시는 분이라면 순서부터 확인해 보세요." / "결론부터 말하면, 순서만 알면 어렵지 않아요." / "그럼 다음 단계는 어떻게 준비할까요?"

공통:
- 한 문장은 짧게, 한 문단 2~4문장.
- 독자에게 말 걸듯 쓴다: 처지를 먼저 짚고("~하시는 분"), 다음 절로 넘어갈 때 한 문장으로 이어 준다.
- 도입 2문단: 상황·질문 → **결론 굵게**. "안녕하세요 + 자기소개"로 시작하지 않는다(도입 변주).
- 예시 문장은 말투 기준일 뿐 그대로 다시 쓰지 않는다(⑧ 4).

| 금지 표현 | 왜 | 대신 쓸 표현 |
|---|---|---|
| "~하여야 한다", "~할 것" | 공문체 = 딱딱함 | 합니다체 "~해야 합니다", 해요체 "~해야 해요" |
| 다른 말투의 종결(합니다체 판이면 "~해요"·"~예요"·"~죠", 해요체 판이면 "~습니다"·"~입니다") | 말투 일관성(`톤` 행) | [톤] 종결 |
| "효과 보장", "100% 만족" 같은 보장 문구 | 보장·과장 | business-profile.md에 있는 사실만(`강점` 행 범위) |
| "100%", "무조건", "누구나 쉽게" | 근거 없는 단정 | 출처 있는 수치, 또는 "많은 분들이 ~합니다" |
| ⑧ 금칙어 전부 | 계약·브랜드 조항 | ⑧ 참고 |

| 권장 표현 | 왜 | 예 |
|---|---|---|
| 독자 처지로 말 걸기 | 친근한 흐름 | "~준비하시는 분이라면", "~해 보세요" |
| 결론 먼저 | 바로 답을 구하는 독자 | "결론부터 말씀드리면, ~" |
| 어려운 용어는 첫 등장 때 괄호 풀이 | 처음 보는 독자 | "갱신(기간을 다시 늘리는 것)" |
| 다음 절 예고 한 문장 | 자연스러운 흐름 | "그럼 다음 단계는 어떻게 준비할까요?"(두 판 공통) |

## ③ 구조 템플릿과 소제목 규칙

**고정 골격**(레퍼런스 0의 겉모습. 표지 슬롯은 초안에 없다 — 표지는 image-plan `00` 행으로 이미지 단계가 만들고 업로드 단계가 맨 앞에 넣는다):

```
# 제목(keyword[ + 제목 지역]. 20~40자)
도입 2문단(상황/질문 → **결론 굵게**)
## 📑 목차
- 소제목 1 … n (번호 이모지 없이 텍스트만)
---
## 1️⃣ 소제목(검색형 명사구/질문)
본문: 비교표(글당 최대 1개) · ✔️/📖/🚧 이모지 줄(빈 줄로 구분) · 💡 팁 줄 · **핵심 굵게**
![슬롯: 절 내용 요약 장면]()          ← 절 끝(다음 소제목 직전) 1~2장
## 2️⃣ …
## n️⃣ 자주 묻는 질문 (FAQ)              ← 권장(2~4문답, **Q.** 굵게 / A. 문단)
[[관련글: …]] ×2~3                     ← "함께 읽으면 좋은 글"(B'에서 실제 URL. 자기 글 2편 미만이거나 주제에 맞는 글이 없으면 생략 — ⑥)
## 📞 <문의 헤딩 문구>: <연락처>        ← `마무리 블록`에 `문의헤딩`이 있을 때만 — 초안의 마지막 줄(문구 = 프로필 `문의 헤딩 문구`, 비면 `문의 안내` · 연락처 = 프로필 `연락처` 행). 없으면 이 줄 없이 FAQ·관련글이 마지막
(마무리 블록의 소개 이미지·장소 카드·해시태그는 build_final.py가 `마무리 블록` 행에 따라 붙임 — 초안에 쓰지 않음)
```

본문 절 전개 방식(구조 템플릿 4종 — 골격 안 `## 1️⃣`~ 절들을 어떻게 펼칠지, 하나를 골라 ⑦ `structure`에 기록):
- **절차형** — 1단계 → … → n단계 → 놓치기 쉬운 점. 주제: [절차형 주제].
- **비교형** — A 소개 → B 소개 → 기준 비교표 → 상황별 추천. 주제: [비교형 주제].
- **체크리스트형** — 항목 1~n(소제목마다 1개) → 놓치기 쉬운 것. 주제: [체크리스트형 주제].
- **Q&A형** — 질문형 소제목 n개("~해도 되나요?"). 주제: [Q&A형 주제].

소제목 규칙:
- 본문 소제목 수: ④의 범위(목차·`## 📞` 문의 헤딩 제외, FAQ 포함).
- 형태: `## 1️⃣ ` 키캡 번호 + 검색형 명사구 또는 질문("~방법", "~순서", "~비용", "~할까요?") + 끝 이모지 선택. 글 제목을 반복하지 않는다.
- 목차 항목 = 본문 소제목 텍스트(번호 이모지 없이, 같은 순서).
- 소제목당 본문 210~1000자 (초기값 = lint 기본값에서 유도: 내림10(min_chars ÷ max_h2) ~ 올림10(max_chars ÷ min_h2) — 측정 전)
- 소제목 앞 여백: 앞 내용 바로 다음 줄에 `ㅤ`(한글 채움 문자) 2줄(build_final.py `H2_FILLER_LINES`), 그다음 빈 줄 1개, 그다음 `## ` — build_final.py가 넣는다(초안에 쓰지 않는다). 네이버에서 문단 사이(빈 줄 1개)보다 한 칸 더 띄운 빈 줄 2개로 보인다.
- 강조 수단은 **굵게 + 💡 줄**. 음영 인용(`>`)은 0~1개. 비교표는 글당 0~1개.
- FAQ: `**Q. …?**` 줄 → 빈 줄 → `A. …` 문단, 2~4문답.

## ⑤ 이미지 규칙

반드시 지킬 것:
- **텍스트 렌더링 금지**: AI 이미지에 글자 렌더링 금지(간판·자막·숫자 포함). 글자는 본문으로. **예외 = 표지** `images/00-cover.png`(1000×1000 합성): 배경(글자 없는 AI 장면·스톡 사진 또는 실사진) 위에 `scripts/make_cover.py`가 제목·브랜드 배지(business-profile.md `배지 문구`가 있을 때)·전화번호(`연락처`가 있을 때)를 얹는다. 글자는 중앙 안전 영역 안. AI 배경 자체에는 글자가 없어야 한다.
- **얼굴 클로즈업 금지**: 인물은 뒷모습·원거리·손·제품 중심.
- **정보성 글 = AI 생성 이미지·무료 스톡 사진 허용(business-profile.md `이미지 소스` 행에 든 것만). 홍보성 글 = 업체 실사진(photos/)만.**
- 사진 재사용 금지: 이전 글에 쓴 실사진 파일·AI 이미지·스톡 사진은 다시 쓰지 않는다. **예외: `마무리 블록`에 `소개이미지`가 있으면 `photos/business-intro.png`는 매 글 마무리 블록(⑥)의 고정 자산**이다.

배치·형식:
- 표지: 초안에 슬롯을 쓰지 않는다. image-plan `00` 행으로 이미지 단계가 만들고, 업로드 단계가 본문 맨 앞에 넣어 대표이미지로 지정한다.
- 본문 이미지: **절 끝(다음 소제목 직전) 1~2장**.
- [현장 장면 규칙]
- 이미지 사이 본문이 이미지당 상한(④)을 넘지 않게 고르게 둔다.
- **캡션 없음**: 업로드본 이미지는 `![](경로)`(alt 비움). 슬롯 설명·image-plan alt는 내부용.
- 슬롯 문법: `![슬롯: 장면 설명]()` — 경로는 이미지 단계에서 채운다.
