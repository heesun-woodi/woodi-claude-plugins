## ① 글의 목적과 독자

- 목적: 정보성 글로 검색 유입 → 신뢰 → 필요할 때만 상담 연결. 홍보글보다 정보성 글 위주(꼭 지켜야 할 점 2).
- 독자: [business-profile.md `고객 지역`]에서 [상품·서비스]를 알아보는 사람.
- 상품·서비스: [business-profile.md `상품·서비스`·`지원 형태`].
- 독자가 글에서 얻어야 할 것:
  1. [이용·신청 순서]
  2. [비용·지원 방식]
  3. [업체를 고를 때 볼 기준]

## ② 톤앤매너

규칙:
- 주 종결어미 = **합니다체**(담당자 결정). 레퍼런스에 해요체가 섞여 있어도 따르지 않는다.

| 구분 | 허용 종결 | 금지 종결 |
|---|---|---|
| 평서 | `~입니다` `~합니다` `~됩니다` `~있습니다` | `~해요` `~예요` `~에요` `~죠` |
| 권유 | `~하세요` `~해 보세요` `~기억해 두세요` | `~볼게요` `~드릴게요` |
| 질문(절 예고·FAQ) | `~까요?` `~나요?` `~ㅂ니까?` `~인가요?` `~세요?` | `~죠?` `~해요?` |

- lint `tone`은 평서문 `요/죠` 종결과 위 목록 밖의 의문문을 센다(규칙 0건).
- 한 문장은 짧게, 한 문단 2~4문장.
- 독자에게 말 걸듯 쓴다: 처지를 먼저 짚고("~하시는 분"), 다음 절로 넘어갈 때 한 문장으로 이어 준다.
- 도입 2문단: 상황·질문 → **결론 굵게**. "안녕하세요 + 업체 소개"로 시작하지 않는다(도입 변주).

| 금지 표현 | 왜 | 대신 쓸 표현 |
|---|---|---|
| "~하여야 한다", "~할 것" | 공문체 = 딱딱함 | "~해야 합니다", "~해 두세요" |
| "~해요", "~예요", "~죠" 종결 | 합니다체 전용(담당자 결정) | "~합니다", "~입니다" |
| "효과 보장", "100% 만족" 같은 보장 문구 | 보장·과장 | business-profile.md에 있는 사실만(`강점` 행 범위) |
| "100%", "무조건", "누구나 쉽게" | 근거 없는 단정 | 출처 있는 수치, 또는 "많은 분들이 ~합니다" |
| ⑧ 금칙어 전부 | 계약·브랜드 조항 | ⑧ 참고 |

| 권장 표현 | 왜 | 예 |
|---|---|---|
| 독자 처지로 말 걸기 | 친근한 흐름 | "~준비하시는 분이라면", "~해 보세요" |
| 결론 먼저 | 바로 답을 구하는 독자 | "결론부터 말씀드리면, ~" |
| 어려운 용어는 첫 등장 때 괄호 풀이 | 처음 보는 독자 | "[전문 용어]([쉬운 풀이])" |
| 다음 절 예고 한 문장 | 자연스러운 흐름 | "그럼 [다음 단계]는 어떻게 준비할까요?" |

- [예시 문장 1] ([logNo])
- [예시 문장 2] ([logNo])

## ③ 구조 템플릿과 소제목 규칙

**고정 골격**(레퍼런스 0의 겉모습. 표지 슬롯은 초안에 없다 — 표지는 image-plan `00` 행으로 이미지 단계가 만들고 업로드 단계가 맨 앞에 넣는다):

```
# 제목(keyword + title_region 지역명 1개, 20~40자)
도입 2문단(상황/질문 → **결론 굵게**)
## 📑 목차
- 소제목 1 … n (번호 이모지 없이 텍스트만)
---
## 1️⃣ 소제목(검색형 명사구/질문)
본문: 비교표(글당 최대 1개) · ✔️/📖/🚧 이모지 줄(빈 줄로 구분) · 💡 팁 줄 · **핵심 굵게**
![슬롯: 절 내용 요약 장면]()          ← 절 끝(다음 소제목 직전) 1~2장
## 2️⃣ …
## n️⃣ 자주 묻는 질문 (FAQ)              ← 권장(2~4문답, **Q.** 굵게 / A. 문단)
[[관련글: …]] ×2~3                     ← "함께 읽으면 좋은 글"(B'에서 실제 URL)
## 📞 문의 안내: [연락처]               ← 고정 헤딩(초안의 마지막 줄)
(업체소개 이미지·장소·해시태그는 build_final.py가 붙임 — 초안에 쓰지 않음)
```

본문 절 전개 방식(구조 템플릿 4종 — 골격 안 `## 1️⃣`~ 절들을 어떻게 펼칠지, 하나를 골라 ⑦ `structure`에 기록):
- **절차형** — 1단계 → … → n단계 → 놓치기 쉬운 점. 주제: [이용·신청 순서 주제].
- **비교형** — A 소개 → B 소개 → 기준 비교표 → 상황별 추천. 주제: [비교할 상품·방식 주제].
- **체크리스트형** — 항목 1~n(소제목마다 1개) → 놓치기 쉬운 것. 주제: [준비물·고르는 기준 주제].
- **Q&A형** — 질문형 소제목 n개("~해도 되나요?"). 주제: [자주 묻는 질문 주제].

소제목 규칙:
- 본문 소제목 수: ④의 범위(목차·문의 제외, FAQ 포함).
- 형태: `## 1️⃣ ` 키캡 번호 + 검색형 명사구 또는 질문("~방법", "~순서", "~비용", "~할까요?") + 끝 이모지 선택. 글 제목을 반복하지 않는다.
- 목차 항목 = 본문 소제목 텍스트(번호 이모지 없이, 같은 순서).
- 소제목당 본문 글자수: [레퍼런스 0 소제목당 글자수 ×0.7~×1.3, 10단위 반올림 — 측정 후 기록].
- 소제목 앞 여백: 앞 내용 바로 다음 줄에 `ㅤ`(한글 채움 문자) 2줄(build_final.py `H2_FILLER_LINES`), 그다음 빈 줄 1개, 그다음 `## ` — build_final.py가 넣는다(초안에 쓰지 않는다). 네이버에서 문단 사이(빈 줄 1개)보다 한 칸 더 띄운 빈 줄 2개로 보인다.
- 강조 수단은 **굵게 + 💡 줄**. 음영 인용(`>`)은 0~1개. 비교표는 글당 0~1개.
- FAQ: `**Q. …?**` 줄 → 빈 줄 → `A. …` 문단, 2~4문답.

## ④ 분량과 비율
<!-- lint: min_chars=1500 max_chars=4000 min_h2=4 max_h2=7 min_images=3 min_sources=2 tags_min=5 tags_max=10 kw_min_body=3 kw_max_body=8 title_min=20 title_max=40 -->
<!-- 수치 원칙: 레퍼런스 0(own-style)이 있으면 구조·분량 특징 → 레퍼런스 0의 값 M(lint 세는 법으로 환산, SKILL 5단계 공식). 레퍼런스 1~4 메모가 가리키는 특징 중 0이 다루지 않는 것 → 그 레퍼런스 값(기본 ×0.7~×1.3, 이미지 상한 ×1.5). 메모가 없는 특징 → 레퍼런스 중앙값. 측정 전 초기값은 lint 기본값이다. -->

세는 법(lint와 같음): `chars` = 공백 제외 글자수, `## 📑 목차` 절(다음 `---`까지)·`**#…**` 해시태그 줄·`ㅤ`(U+3164) 제외. `h2_count` = `## ` 소제목, `## 📑 목차`·`## 📞 문의` 제외. `images` = 본문 이미지, 표지(`00-cover.*`)·업체소개(`business-intro`) 제외.
레퍼런스 0 환산(M): [측정표 원값 → lint 세는 법 환산값 — 측정 후 기록].

- 본문 글자수(공백 제외): **1500 ~ 4000자** (초기값 = lint 기본값. 측정 후: 하한 = max(1500, 100단위 내림(M×0.7)), 상한 = max(하한+1000, 100단위 올림(M×1.4)))
- 소제목(`##`) 수: **4 ~ 7개** (초기값. 측정 후: min_h2 = 4(공식 고정값), max_h2 = max(7, M))
- 이미지 수: **3장 이상** (초기값. 측정 후: 하한 = max(3, min_h2 + 1, 올림(하한 글자수 ÷ 이미지당 상한)), 권장 장수 = 올림(본문 글자수 ÷ 이미지당 목표))
- 이미지당 글자수: **목표 [M 10단위]자 이하, 상한 [목표×1.5]자** (측정 후 기록)
- 강조(굵게) 빈도: **1000자당 [내림(M×0.7)]~[올림(M×1.3)]회**, 핵심 수치·결론·FAQ 질문 줄에만 (측정 후 기록)
- 비교표: **글당 0~1개** (표는 붙여넣기 전용이라 업로드 폴백 위험 → 최대 1)
- 음영 인용(`>` 블록): **글당 0~1개** (강조는 굵게 + 💡 줄이 맡는다)
- 출처: **2개 이상**, 형식 `(출처: https://…)` 단독 괄호(⑧ 6). 초안·draft-v2.md에만 있고 업로드본에서는 제거된다 (lint 기본값. 지어내기 금지 원칙)
- 태그 수: **5 ~ 10개** (lint 기본값. 본문 끝 해시태그 줄은 같은 tags로 만든다)
- 제목: **20 ~ 40자**, keyword + title_region 지역명 1개. 본문 키워드: **3 ~ 8회** (lint 기본값 = naver-seo-checklist.md)

## ⑤ 이미지 규칙

반드시 지킬 것:
- **텍스트 렌더링 금지**: AI 이미지에 글자 렌더링 금지(간판·자막·숫자 포함). 글자는 본문으로. **예외 = 표지** `images/00-cover.png`(1000×1000 합성): 배경(글자 없는 AI 장면 또는 실사진) 위에 `scripts/make_cover.py`가 제목·브랜드 배지(business-profile.md `배지 문구`가 있을 때)·전화번호를 얹는다. 글자는 중앙 안전 영역 안. AI 배경 자체에는 글자가 없어야 한다.
- **얼굴 클로즈업 금지**: 인물은 뒷모습·원거리·손·제품 중심.
- **정보성 글 = AI 생성 이미지 허용. 홍보성 글 = 업체 실사진(photos/)만.**
- 사진 재사용 금지: 이전 글에 쓴 실사진 파일·AI 이미지는 다시 쓰지 않는다. **예외: `photos/business-intro.png`는 매 글 마무리 블록(⑥)의 고정 자산**이다.

배치·형식:
- 표지: 초안에 슬롯을 쓰지 않는다. image-plan `00` 행으로 이미지 단계가 만들고, 업로드 단계가 본문 맨 앞에 넣어 대표이미지로 지정한다.
- 본문 이미지: **절 끝(다음 소제목 직전) 1~2장**.
- 중간 작업 사진: 본문 중간 절에 **[업종의 대표 작업·제품 장면] 최소 1장**. 이미지 사이 본문이 이미지당 상한(④)을 넘지 않게 고르게.
- **캡션 없음**: 업로드본 이미지는 `![](경로)`(alt 비움). 슬롯 설명·image-plan alt는 내부용.
- 슬롯 문법: `![슬롯: 장면 설명]()` — 경로는 이미지 단계에서 채운다.

## ⑥ 마무리 규칙

줄글 CTA 단락은 쓰지 않는다. 글 끝 순서는 고정이다:

1. **FAQ**(권장, ③).
2. **관련글 링크 2~3개** — "함께 읽으면 좋은 글".
   - 고르는 기준: `work/own-posts.json`에서 (a) 같은 상품·서비스 주제 (b) 다음 단계 주제 (c) 최근 1년 이내 우선.
   - URL은 `https://blog.naver.com/<자기 블로그 ID>/<logNo>` 실제 값만(자기 블로그 ID = .env `NAVER_BLOG_ID`). 지어낸 URL 금지. 링크 텍스트는 그 글의 실제 제목.
3. `## 📞 문의 안내: [연락처]` — 고정 헤딩, 초안의 마지막 줄(lint·build는 `## 📞 문의` 접두로 판정).
4. `![](<작업 폴더 절대경로>/photos/business-intro.png)` — 업체명·연락처·주소는 이 이미지가 맡는다.
5. `:::place <장소 검색어>:::` — 네이버 장소 카드. 검색어는 business-profile.md 기본정보 표의 `장소 검색어` 행(비어 있으면 build_final.py가 멈춘다). 리허설에서 1번 결과가 이 업체가 아니면 검색어에 지역명을 더해 확정한다.
6. 빈 줄 → `**#태그 #태그 …**` — frontmatter tags(태그 안 공백 제거).

4~6은 `scripts/build_final.py`가 붙인다(초안에 쓰지 않는다). lint `closing_block`(upload)이 3~6 순서를 본다.
- 골격에 업체 안내 절은 없다. 본문에서 업체를 말할 때는 business-profile.md `강점` 범위와 ⑧ 금칙 안에서만. 홍보성 글은 ⑨.

## ⑦ 변주 축

| 축 | 선택지 | 기록 키 | 자기 글 현황(10편) |
|---|---|---|---|
| 도입부 유형 | 질문 / 상황 / 통계 / 오해 바로잡기 | intro | [측정 후 기록] |
| 구조 템플릿(본문 전개) | 절차형 / 비교형 / 체크리스트형 / Q&A형 | structure | [측정 후 기록] |
| 지역 키워드 조합 | business-profile.md `고객 지역` 중 2개 | region | [측정 후 기록] |
| 제목 지역 | region 2개 중 1개(아래 로테이션) | title_region | [측정 후 기록] |
| (축 아님) 글 유형 | 정보 / 홍보 — ⑨ 비율용 | type | [측정 후 기록] |

`cta` 축은 없다(마무리는 ⑥ 고정 블록). 소제목 수는 변주 축이 아니다 — ④ 범위 안에서 주제에 맞게 정하고 기록하지 않는다.

`title_region` 로테이션:
1. 게이트 1 **전에** 메인이 `work/variation-log.md`의 `title_region` 열을 읽고, business-profile.md `고객 지역` 순서에서 **최근 4편에 쓰이지 않은 첫 지역**을 "이번 제목 지역"으로 정해 게이트 1에 보여 준다. 로그가 없으면 `고객 지역`의 첫 지역.
2. 담당자가 고른 region 2개에 그 지역이 있으면 그것, 없으면 2개 중 로그상 더 오래전에 쓰인 쪽(안 쓰인 쪽 우선, 같으면 `고객 지역` 순서 앞쪽).
3. 제목에 그 지역명을 1개만 넣는다(lint `title_region`).

규칙: **최근 5편(work/variation-log.md)과 겹치지 않게** — 최근 5줄 **각각**과 비교해 4개 축(구조·도입부·지역·제목 지역) 중 **2개 이상**이 달라야 한다(한 줄이라도 1개 축만 다르면 다시 고른다). 고른 값은 final.md frontmatter `variation: {type, structure, intro, region: [..], title_region}`에 기록한다(type = 정보|홍보, ⑨의 비율 계산에 쓰인다).
업로드 성공 시 메인이 `work/variation-log.md`에 7열 한 줄을 추가한다: `YYYY-MM-DD | posts/NNN-slug | type | structure | intro | region | title_region`.

## ⑧ 금칙과 주의

1. 금칙어: business-profile.md "## 금칙어" 그대로(계약·브랜드 금칙어 목록, 공백 무시 비교). 단어만 피하는 게 아니라 같은 사실의 **암시도 쓰지 않는다**.
   - **의미 규칙**: 목록에 없는 표현도 금칙어가 가리키는 사실을 암시하면 쓰지 않는다(writer·fact-checker 몫).
2. 꼭 지켜야 할 점(business-profile.md 그대로).
3. 지어내기 금지: 수치·일정·수수료·법령 조항은 출처 URL 없이 쓰지 않는다. 모르면 `[출처 필요]`로 남기고 팩트체크 단계로 넘긴다.
4. 복붙 금지: 레퍼런스·소스 블로그 문장을 그대로 옮기지 않는다(구조와 이유만 따른다). 자기 기존 글 문장도 그대로 재사용하지 않는다(② 예시는 말투 기준일 뿐).
5. 금칙어는 `scripts/lint_post.py`가 business-profile.md "## 금칙어"에서 직접 읽어 검사한다(절이 비면 lint가 멈춘다). 목록 밖 암시 표현은 lint가 못 잡으므로 위 의미 규칙으로 writer·fact-checker가 본다.
6. **출처 표기 형식**: 숫자·조항 문장 끝에 `(출처: URL)` **단독 괄호**만 쓴다. 조항·시행일은 문장 본문에 쓴다 — "<법령명> 시행규칙 제N조제1항(시행 YYYY-MM-DD)에 따라 …입니다(출처: URL)." 한 괄호에 조항·시행일과 출처를 섞지 않는다(`(…제N조제1항, 시행 YYYY-MM-DD, 출처: URL)` 금지). `[출처](URL)` 링크형 금지, URL 안 괄호 금지. lint `source_format`(전 단계)이 `출처:` 출현 수와 단독 괄호 수를 대조한다. 출처는 초안·draft-v2.md·factcheck.md에 남고, 업로드본(final.md)에서는 `source_format`을 통과한 단독 괄호만 기계 제거된다(lint upload `sources_stripped`).
7. 말투: 해요체 종결은 lint `tone`이 센다(②, 전 단계).
