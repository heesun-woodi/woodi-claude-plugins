## 사용법

### 기본 동선 — 시트가 정본, 클로드 창은 스크래치

이번 워크숍은 **워크숍 시트 1개**를 워크스페이스로 씁니다. 각자 자기 클로드 창에서 카드를 돌리고, **카드의 마지막 출력을 시트의 지정된 자리에 붙여넣습니다.** 클로드 창에만 남아 있는 결과는 없는 것과 같습니다. 옆 구간 담당자이 볼 수 없고, 오후에 본인도 못 찾습니다.

1. 각 카드의 **프롬프트 코드블록을 통째로 복사**해 클로드 대화창에 붙여넣습니다.
2. `[대괄호]` 안은 본인 상황에 맞게 **치환**합니다. 치환하지 않으면 클로드가 되물어봅니다.
3. 출력이 나오면 **"확인할 것 / 의심할 것"** 항목을 하나씩 눈으로 대조합니다. 여기가 이 킷의 본체입니다. 숫자를 받는 게 목적이 아니라 **숫자를 의심하는 훈련**이 목적입니다.
4. 대조가 끝나면 카드의 **마지막 출력(시트 붙여넣기용 블록)을 복사해 각 카드에 적힌 착지 위치에 붙입니다.** 카드 하나가 끝날 때마다 붙입니다. 몰아서 붙이지 않습니다.
5. 카드는 **순서대로** 돌립니다. STEP 0을 건너뛰면 이후 전부 틀린 이벤트로 계산됩니다. 단 **STEP 3은 [Day 2] 개별 과제**이므로, [Day 1]에는 STEP 2 → STEP 4로 넘어갑니다.
6. MCP가 안 되면 **부록 B(백업 경로)**로 갑니다. 백업 경로도 **착지 시트 위치는 정규 경로와 같습니다.**
7. 카드는 `[분석도구]` MCP를 전제로 씁니다. **도구별 명칭 대응(이벤트 사전·퍼널·사용자 속성 등)은 README "데이터 소스 일반화" 표를 참조**하세요. 카드 본문은 도구 중립적인 일반 용어로 적혀 있습니다.

### 시트 붙여넣기 규칙 (전 카드 공통 — 이것만은 지켜주세요)

- **각 카드의 마지막 출력은 반드시 '시트 붙여넣기용 블록'입니다.** 형식은 **탭(tab) 문자로 구분된 값(TSV), 헤더 포함**, 컬럼 순서는 착지 시트 섹션의 컬럼과 **동일한 순서**입니다.
- **마크다운 파이프(`|`) 표는 시트에 붙이면 한 셀에 뭉개집니다.** 화면에서 읽기 좋은 파이프 표는 그대로 두되, **마지막에 TSV로 한 번 더** 뽑게 시킵니다. 카드 프롬프트 본문에 이 요구가 이미 들어 있습니다.
- 붙여넣을 때는 착지 섹션의 **첫 데이터 셀을 클릭하고 그냥 `Ctrl+V`(⌘V)** 하면 열이 자동으로 나뉩니다. 나뉘지 않으면 붙인 범위를 선택하고 `데이터 → 텍스트를 열로 분할 → 구분자: 탭`.
- 시트에 이미 헤더 행이 있으므로, 붙인 뒤 **중복된 헤더 행 1줄은 지웁니다.**
- 숫자가 텍스트로 붙었다면(왼쪽 정렬) 클로드에게 `숫자 컬럼에서 쉼표·%·₩ 기호를 빼고 순수 숫자만 넣어서 TSV를 다시 출력해줘`라고 요청합니다.

### 모든 카드에서 쓰는 공통 문구 2개 (외워두세요)

한 번 배워두면 카드 내내 씁니다. 카드별 팁에서는 반복하지 않습니다.

| 상황 | 그대로 복사해 쓰는 문구 |
|---|---|
| **환각 방지** (모든 카드 첫 실행 시) | `추정하지 말고 실제 쿼리 결과만 사용해줘. 쿼리가 실패하면 실패했다고 말해줘. 값을 만들어내지 마.` |
| **출력이 표가 아니거나 파이프 표만 나왔을 때** | `위 결과를 헤더 포함 탭 구분 TSV 코드블록으로만 다시 출력해줘. 설명 문장은 코드블록 밖에 써줘.` |

## 카드 0-1. 프로젝트와 이벤트 목록 전수 스캔

**목적**: 우리 프로젝트에 어떤 이벤트가 실제로 적재되고 있는지 전체 지도를 먼저 확보합니다.

```
[분석도구] MCP를 사용해서 내가 접근할 수 있는 프로젝트 목록을 먼저 보여줘.

그다음 [프로젝트명 또는 "가장 이벤트 볼륨이 큰 프로젝트"]를 골라서, 최근 90일 기준으로
발생한 이벤트를 전부 나열해줘. 다음 표 형식으로 정리해줘.

| 이벤트명 | 최근 90일 발생 수 | 고유 사용자 수 | 최초 적재일 | 최근 발생일 |

정렬은 발생 수 내림차순으로 하고, 발생 수가 0이거나 최근 30일 내 발생이 없는 이벤트는
표 아래에 "비활성 의심" 목록으로 따로 묶어줘.

마지막에 다음 세 가지를 한 줄씩 알려줘.
1. 이 프로젝트에서 데이터가 존재하는 가장 최근 날짜
2. 이벤트명 네이밍 규칙에서 관찰되는 패턴 (예: 화면 단위인지 액션 단위인지)
3. 이름만 봐서는 무슨 이벤트인지 알 수 없는 것 상위 10개

나는 [제품 유형 한 줄] "[제품명]"의 PM이야. 앱 여정은 대략
[전체 여정 단계 — 브리프 1절의 코어 여정을 화살표로 이어 적기] 순서야.

추정하지 말고 실제 쿼리 결과만 사용해줘. 쿼리가 실패하면 실패했다고 말해줘.
```

**기대 출력**
- 이벤트 목록 표 (발생 수 내림차순) + 비활성 의심 목록
- 데이터 최신 날짜 1줄
- 네이밍 규칙 관찰 + 정체불명 이벤트 10개

**📋 시트로 옮기는 것: 딱 1줄**

- `0_HOME`의 **데이터 최신 날짜** 칸에 날짜 한 줄만 적습니다.
- **이벤트 전수 목록은 시트에 옮기지 않습니다.** 클로드 창에 그대로 두고, 다음 카드에서 "앞에서 나열한 이벤트 목록"으로 계속 참조합니다. 이 카드에서 표를 옮기기 시작하면 STEP 0에서만 20분이 날아갑니다.
- 정체불명 이벤트·비활성 의심 목록 중 **본인 담당 구간과 관련된 것만** `0_HOME` 파킹랏(계측 공백)에 한 줄씩 적습니다.

**🤖 클로드 활용 팁**

- **치환 예시**: `[프로젝트명 또는 "가장 이벤트 볼륨이 큰 프로젝트"]` → 프로젝트명을 모르면 그대로 두고 돌리세요. 클로드가 접근 가능한 프로젝트를 먼저 나열해줍니다. 알고 있다면 `[제품명] (Production)`처럼 정확히 적습니다.
- **숫자를 믿기 전**: 데이터 최신 날짜가 오늘에 가깝지 않으면(예: 몇 달 전에서 끊김) **그 사실을 먼저 확정하고 시작합니다.** 이후 모든 카드의 "최근 90일"이 실제로는 다른 기간을 의미하게 됩니다.
- **못 찾을 때 재프롬프트**: `이벤트명에 'consult'가 포함된 이벤트를 모두 나열해줘` / `이벤트명에 'sign'이나 'auth'가 포함된 이벤트를 모두 나열해줘`처럼 **키워드로 좁혀** 다시 물어보세요. 여정 단계를 한국어로 물으면 못 찾습니다.

**확인할 것 / 의심할 것**
- [ ] **데이터 최신 날짜**를 먼저 봅니다. `[기존 데이터 자산]`(브리프 3절)의 최신 시점과 `[분석도구]`의 최신 시점이 같은지, 어느 쪽이 더 최근인지가 이후 모든 분석의 전제입니다. 완전주 기준 최신이 언제인지까지 적어두세요.
- [ ] `[전체 여정 단계]` 수보다 이벤트가 **훨씬 많다면** 화면 단위 로깅이 섞여 있는 것입니다. 액션 단위 이벤트를 골라야 합니다.
- [ ] 여정 단계보다 이벤트가 **적다면** 미들 퍼널이 아예 적재되지 않고 있을 수 있습니다. 이 경우 구간 B 분석은 STEP 3([Day 2] 과제)에서 막히므로 지금 알아두어야 합니다.
- [ ] 발생 수가 유난히 큰 이벤트(예: 화면 노출류)는 퍼널 단계로 쓰면 안 됩니다. 분모가 부풀어 전환율이 실제보다 낮게 나옵니다.

## 카드 0-2. 여정 단계 → 후보 이벤트 매핑

```
| 여정 단계 | 1순위 후보 이벤트 | 2순위 후보 | 판단 근거 | 확신도(상/중/하) |

[마지막 출력 — 시트 붙여넣기용]
```

## 카드 1-1. Depth 1 — 최상위 퍼널 현재 수치

**목적**: 내 담당 구간의 목표지표가 지금 몇 %인지, 분모·분자 절대값과 함께 확정합니다.

```
[분석도구] MCP로 아래 퍼널의 최상위 전환율을 계산해줘.

[집계 조건]
- 기간: [최근 90일 / 또는 데이터가 있는 최근 완전한 90일 구간]
- 플랫폼: 전체
- 세그먼트: 전체 사용자
- 전환 윈도우: [7일]

[퍼널 단계 — 카드 0-2에서 확정한 이벤트명으로 치환]
1. [1단계 이벤트명]
2. [2단계 이벤트명]
...
N. [최종 단계 이벤트명]

[출력 규칙 — 반드시 지켜줘]
1. **표는 하나만 만들어줘. 퍼널 표와 이탈 표를 나누지 말고 아래 6열 단일 표로 통합해줘.**
   | 단계 | 도달 수 | 전 단계 대비 | 첫 단계 대비 | 이탈률 | 이탈 인원 |
   ※ 전환율은 '전 단계 대비'와 '첫 단계 대비' 두 컬럼 모두 채워줘. 하나만 적으면 안 돼.
   ※ 이탈률·이탈 인원은 '그 단계로 들어오지 못한' 기준(직전 단계 → 이 단계)으로 계산해줘.
     1단계는 이탈률·이탈 인원을 비워둬.
2. 표 상단에 집계 기간·플랫폼·세그먼트·전환 윈도우를 고정 표기해줘.
3. 표 아래에 "이 퍼널의 분모 정의"를 **별도의 한 문장**으로 명시해줘.
   (예: "분모 = 기간 내 [1단계 이벤트]를 1회 이상 발생시킨 고유 사용자")

[마지막 출력 — 시트 붙여넣기용]
A. 위 6열 표를 **헤더 포함 탭 구분 TSV 코드블록**으로 다시 출력해줘.
   컬럼 순서 고정: 단계 / 도달 수 / 전 단계 대비 / 첫 단계 대비 / 이탈률 / 이탈 인원
   전환율·이탈률은 `62.4` 처럼 % 기호 없는 숫자로만, 인원은 쉼표 없이 숫자로만.
B. 그다음 **재현용 쿼리 조건**(기간·플랫폼·세그먼트·전환 윈도우·이벤트명 목록·
   코호트 정의)을 `항목 / 값` 2열 TSV로 따로 한 번 더 출력해줘.
   A와 B는 별개의 코드블록으로.

추정하지 말고 실제 쿼리 결과만 사용해줘. 쿼리가 실패하면 실패했다고 말해줘.
```

**기대 출력**
- 집계 조건이 고정 표기된 **6열 단일 퍼널 표** (전 단계 대비 / 첫 단계 대비 + 이탈률 / 이탈 인원)
- 분모 정의 1문장 (표와 별도 줄)
- **시트 붙여넣기용 TSV 2블록**: (A) 6열 퍼널 표 / (B) 재현용 쿼리 조건 2열

**📋 착지: `2/3_구간 탭` 섹션 S2**

- (A) 6열 TSV → **S2 퍼널 표**. 시트 S2의 컬럼 순서가 TSV와 같으므로 그대로 붙습니다.
- **분모 정의 1문장** → S2 위쪽 `분모 정의` 칸에 문장 그대로.
- (B) 쿼리 조건 TSV → **구간 탭 맨 오른쪽 RAW 붙여넣기 존**. 여기 없으면 나중에 숫자가 흔들릴 때 재현할 방법이 없습니다.

**🤖 클로드 활용 팁**

- **치환 예시**: `[최근 90일 / 또는 데이터가 있는 최근 완전한 90일 구간]` → 카드 0-1에서 확인한 최신 날짜가 오늘보다 한참 전이면 `2024-01-01 ~ 2024-03-31 (완전주 기준 최신 90일)`처럼 **날짜를 직접 박아** 넣습니다. "최근 90일"만 두면 빈 구간을 포함해 숫자가 낮게 나옵니다.
- **숫자를 믿기 전 — 합계 검산**: 각 단계의 `이탈 인원 + 다음 단계 도달 수 = 그 단계 도달 수`가 맞는지 한 줄만 직접 더해보세요. 안 맞으면 두 표를 다른 기준으로 계산한 것입니다.
- **100% 초과가 보이면**: 어느 컬럼이든 100을 넘으면 즉시 멈추고 `이 단계에서 분자와 분모에 각각 어떤 사용자가 포함되는지 정의를 다시 말해줘`라고 물으세요. 모집단 혼입 신호입니다(카드 2-2).

> **흔한 함정 — 전환율이 100%를 넘는 경우**
> 분자에는 기존 유저 재유입까지 들어가는데 분모는 신규 설치만 세면, 퍼널 시트의 전환율이 100%를 넘을 수 있습니다. 전환율은 정의상 100%를 넘을 수 없습니다. **100% 초과는 데이터 이상이 아니라 정의 이상의 신호**입니다.

**확인할 것 / 의심할 것**
- [ ] **두 전환율이 모두 나왔는지** 먼저 봅니다. 한 줄만 나왔으면 다시 시키세요. 여기서 섞이면 STEP 4의 기회손실 계산이 전부 틀어집니다.
- [ ] 어느 단계든 전환율이 **100%를 초과하면 즉시 멈춥니다.** 분자와 분모의 모집단이 다르다는 뜻입니다 (카드 2-2 참조).
- [ ] 이탈률이 큰 단계 ≠ 문제입니다. 퍼널 앞단은 원래 이탈률이 큽니다. **이탈률(%)과 이탈 인원(명)을 나란히** 봐야 합니다.
- [ ] 전환 윈도우를 바꾸면(7일 → 30일) 숫자가 크게 달라지는지 한 번 확인하세요. 크게 달라지면 우리 여정이 긴 여정이라는 뜻이고, 윈도우 설정 자체가 합의 대상입니다.

## 카드 1-2. Depth 2 — 코호트 분해 + 방문자 비중

**목적**: 전체 숫자가 숨기고 있는 코호트를 드러냅니다. **전체 지표는 문제영역을 숨깁니다.**

```
앞 카드에서 만든 퍼널을 아래 축으로 각각 분해해줘. 축마다 별도 표로 만들어줘.

[분해 축]
A. 신규 사용자 / 기존 사용자
B. 유입 채널 (광고 / CRM·푸시 / 오가닉 / 제휴 — 실제 프로퍼티 값에 맞게 조정)
C. 플랫폼 (또는 우리 서비스의 지배적 세그먼트 축)

[출력 규칙]
각 축의 표는 다음 컬럼을 반드시 포함해줘.

| 코호트 | 진입자 수 | 전체 대비 비중(%) | 최종 전환율 | 전체 평균 대비 |

- "전체 대비 비중"을 빠뜨리지 마. 전환율이 낮아도 비중이 1%면 문제영역이 아니야.
- "전체 평균 대비"는 배수로 표기해줘 (예: 0.5배, 1.5배).
- 각 축마다 표 아래에 "이 축에서 편차가 가장 큰 코호트"를 한 줄로 지목해줘.
- 마지막에 세 축을 통틀어 "편차가 가장 크게 벌어지는 축은 무엇이고, 왜 그렇게 보는지"를
  3줄로 정리해줘.

주의: 코호트 정의(특히 '신규'의 기준)를 어떻게 잡았는지 명시해줘.

[마지막 출력 — 시트 붙여넣기용]
위에서 구간별로 나눠 만든 표 3개를 **하나의 표로 합쳐서** 헤더 포함 탭 구분 TSV
코드블록으로 출력해줘. 맨 앞에 '분해 축' 컬럼을 추가해 어느 축의 행인지 구분해줘.

  분해 축 / 코호트 / 진입자 수 / 전체 대비 비중 / 최종 전환율 / 전체 평균 대비 배수

- '분해 축' 값은 `신규·기존` / `유입 채널` / `플랫폼` 중 하나로 통일해줘.
- 비중·전환율은 % 기호 없는 숫자, 배수는 `0.6` 처럼 숫자만.
- 쪼갤 프로퍼티가 없어 계산하지 못한 축은 그 축의 행 하나에 코호트 `측정 불가`,
  나머지 칸은 비워두고 넣어줘. 축 자체를 빼지 마.
```

**기대 출력**
- 축 3개 × 코호트별 표 (진입자 수 · **비중** · 전환율 · 전체 평균 대비 배수)
- 구간별 최대 편차 코호트 지목 + 편차가 가장 큰 축 3줄 정리
- **시트 붙여넣기용 TSV — '분해 축' 열이 붙은 단일 표**

**📋 착지: `2/3_구간 탭` 섹션 S3**

- S3은 축 구분 없이 한 덩어리 표입니다. '분해 축' 열로 정렬·필터해서 봅니다. 축마다 표를 따로 붙이지 마세요.
- 편차가 가장 큰 축 3줄 정리는 S3 아래 `해석` 칸에 문장으로 적습니다.

**🤖 클로드 활용 팁**

- **치환 예시**: `B. 유입 채널 (광고 / CRM·푸시 / 오가닉 / 제휴 — 실제 프로퍼티 값에 맞게 조정)` → 카드 0-3에서 확인한 실제 값으로 바꿔 적습니다. 예: `B. 유입 채널 (utm_source 값 기준: paid_ad / crm_push / organic / partner)`. 우리 말로 된 채널명을 그대로 두면 클로드가 매칭에 실패합니다.
- **숫자를 믿기 전 — 합계 검산**: 각 축마다 **비중 합이 100에 가까운지** 확인하세요. 한참 모자라면 `null`·`기타`가 빠진 것이고, 그 축의 결과는 그만큼 왜곡돼 있습니다.
- **'신규' 정의 되묻기**: `'신규'를 무엇으로 정의했는지 한 문장으로 말해줘 — 기간 내 첫 이벤트 발생인지, 설치일 기준인지.` 이 한 줄이 카드 2-2의 전제입니다.

**확인할 것 / 의심할 것**
- [ ] **쪼갤 때마다 편차가 커지는 축이 문제영역의 후보**입니다. 편차가 안 벌어지는 축은 버리세요.
- [ ] 비중이 작은 코호트는 전환율이 아무리 나빠도 문제영역이 되기 어렵습니다. 실험 표본이 모이지 않기 때문입니다. **(경험칙: 비중 5% 미만이면 후보에서 빼고 봅니다 — 정본 기준이 아니라 현장 눈금이므로, 우리 트래픽 규모에 맞게 그 자리에서 조정하세요.)**
- [ ] '신규'의 정의를 클로드가 무엇으로 잡았는지 확인하세요. "기간 내 첫 이벤트 발생"인지 "설치일 기준"인지에 따라 숫자가 달라집니다.
- [ ] 유입 채널에서 **CRM·푸시 비중이 크다면** 카드 2-2가 특히 중요해집니다.

## 카드 2-1. Depth 3 — 단계별 전환율과 누수 구간 특정

**목적**: 내 담당 구간 안에서 어느 구간이 가장 많이 새는지 인원 수까지 특정합니다.

```
내 담당 구간의 퍼널을 최대한 잘게 쪼개서 단계별 전환율을 계산해줘.

[퍼널 — 카드 0-2 매핑표의 이벤트명으로 치환]
[1단계] → [2단계] → [3단계] → ... → [최종단계]

[출력 규칙]
1. 단계별 표는 **카드 1-1과 똑같은 6열 형식**으로 만들어줘. 컬럼 순서를 바꾸지 마.
   | 단계 | 도달 수 | 전 단계 대비 | 첫 단계 대비 | 이탈률 | 이탈 인원 |
2. 이탈 인원이 많은 순으로 정렬한 별도 표를 하나 더 만들어줘 (화면 확인용).
   | 순위 | 구간 | 이탈률(%) | 이탈 인원(명) | 이 구간 진입자 비중(%) |
3. 각 구간에 대해 "사용자 관점에서 여기서 무슨 일이 일어나고 있을 것 같은가"를
   추측이 아니라 데이터로 뒷받침되는 것만 한 줄씩 적어줘.
   데이터로 알 수 없는 것은 "데이터로 확인 불가 — 정성조사 필요"라고 명시해줘.
4. 마지막에 "이탈률은 큰데 인원은 적은 구간"과 "이탈률은 작은데 인원은 많은 구간"을
   각각 지목해줘.

집계 조건(기간·플랫폼·세그먼트·전환 윈도우)은 표 상단에 고정 표기해줘.

[마지막 출력 — 시트 붙여넣기용]
A. 1번의 6열 표를 **헤더 포함 탭 구분 TSV 코드블록**으로 다시 출력해줘.
   컬럼 순서 고정: 단계 / 도달 수 / 전 단계 대비 / 첫 단계 대비 / 이탈률 / 이탈 인원
   (카드 1-1의 TSV와 완전히 같은 컬럼 순서여야 한다)
B. 3번에서 **"데이터로 확인 불가 — 정성조사 필요"로 표시한 항목만** 골라
   `구간 / 확인 불가한 질문` 2열 TSV로 따로 출력해줘. 해당 항목이 없으면 `없음` 한 줄.
   A와 B는 별개의 코드블록으로.

추정하지 말고 실제 쿼리 결과만 사용해줘. 쿼리가 실패하면 실패했다고 말해줘.
```

**기대 출력**
- **카드 1-1과 동일한 6열 형식**의 단계별 표
- 이탈 인원 순 정렬표 (화면 확인용)
- 데이터로 확인 가능한 것 / 정성조사 필요한 것의 구분
- **시트 붙여넣기용 TSV 2블록**: (A) 6열 표 / (B) 정성조사 필요 항목

**📋 착지: `2/3_구간 탭` 섹션 S2 (카드 1-1 아래 이어붙임)**

- (A) 6열 TSV → **S2의 1-1 표 바로 아래**. 컬럼 순서가 같으므로 세로로 이어 붙입니다. 어느 카드에서 나온 행인지 S2의 `출처` 열에 `2-1`이라고 적어둡니다.
- (B) **"정성조사 필요" 항목만** `0_HOME` 파킹랏의 **정성조사 필요** 구획으로 옮깁니다. 이탈 인원 순 정렬표는 시트에 옮기지 않습니다 — 6열 표를 정렬하면 같은 정보가 나옵니다.

**🤖 클로드 활용 팁**

- **치환 예시**: `[1단계] → [2단계] → ... → [최종단계]` → 카드 0-2 TSV의 '1순위 이벤트' 열을 그대로 화살표로 이어 붙입니다. 예: `consult_chat_opened → consult_session_started → client_info_submitted → quote_delivered`. 확신도 '하'인 이벤트는 넣기 전에 카드 0-3으로 한 번 확인합니다.
- **단계가 3개 이하로 나오면**: `이 구간을 화면 단위·폼 항목 단위까지 더 쪼갤 수 있는 이벤트가 있는지 다시 찾아줘`라고 되물으세요. 덜 쪼갠 퍼널은 문제영역을 특정하지 못합니다.
- **원인 단정에 제동**: 클로드가 "~해서 이탈한 것으로 보인다"고 쓰면 `그 문장이 데이터로 뒷받침되는지, 아니면 추측인지 각각 표시해줘`라고 시키세요. 정량은 **어디서** 새는지만 말해줍니다.

**확인할 것 / 의심할 것**
- [ ] **큰 이탈률 ≠ 문제.** 반드시 STEP 4의 벤치마크 비교와 함께 봅니다. 이 카드 결과만으로 문제영역을 정하지 마세요.
- [ ] **작은 이탈률이라도 볼륨이 크면 절대 손실이 큽니다.** "이탈률은 작은데 인원은 많은 구간"이 종종 진짜 답입니다.
- [ ] 클로드가 "사용자가 ~해서 이탈한 것으로 보인다"고 단정하면 의심하세요. 정량 데이터는 **어디서** 새는지는 말해주지만 **왜** 새는지는 말해주지 못합니다. 이건 문제정의 단계(KB 02장)와 Sprint 1(정성조사)의 몫입니다.
- [ ] 단계 수가 3개 이하로 나왔다면 아직 덜 쪼갠 것입니다. 화면·폼 항목 단위까지 내려갈 수 있는지 다시 물어보세요.

## 카드 2-2. 신규 코호트 vs 기존 유저 재방문 분리 — CRM 리터치 혼입 검증

**목적**: 하나의 지표에 두 모집단이 섞여 있는지 검증합니다.

```
아래 검증 과제를 수행해줘. 배경 사실을 먼저 읽고 시작해줘.

[배경 — 알려진 데이터 결함 (브리프 3절에서 복사)]
[알려진 데이터 결함 — 브리프 3절에서 복사]

[검증 과제]
[분석도구]에서 내 담당 구간의 퍼널을 아래 두 모집단으로 완전히 분리해서 각각 계산해줘.

(1) 신규 코호트 전환율
    = 해당 기간에 신규 유입된(첫 세션 발생) 사용자만 대상으로,

(2) 기존 유저 재진입 수
    = 신규가 아닌 사용자가 [목표 단계]를 발생시킨 수. 전환율이 아니라 '수'로 집계.

[출력 규칙]
1. (1)과 (2)를 절대 합산하지 마. 별도 표 두 개로 만들어줘.
2. 주간 단위 추이표를 만들어서, 두 숫자가 시간에 따라 어떻게 움직였는지 보여줘.
3. "(1)+(2)를 합쳐 하나의 전환율로 계산했을 때" 나오는 숫자도 참고용으로 한 번 계산해서,
   (1)과 얼마나 차이 나는지 배수로 보여줘.
4. 마지막에 답해줘: 우리가 현재 관리 지표로 쓰는 숫자는 (1)에 가까운가, (3)에 가까운가?

이 축으로 쪼갤 프로퍼티가 없다면, 없다고 명확히 말하고 대안 방법을 제안해줘.

[마지막 출력 — 시트 붙여넣기용]
위 결과를 **딱 4행**으로 압축해서 헤더 포함 탭 구분 TSV 코드블록으로 출력해줘.
컬럼은 `항목 / 값 / 근거·정의` 3열, 행은 아래 4개 고정 (순서 바꾸지 마):

  신규 코호트 전환율
  기존 유저 재진입 수
  합산 시 차이 배수
  판정 1문장

- '판정 1문장' 행의 값 칸에는 "현행 관리 지표는 (1)/(3) 중 무엇에 가까운가"를
  한 문장으로 넣어줘.
```

## 카드 3-3. 선행지표 → 최종 KPI 연결 검증  🗓 [Day 2] 과제

> **이 카드가 검증하는 것 (구간 B)**
> 구간 B의 **핵심 KPI는 `[구간 B 핵심지표]`**입니다. **`[구간 B 선행지표 후보]`는 최종 KPI가 아니라, 담당자가 "여기가 올라가면 최종 전환도 올라갈 것"이라고 가정하고 있는 선행지표 후보**입니다. 이 카드는 그 가정을 검증합니다 — **"`[구간 B 선행지표 후보]` → `[구간 B 핵심지표]`" 상관이 우리 데이터에 실제로 있는가.**

> **흔한 함정 — 인과 사슬이 중간에 끊겨 있는 경우**

- [ ] n이 20 미만이면 상관계수를 근거로 쓰지 마세요. 방향 참고용입니다.
- [ ] 대리 지표를 썼다면 (B) TSV에 `(대리)` 표기가 붙어 있는지 확인하세요. 표기 없이 골트리에 들어가면 다음 주에 아무도 구분하지 못합니다.
- [ ] `[분석도구]`에 최종 전환·매출 데이터가 없다면, 그 자체가 "중간지표와 최종지표를 연결해 볼 수 없는 구조"라는 발견입니다. `0_HOME` 파킹랏의 계측 공백에 적으세요.

## 카드 4-1. 벤치마크 소스 확보

**목적**: Gap을 계산하기 전에 **무엇과 비교할 것인지** 먼저 정합니다.

```
내가 문제영역 후보로 보고 있는 구간 [구간명]의 현재 전환율 [현재값]%에 대해,
비교할 벤치마크를 아래 우선순위대로 찾아줘.

[벤치마크 소스 우선순위 — 반드시 이 순서로]
1순위. 자사 인접 세그먼트 — 우리 데이터 안에서 같은 구간을 가장 잘 통과하는 코호트
       (예: 특정 유입채널 / 특정 플랫폼 / 특정 진입경로)
       → 조건이 가장 유사하고 반박이 어려움. 세그먼트 정의를 명확히 적을 것.
2순위. 자사 과거 시점 — 같은 지표의 과거 최고 수준 또는 특정 시점
       → 계절성·트래픽 믹스 변화를 보정해야 함
3순위. 업계 벤치마크 리포트
       → 분모 정의가 우리와 다를 수 있음. 반드시 정의를 확인하고 명시할 것
4순위. 경쟁사 관측치
       → 추정치이므로 신뢰도를 낮게 잡을 것

[출력 규칙]
| 순위 | 소스 | 벤치마크 값 | 분모 정의 | 신뢰도(상/중/하) |

- 1순위(자사 인접 세그먼트)는 [분석도구]에서 직접 계산해줘. 여기가 가장 중요해.
- 각 소스마다 "이 벤치마크를 쓸 때의 주의사항"을 한 줄씩 적어줘.
- 최종적으로 "이번 계산에 대표 벤치마크로 쓸 것 1개"를 골라주고 그 이유를 적어줘.

주의: [알려진 데이터 결함]에 극단값(예: 한 세그먼트의 전환율이 100%에 근접)이 있다면,
그 숫자는 모집단 혼입에 오염돼 있을 수 있으므로 그대로 벤치마크로 쓰면 안 돼.
쓰려면 신규 코호트 기준으로 다시 계산한 값을 써야 해.

[마지막 출력 — 시트 붙여넣기용]
A. 벤치마크 표를 헤더 포함 탭 구분 TSV 코드블록으로 출력해줘. 4행(1~4순위) 고정.
     순위 / 소스 / 벤치마크 값 / 분모 정의 / 신뢰도 / 주의 1줄
   확보하지 못한 순위는 벤치마크 값 칸에 `확보 필요`라고 쓰고 행은 남겨둬.
   벤치마크 값은 % 기호 없는 숫자로.
B. 그다음 **대표 벤치마크 1개**를 `항목 / 내용` 2열 TSV로 따로 출력해줘. 3행 고정.
     대표 벤치마크 값 / 소스 / 선정 사유
   A와 B는 별개의 코드블록으로.
```

**기대 출력**
- 4개 소스별 벤치마크 표 (값 · **분모 정의** · 신뢰도 · 주의 1줄)
- **시트 붙여넣기용 TSV 2블록**: (A) 4순위 벤치마크 표 / (B) **대표 벤치마크 1개 + 사유** (별도 행)

**📋 착지: `2/3_구간 탭` 섹션 S6**

- (A) → S6 벤치마크 표.
- (B) → S6 상단의 `대표 벤치마크` 칸. **이 값이 카드 4-2의 Gap 배수 수식과 카드 4-3의 목표 전환율에 그대로 물립니다.** 여기가 비어 있으면 S7·S8 계산기가 작동하지 않습니다.

**🤖 클로드 활용 팁**

- **치환 예시**: `[구간명]`·`[현재값]` → 카드 2-1의 6열 표에서 가져옵니다. 예: `구간 = 상세 조회 → 신청서 작성 시작`, `현재값 = 36.7`. **분모를 함께 적어주세요** — `현재값 36.7% (분모: 해당 구간 1단계에 도달한 신규 코호트)`. 분모 없이 넣으면 벤치마크와 분모가 어긋난 채로 계산됩니다.
- **분모가 다르면 무효**: 외부 벤치마크가 나오면 `이 벤치마크의 분모 정의가 우리 분모와 같은지 한 문장으로 대조해줘. 다르면 '사용 불가'라고 써줘.` 다른 분모끼리 나눈 배수는 아무 의미가 없습니다.
- **1순위를 건너뛰지 않게**: 클로드가 업계 리포트부터 들고 오면 `외부 자료 말고, 우리 [분석도구] 데이터 안에서 이 구간을 가장 잘 통과하는 코호트를 먼저 찾아줘`로 되돌리세요. 자사 인접 세그먼트가 가장 반박하기 어려운 벤치마크입니다.

**확인할 것 / 의심할 것**
- [ ] **외부 리포트를 찾기 전에 우리 안에서 가장 잘하는 코호트를 먼저 봅니다.** 1순위를 건너뛰고 3순위부터 시작하면 반박당합니다.
- [ ] 외부 벤치마크는 **분모 정의가 우리와 같은지** 반드시 확인하세요. 다르면 그 숫자는 쓸 수 없습니다.
- [ ] 목표 전환율은 **벤치마크까지만** 잡습니다. "상위 10%까지 개선하면"은 과대 추정으로 신뢰를 잃습니다.
- [ ] 자사 인접 세그먼트를 벤치마크로 쓸 때, 그 세그먼트가 원래 전환이 잘 될 수밖에 없는 조건(예: 고관여 유입)인지 확인하세요. 그렇다면 도달 불가능한 목표입니다.

## 카드 4-2. Gap 배수 — 입력값 산출

**목적**: Gap을 **배수**로 만들어 의사결정 가능한 형태로 바꿉니다.

> **계산 주체가 바뀝니다.** `Gap 배수 = 벤치마크 전환율 ÷ 현재 전환율` 이라는 나눗셈은 **시트 S7의 수식이 수행합니다.** 이 카드의 역할은 그 수식에 들어갈 **입력값 표(후보별 현재값 · 벤치마크 · 진입자 수)를 정확하게 뽑아오는 것**입니다.
> 클로드가 계산한 배수는 버리지 말고 **교차검증 열**에 넣습니다. 시트 수식 결과와 다르면 둘 중 하나가 틀린 것이고, 대개는 분모가 어긋난 것입니다.

```
아래 정의에 따라 Gap 계산에 들어갈 입력값을 정리해줘.

  Gap 배수 = 벤치마크 전환율 ÷ 현재 전환율

※ %p 차이가 아니라 반드시 '배수'로 표현해줘. (예: "12%p 낮다"가 아니라 "2.5배 낮다")
※ 최종 배수는 내가 시트 수식으로 계산할 거야. 너는 입력값을 정확히 뽑아주고,
  네가 계산한 배수는 '교차검증용'으로 따로 표기해줘.

[입력값]
- 구간: [구간명]
- 현재 전환율: [현재값]% (분모 정의: [분모])
- 벤치마크: [벤치마크값]% (소스: [소스], 분모 정의: [분모])

[과제]
1. 문제영역 후보 구간별로 아래 입력값을 채운 표를 만들어줘.
   | 후보 구간 | 기준 | 현재 전환율 | 벤치마크 | 진입자 수 | 분모 일치 여부 |
   - '기준'은 `전체` 또는 코호트명(앞 카드에서 편차가 가장 컸던 코호트).
     후보마다 `전체` 행과 코호트 행을 각각 만들어줘. 이 두 줄의 차이가 문제의 위치를 보여줘.
   - '분모 일치 여부'는 현재값과 벤치마크의 분모 정의가 같은지 `일치` / `불일치` 로 판정.
     불일치면 그 행은 계산할 수 없으니 그렇게 적어줘.
2. 각 행에 대해 네가 계산한 Gap 배수를 '교차검증' 열로 하나 더 붙여줘.
3. 마지막에 한 문장으로 정리해줘:
   "전체 기준으로는 벤치마크 대비 ○배 낮은데, [코호트] 기준으로는 △배 낮다."

[마지막 출력 — 시트 붙여넣기용]
위 표를 헤더 포함 탭 구분 TSV 코드블록으로 출력해줘. 컬럼 순서 고정:

  후보 구간 / 기준 / 현재 전환율 / 벤치마크 / 진입자 수 / 분모 일치 여부 / Gap 배수(교차검증)

- 전환율은 % 기호 없는 숫자, 진입자 수는 쉼표 없이 숫자로만.
- 3번의 한 문장은 TSV 밖에 따로 적어줘.
```

**기대 출력**
- 후보 구간 × 기준(전체/코호트)별 **입력값 표** (현재값 · 벤치마크 · 진입자 수 · 분모 일치 여부)
- 클로드가 계산한 Gap 배수 (교차검증용)
- "전체 기준 ○배 / 코호트 기준 △배" 한 문장

**📋 착지: `2/3_구간 탭` 섹션 S7**

- TSV → S7. **`Gap 배수` 열은 시트 수식(`= 벤치마크 ÷ 현재값`)이 자동 계산합니다.** 그 열에 손으로 값을 적지 마세요.
- 클로드가 낸 배수는 **`Gap 배수(교차검증)` 열**에 그대로 들어갑니다. 수식 결과와 눈에 띄게 다르면 그 행의 분모를 다시 봅니다.
- 한 문장 정리는 S7 아래 `해석` 칸에 적습니다.

**🤖 클로드 활용 팁**

- **치환 예시**: `[벤치마크값]% (소스: [소스], 분모 정의: [분모])` → 카드 4-1 (B) TSV의 대표 벤치마크를 그대로 옮깁니다. 예: `벤치마크: 62.5% (소스: 자사 인접 세그먼트 — 오가닉 유입 신규 코호트, 분모 정의: 해당 구간 1단계에 도달한 신규 사용자)`.
- **숫자를 믿기 전 — 분모 재확인**: `분모 일치 여부` 열에 `불일치`가 하나라도 있으면 **그 행의 배수는 무효**입니다. 계산을 진행하지 말고 카드 4-1로 돌아가 같은 분모의 벤치마크를 다시 찾으세요.

**확인할 것 / 의심할 것**

## C-3. 흔한 막힘과 개입 포인트

| 막힘 | 신호 | 코치 개입 |
|---|---|---|
| **클로드 창에만 결과가 있고 시트가 비어 있음** | 카드를 2~3개 연달아 돌렸는데 구간 탭 섹션이 그대로 비어 있음 | **그 자리에서 멈추고 TSV 블록부터 붙이게 합니다.** "위 결과를 헤더 포함 탭 구분 TSV로만 다시 출력해줘"를 대신 읽어줍니다. 분석을 더 하는 것보다 지금까지 나온 것을 시트에 올리는 게 우선입니다 |
| **STEP 0에서 이벤트를 못 찾음** | 30분 넘게 이벤트 탐색만 반복 | 25분에 끊고 "후보 없음"으로 확정 → 계측 공백 목록으로 전환. 완벽한 매핑을 기다리지 않습니다 |
| **파이프 표를 시트에 붙여 한 셀에 뭉개짐** | 시트 한 칸에 표 전체가 들어가 있음 | 붙인 셀을 지우고 TSV로 다시 받게 합니다. `데이터 → 텍스트를 열로 분할`로 수습하려 하지 말고 다시 받는 편이 빠릅니다 |
| **분모 논쟁 발생** | "전 단계 대비냐 첫 단계 대비냐"로 대화가 멈춤 | **이 논쟁을 넘기지 마세요.** 이게 곧 지표 정의 합의 과정입니다. 그 자리에서 확정하고 `01_goal-tree-template.md` 1절에 기록 |
| **클로드 출력을 그대로 수용** | 체크리스트를 안 읽고 다음 카드로 넘어감 | 담당 2인 중 체크 역할에게 소리 내어 읽게 합니다. 특히 100% 초과·모집단 혼입 항목 |
| **이탈률만 보고 결론** | "여기가 85%나 빠져요"로 문제영역 확정 | "퍼널 앞단은 원래 그렇습니다. Gap 배수와 인원은요?" |
| **문제영역을 3개 이상 선정** | 후보를 다 남기려 함 | 제외 사유표를 강제합니다. 뺀 이유를 쓰다 보면 스스로 좁혀집니다 |
| **기회손실을 낙관으로 계산** | 목표를 오염된 극단값이나 업계 상위로 잡음 | "벤치마크까지만, 대표값은 보수." 과대 추정 한 번이면 이후 숫자의 신뢰를 전부 잃습니다 |
| **인과로 단정** | "이 세그먼트가 문제라서 전환이 낮다" | 계측·믹스·행동 3분류(카드 2-3)로 되돌립니다 |
| **MCP 연결 실패** | 초반 15분 내 판별 | 즉시 부록 B로 전환. 붙잡고 있지 않습니다. 한 구간만 실패하면 그 구간을 백업 경로로 |
| **한 구간에 데이터가 아예 없음** | 미들 퍼널 이벤트 부재 | 이것 자체를 결론으로 씁니다 — "측정할 수 없는 것은 개선할 수 없다"가 그 구간의 첫 과제가 됩니다 |

## C-4. 세션 종료 판정

아래가 모두 있으면 종료합니다. **판정은 클로드 창이 아니라 시트를 보고 합니다.** 하나라도 없으면 무엇이 없는지 명시하고 [Day 2] 과제로 넘깁니다.

- [ ] 구간별 여정 단계 → 이벤트 매핑표 (후보 없음 포함) — 구간 탭 **S1**
- [ ] 구간별 퍼널 Depth 3 이상 분해표 (전 단계 대비 / 첫 단계 대비 2줄) — 구간 탭 **S2**, 코호트 분해 **S3**
- [ ] 신규 코호트 vs 기존 유저 분리 결과 (또는 "분리 불가" 판정) — 구간 탭 **S4** + `1_공통퍼널_분모` 확정 근거 칸
- [ ] 구간별 Gap 배수 + 벤치마크 소스 명시 — 구간 탭 **S6·S7**
- [ ] 보수 기준 기회손실 금액 — 구간 탭 **S8** (시트 계산기 결과)
- [ ] 구간별 4렌즈 표 + 문제영역 후보 1~2개 + **제외 사유표** + 세그먼트 유의성 5체크 — 탭 **`4_영역선정_순위`**
- [ ] 구간별 토론 안건 7행 — `4_영역선정_순위` 토론 안건 존
- [ ] `01_goal-tree-template.md` 6절 완성 조건 표 (두 구간 모두) + 탭 **`6_골트리_NSM`**
- [ ] NSM 결정 기록란 (`01_goal-tree-template.md` 4-4) — 결정 보류도 기록으로 남깁니다
- [ ] `0_HOME` 파킹랏에 계측 공백·정성조사 필요·보류 항목이 옮겨져 있음
