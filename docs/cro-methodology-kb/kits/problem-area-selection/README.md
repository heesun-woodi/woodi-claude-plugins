# 실험영역(문제영역) 선정 워크숍 킷 — 표준판

> KB [01. 문제영역 선정](../../01_problem-area-selection.md) 챕터의 방법론을 **고객사 워크숍 1일 + 개별 과제**로 실행하는 재사용 킷.
> AX 워크숍 방식 — AI(클로드)가 초안·숫자를 뽑고, 사람이 의심·토론·판단한다. 코치가 대신 분석해주지 않고, 고객사 멤버가 당일 직접 분석하도록 이끈다.

## 킷이 커버하는 방법론 (정본 — 변형 금지)

1. **선정 절차 5단계**: 최종 KPI 합의 → critical path 퍼널 정의 → 구간별 핵심 KPI 합의 → 선행지표 상관성 검증 → **이탈률 × 트래픽** 기준 핵심 퍼널(문제영역) 선정
2. **임팩트 4렌즈**: 볼륨 · 누수 · Gap · 비용(CAC). 영역 임팩트 ≈ 경험 사용자 수 × 개선 Gap
3. **Gap은 배수**: Gap 배수 = 벤치마크 전환율 ÷ 현재 전환율 (%p 아님). 벤치마크 우선순위 = ①자사 인접 세그먼트 > ②자사 과거 시점 > ③업계 리포트 > ④경쟁사 관측치
4. **기회손실 3식** (시트 계산기가 계산 — 클로드 계산값은 대조용):
   - ① 개선 대상 인원 = 영역 트래픽 × (목표 전환율 − 현재 전환율)
   - ② 증분 전환 수 = ① × 이후 퍼널 잔여 전환율 (현 수준 유지 가정)
   - ③ 기회손실 금액 = ② × 전환 가치 단가 × 기간 배수
   - 3시나리오: **보수 = Gap의 1/3 지점(대표값) / 중도 = 1/2 지점 / 낙관 = 벤치마크 수준**. 목표는 벤치마크까지만.
5. **분모 명시 2줄 원칙**: 모든 전환율은 "전 단계 대비"와 "첫 단계 대비"를 병기
6. **모집단 분리**: 신규 코호트와 기존 유저 재방문(CRM 리터치)은 절대 합산하지 않는다
7. **세그먼트 유의성 5체크** (①규모 5~10%+ ②실험군 분리 가능 ③행동 기반 정의 ④반복 측정 재현 ⑤전략 설계 가능) — **현장 눈금이며 정본 기준이 아님**. 이 라벨을 지우지 않는다
8. **카드 TSV ↔ 시트 열 1:1 정합**: 분석 카드의 마지막 출력(TSV)의 컬럼 순서 = 시트 착지 섹션의 컬럼 순서. 시트가 정본, 클로드 창은 스크래치
9. ICE가 언급될 때는 항상 **합산식(I+C+E, 각 1~10, 최대 30)**이며, 워크숍 주간의 ICE는 "그루밍 전 1차(잠정)" — [05 챕터](../../05_prioritization-ice.md) 참조

## 배포 절차 (코치)

1. **브리프 작성**: `00_client-brief-template.md`를 복사해 고객사 팩트·구간 정의·여정 단계·알려진 데이터 결함을 채운다. 이 브리프가 모든 문서의 치환 변수 값의 단일 출처다.
2. **치환**: 01~05 문서를 복사한 뒤 아래 치환 변수 용어집대로 브리프 값을 채운다. `[대괄호]`가 남아 있으면 배포 금지.
3. **시트 생성**: `scripts/build_workshop_sheet.py` 상단 CONFIG를 브리프 값으로 수정하고 실행한다 (`06_workshop-sheet-spec.md`가 구조 정본).
4. **리허설**: 카드 1장을 실제로 돌려 TSV → 시트 붙여넣기가 열 단위로 맞는지 확인한다.
5. **당일**: `03_workshop-facilitation-guide.md`의 블록 캐논대로 진행한다.

## 데이터 소스 일반화

카드는 `[분석도구]` MCP를 전제로 하며 Amplitude·GA4·Mixpanel 어느 것이든 동작한다. 도구별 개념 대응:

| 개념 | Amplitude | GA4 | Mixpanel |
|---|---|---|---|
| 이벤트 | Event | Event | Event |
| 이벤트 속성 | Event Property | Event Parameter | Event Property |
| 사용자 속성 | User Property | User Property / Audience | User Profile Property |
| 퍼널 | Funnel Analysis | Funnel Exploration | Funnels |
| 이벤트 사전 | Data(Taxonomy)/Lexicon | Events 설정 | Lexicon |

주의: GA4는 기본 보존 기간(2/14개월)과 샘플링이 있어 "최근 90일 완전주" 치환 시 보존 설정을 먼저 확인한다. Mixpanel·Amplitude는 코호트 정의(첫 이벤트 기준)를 MCP가 어떻게 잡는지 카드 1-2의 "신규 정의 되묻기"로 반드시 확인한다.

## 익명화 규칙

킷 문서의 사례 박스는 일반 함정 서술만 쓴다(수치는 범위·배수로만 표기). 고객사 실명·실수치는 배포용 사본에서 브리프 값으로 채워지는 것이며, 이 표준판에는 어떤 고객사 실명도 넣지 않는다.
