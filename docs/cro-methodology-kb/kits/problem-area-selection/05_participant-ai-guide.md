# 클로드(Claude) 활용 가이드 — 워크숍 당일 참가자용

> **용도**: [Day 1] 문제영역 선정 워크숍 시작 전 5분 안에 읽는 분석 도구 활용 안내입니다.
> **대상**: 워크숍 참가자 전원. 워크숍 시작 전 개인 화면에서 확인합니다.
> **표준판** — 배포 전 `[대괄호]` 전부 치환.

---

## 1. 시작 체크 (2분)

워크숍 시작 직후, 아래 프롬프트를 클로드에 그대로 복사해서 실행합니다.

```
연결된 [분석도구] 프로젝트 이름과 데이터가 적재된 가장 최근 날짜를 알려줘.
쿼리를 실제로 실행해서 확인해줘.
```

**기대 출력**: 프로젝트 이름 + 최근 날짜 (예: `YYYY-MM-DD`)

**확인·의심 포인트**
- 날짜가 수년 전이거나 "데이터 없음"이 나오면 연결이 잘못된 것입니다.
- 쿼리를 "실행했다"는 문장 없이 바로 숫자가 나오면 클로드가 추정한 것일 수 있습니다. "실제로 조회한 게 맞아?"라고 되물으세요.

**실패 시**: 즉시 손을 들어 코치에게 알립니다. 15분 내 판별 → 백업 경로([기존 데이터 자산]) 전환 여부는 코치가 결정합니다.

---

## 2. 좋은 분석 프롬프트의 구조

프롬프트에 아래 4요소가 모두 담겨야 의미 있는 숫자가 나옵니다.

| 요소 | 질문 | 예시 |
|---|---|---|
| **대상** | 누가 (세그먼트·코호트) | 신규 설치 유저 / AOS |
| **조건** | 기간·필터 | 최근 4주(완전주 기준) |
| **행동** | 무슨 이벤트 | [여정 단계 A] → [여정 단계 B] |
| **지표** | 무엇으로 측정 | 전환율, 주차별 추이 |

**나쁜 예** — 4요소 중 3개가 빠져 있습니다.
```
가입 전환율 알려줘
```
→ 분모가 뭔지, 기간이 언제인지, 코호트가 누구인지 없습니다. 클로드가 임의로 채워 넣어 검증 불가능한 숫자가 나옵니다.

**좋은 예** — 4요소가 모두 포함되어 있습니다.
```
최근 4주(완전주 기준) 동안 신규 설치 유저 중,
[여정 단계 A] → [여정 단계 B] 전환율을
주차별로 알려줘.
```

---

## 3. 결과를 시트로 옮기는 법

분석 결과가 나오면 아래 고정 문구를 그대로 복사해서 바로 보냅니다.

```
위 결과를 헤더 포함, 탭(tab) 문자로 구분된 TSV 코드블록으로만 다시 출력해줘.
```

그 다음:
1. 코드블록 안의 텍스트를 전체 복사합니다.
2. 워크숍 시트 해당 섹션의 **첫 번째 셀**에 붙여넣기(Ctrl+V 또는 Cmd+V)합니다.
3. 열이 나뉘지 않으면: 시트 메뉴 `데이터 > 텍스트를 열로 분리` → 구분자: 탭.

**정리 안 된 원출력**은 버리지 말고, 해당 구간 탭(`2_구간A_분석` 또는 `3_구간B_분석`)의 **맨 오른쪽 RAW 존**에 그대로 붙여둡니다. 나중에 숫자를 재검증할 때 원본이 필요합니다.

---

## 4. 숫자를 믿기 전 확인 3가지

숫자가 나왔을 때 바로 기록하지 말고 아래 세 가지를 먼저 확인합니다.

**① 분모가 뭔지 되물어라**

```
이 전환율의 분모와 분자를 정확히 말해줘.
```
전환율이 같은 이름이어도 분모가 다르면 완전히 다른 숫자입니다.

**② 합계를 검산하라**

코호트별로 쪼갠 숫자의 합이 전체 숫자와 대략 맞는지 확인합니다.  
크게 어긋나면 중복 집계 또는 필터 누락입니다.

**③ 전환율이 100%를 넘으면 즉시 의심하라**

전환율은 정의상 100%를 넘을 수 없습니다. 넘는다면 흔한 원인은 신규 유입과 리터치 재유입이 한 지표 안에 함께 세어지는 경우입니다. 100%를 넘는 숫자가 나오면 분모-분자의 모집단이 섞여 있는 것으로 먼저 의심합니다.

## 5. 막혔을 때 재프롬프트 패턴

**이벤트명을 못 찾을 때**
```
이벤트명에 [핵심 전환 키워드 — 예: 'checkout', 'signup']가 포함된 이벤트를 모두 나열해줘.
```

**결과가 이상하거나 너무 클/작을 때**
```
방금 쿼리의 조건(기간·필터·분모)을 그대로 보여줘.
```

**클로드가 추정·요약으로 답할 때 (환각 방지 고정 문구)**
```
추정하지 말고 실제 쿼리 결과만 사용해줘.
실행이 실패하면 실패했다고 말해줘.
```
이 문구를 어떤 프롬프트에도 붙여도 됩니다. 특히 처음 보는 이벤트나 지표를 물을 때 습관적으로 추가하세요.

---

## 6. 15분 룰

**한 지점에서 15분 이상 막히면 즉시 코치를 호출합니다.**

분석이 막히는 이유는 대부분 세 가지입니다: 이벤트명이 달라서 / 필터 조건이 맞지 않아서 / [분석도구]에 해당 데이터가 없어서. 세 번째라면 15분을 더 써도 해결되지 않습니다.

완벽한 숫자보다 **출처가 명확한 숫자**가 우선입니다. "정확하지 않을 수 있지만 이 조건으로 뽑은 숫자"라고 명시하고 넘어가는 것이 비워두는 것보다 낫습니다.
