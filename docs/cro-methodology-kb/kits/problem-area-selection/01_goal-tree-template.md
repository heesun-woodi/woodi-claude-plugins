# 01. 골트리(지표 트리) + NSM 토론 프레임 — 표준 템플릿

> **용도**: 실험영역 선정 워크숍 [Day 1]에서 "우리 목표와 선행지표가 어떻게 연결되는가"를 한 장으로 합의하기 위한 **토론 출발점 문서**입니다.
> **대상**: [고객사명] 코칭 참여 멤버 전원 — 워크숍 시작 시 함께 열어놓고 그 자리에서 채워 넣습니다.
> **표준판 — 배포 전 `[대괄호]` 항목을 전부 `00_client-brief-template.md`(브리프) 값으로 치환합니다. 치환이 남아 있으면 배포 금지.**

---

## 0. 이 문서를 읽는 법

이 문서는 **정답지가 아닙니다.** 트리의 가지와 지표 후보는 코치가 임의로 배치한 초안이고, 워크숍의 목적은 이 초안을 **지우고 고쳐서 팀의 트리로 만드는 것**입니다.

- **[ ] 빈칸**은 당일 토론으로 채웁니다. 미리 채워오지 않으셔도 됩니다.
- **[이벤트명 매핑: 당일 확인]** 표시는 `[분석도구]` 실제 이벤트명을 모르는 상태에서 "여정 단계" 수준으로만 적어둔 곳입니다. `02_analysis-prompt-cards.md`의 STEP 0을 돌려서 실제 이벤트명을 찾아 채웁니다.
- 트리의 가지를 **추가·삭제·이동하는 것이 이 세션의 핵심 작업**입니다. 초안대로 확인만 하고 넘어가면 세션이 실패한 것입니다.

### 이 세션이 끝났을 때 도달해야 하는 상태

> **"목표 → 선행지표 → 상관성 → 영향 사용자 규모 → 개선 여지 → 그래서 중요한 영역"** 을 한 장으로 막힘없이 말할 수 있는 상태.

6절의 완성 조건 표를 채우면 이 상태에 도달했는지 자체 판정할 수 있습니다.

## 1. 골트리 초안 — 전체 구조

```
[최종 KPI]  (후행지표 / Lagging)
         │
         │  ※ 이 사이의 연결이 현재 데이터로 확인되지 않음 → 4-3절 근거 A 참조
         │
    ┌────┴─────────────────────────────────────────┐
    │                                              │
[구간 A 목표지표]                                 [구간 B 목표지표]
 [구간 A 핵심지표]                                [구간 B 핵심지표]
 (범위: [구간 A 여정 범위])                        (범위: [구간 B 여정 범위])
 담당 제안: [구간 A 담당]                          담당 제안: [구간 B 담당]
```

**먼저 합의해야 할 것 — 두 목표지표의 분모**

| 목표지표 | 분모 후보 1 | 분모 후보 2 | 분모 후보 3 | 당일 확정 |
|---|---|---|---|---|
| A. [구간 A 핵심지표] | 앱 설치자 | 서비스 최초 사용자(가입 완료) | 핵심가치 경험 도달자 | [ ] |
| B. [구간 B 핵심지표] | [구간 A 핵심 전환] 완료자 | 대화/프로세스 시작자(고객 첫 응답) | 핵심 정보 제출 완료자 | [ ] |

> 분모가 다르면 같은 이름의 지표가 전혀 다른 숫자가 됩니다. 이후 모든 Gap 계산과 기회손실 환산이 여기서 갈리므로, **다른 논의보다 먼저 확정**합니다.

## 2. 구간 A 선행지표 후보 분해 — [구간 A 핵심지표] 전

여정 단계 기준으로 적었습니다. 실제 이벤트명은 당일 `[분석도구]`에서 매핑합니다.

```
[구간 A 목표지표] [구간 A 핵심지표]
  │
  ├─ 도달 (Reach) — 핵심가치 경험 지점까지 몇 명이 오는가
  │     ├─ 설치 → 가입 완료율                          [이벤트명 매핑: 당일 확인]
  │     ├─ 가입 완료 → 핵심가치 경험(활성화) 도달률     [이벤트명 매핑: 당일 확인]
  │     └─ 핵심가치 경험 → 전환 신청 진입률              [이벤트명 매핑: 당일 확인]
  │
  ├─ 전환 (Convert) — 전환 신청을 시작한 사람이 신청을 완료하는가
  │     ├─ 전환 신청 진입 → 신청 완료율                  [이벤트명 매핑: 당일 확인]
  │     ├─ 신청 페이지 체류·핵심 콘텐츠 도달률            [이벤트명 매핑: 당일 확인]
  │     └─ 신청 진입 → 폼 제출 완료율                    [이벤트명 매핑: 당일 확인]
  │
  ├─ 완료 (Complete)
  │     └─ 폼 제출 → [구간 A 핵심지표] 도달률              [이벤트명 매핑: 당일 확인]
  │
  └─ 코호트 축 (모든 가지에 공통으로 곱해서 봄)
        ├─ 신규 코호트 / 기존 유저 재방문(CRM 리터치)
        ├─ OS별 세그먼트 (해당 제품의 주요 플랫폼)
        └─ 유입채널 (전환광고 / CRM / 오가닉 / 제휴)
```

**구간 A에서 미리 알고 있는 것 (사전 진단 근거)**

> **[사전 진단에서 확인된 세그먼트 갭 — 브리프 3절의 정량 발견을 여기에 채운다]**
> 항목, 수치(또는 배수), 출처(데이터 범위·기준 시점 포함)를 행으로 추가한다. 확인 전이면 `미확인`으로 남긴다.

| 항목 | 수치 | 출처 |
|---|---|---|
| [세그먼트 A] 설치 → [구간 A 핵심지표] | [ ] | [ ] |
| [세그먼트 B] 설치 → [구간 A 핵심지표] | [ ] | [ ] |
| 갭 | [ ] | [ ] |

> **흔한 함정**: OS별·채널별로 설치 → 핵심 전환 전환율이 크게 벌어질 수 있습니다. 갭이 크다면 세그먼트 분리 후 각각 분모로 삼아야 Gap 계산이 유효합니다.

## 3. 구간 B 선행지표 후보 분해 — [구간 A 핵심지표] 이후

```
[구간 B 목표지표] [구간 B 핵심지표]
  │
  ├─ [선행지표 후보 — 고객사 담당자가 가정하는 중간 전환 지표.
  │    [구간 B 핵심지표]와의 상관성은 [Day 2] STEP 3에서 자사 데이터로 검증하며,
  │    [Day 1]에는 가정으로 명시하고 넘어갑니다.]
  │   [구간 B 선행지표 후보]
  │     │
  │     ├─ 시작 (Start) — [구간 A 핵심지표]를 완료한 사람이 실제로 프로세스를 시작하는가
  │     │     ├─ [구간 A 핵심 전환] → 고객 첫 응답률            [이벤트명 매핑: 당일 확인]
  │     │     ├─ 오픈 후 24h / 72h 내 첫 응답률               [이벤트명 매핑: 당일 확인]
  │     │     └─ 서비스 측 첫 메시지 → 고객 응답 소요시간      [이벤트명 매핑: 당일 확인]
  │     │
  │     ├─ 진행 (Progress) — 미들 퍼널. 현재 주간 관리 지표에 없는 구간
  │     │     ├─ 프로세스 시작 → 1차 정보 입력 진입률          [이벤트명 매핑: 당일 확인]
  │     │     ├─ 1차 정보 입력 진입 → 완료율                   [이벤트명 매핑: 당일 확인]
  │     │     ├─ 1차 → 2차 정보 입력 완료율                    [이벤트명 매핑: 당일 확인]
  │     │     └─ 입력 항목별 이탈 지점 (필드 단위)              [이벤트명 매핑: 당일 확인]
  │     │
  │     └─ 도달 (Reach) — 핵심 판단 근거(견적·결과 등)까지 가는가
  │           └─ 2차 정보 입력 → 핵심 결과(견적·제안서 등) 수령률  [이벤트명 매핑: 당일 확인]
  │
  ├─ 전환 (Convert) — 핵심 결과를 받은 사람이 [구간 B 핵심지표]까지 가는가
  │     └─ 핵심 결과 수령 → [구간 B 핵심지표] 완료율               [이벤트명 매핑: 당일 확인]
  │
  └─ 코호트 축
        ├─ 신규 코호트 / 기존 유저 재오픈
        ├─ OS별 세그먼트
        ├─ 사람 개입 변수 (담당자·운영 인력 그룹 등)
        └─ 상품군 / 카테고리 / 고객 세그먼트
```

**구간 B에서 미리 알고 있는 것**

- 주간 대시보드가 추적하는 단계는 `설치 → [구간 A 핵심 전환] → [최종 KPI]` 등 최소 단계뿐이며, **미들 퍼널(프로세스 시작 → 1차/2차 정보 입력)은 주간 관리 지표에 존재하지 않습니다.**
- 과거에 산발적으로 계산한 흔적이 있다면 해당 수치는 **자사 과거 시점 벤치마크 후보**로만 씁니다 — 주간 운영 지표로 이어지지 않은 수치는 현재 현황이 아닙니다.

> 구간 B 토론 시 유의: 사람(담당자·운영 인력)이 개입하는 구간이 있다면, 지표가 낮을 때 그것이 **제품 문제인지 운영 문제인지**를 트리 위에서 분리해두어야 이후 실험 설계가 가능합니다. 가지를 나눌 때 "제품이 바꿀 수 있는 것 / 운영이 바꿀 수 있는 것"으로 표시해두세요.

## 4. 북극성 지표(NSM) 토론

이 절은 **결론이 정해져 있지 않습니다.** 현행 NSM과 변경 후보를 [Day 1]에 토론하고, 결론을 4-4절 결정 기록란에 남깁니다. 준비물은 결론을 정해두지 말고 **토론 프레임만 제공**합니다.

### 4-1. 좋은 NSM의 4조건 (평가 기준)

| 조건 | 설명 |
|---|---|
| **가치 정합성** | 고객에게 전달되는 가치와 직결되는가 (매출·MAU 같은 허영 지표가 아니라 "고객이 가치를 경험한 빈도") |
| **선행성** | 사후 지표가 아니라 사업 성과를 **선행**하는 지표인가 |
| **측정 가능성** | 일·주 단위로 추적 가능한가 |
| **단일성** | 팀이 한 방향으로 움직일 수 있도록 **단 하나**인가 |

### 4-2. 후보 평가 표 — 당일 채움

각 칸에 O / △ / X 와 한 줄 근거를 적습니다.

| 후보 | 가치 정합성 | 선행성 | 측정 가능성 | 단일성 | 종합 판정 |
|---|---|---|---|---|---|
| **후보 1. [구간 A 핵심지표] (현행 유지)** | [ ] | [ ] | [ ] | [ ] | [ ] |
| **후보 2. [구간 B 핵심지표]** ※ 구간 B 목표지표와 정의가 동일합니다. 논의 시 참고. | [ ] | [ ] | [ ] | [ ] | [ ] |
| **후보 3. [제3후보: 당일 제안]** | [ ] | [ ] | [ ] | [ ] | [ ] |

**제3후보를 낼 때의 발상 가이드** (예시일 뿐, 이대로 쓰지 마세요)
- 두 구간의 중간 지점에 있는 지표 — 예: "핵심 결과(견적·제안서 등)를 수령한 주간 사용자 수"
- 가치 경험의 빈도를 담은 지표 — 예: "스스로 판단할 근거를 얻은 사용자 수"를 무엇으로 계측할 것인가
- 핵심 전환 이전에 고객이 가치를 느끼는 순간이 따로 있는가

### 4-3. 논의에 올릴 근거 (중립 제시 — 어느 방향의 결론도 아님)

**근거 A. [구간 A 핵심지표] → [최종 KPI] 주간 상관**

> **[고객사 자체 근거 — 브리프 3절의 정량 발견(선행지표 → 최종 KPI 상관 등)을 여기에 채운다]**
> 관계 쌍, 상관계수, 집계 단위(주간/월간), 표본 수(n), 기간을 행으로 추가한다. 미확인이면 `미확인` 명시.

| 관계 | 상관계수 |
|---|---:|
| [마케팅 투자 → 설치] | [ ] |
| [마케팅 투자 → 구간 A 핵심 전환] | [ ] |
| [설치 → 구간 A 핵심 전환] | [ ] |
| **[구간 A 핵심 전환 → 최종 KPI]** | **[ ]** |
| [마케팅 투자 → 최종 KPI] | [ ] |

> **흔한 함정 — 연결이 중간에 끊긴 지표**
>
> 마케팅비 → 설치 → 핵심 전환까지는 주간 상관이 뚜렷한데, **핵심 전환 → 최종 KPI의 주간 상관은 거의 없을** 수 있습니다. 이때 핵심 전환 수를 최종 KPI의 선행지표로 쓰고 있었다면 아래 두 해석이 맞섭니다.

- **"바꿔야 한다" 쪽 해석**: 돈을 써서 핵심 전환까지는 늘릴 수 있지만, 그 주의 최종 KPI는 늘지 않습니다. 인과 사슬이 핵심 전환에서 끊겨 있으므로 구간 A 핵심지표는 사업 성과를 선행하지 못합니다.
- **"유지해도 된다" 쪽 해석**: 상관은 인과가 아닙니다. 주간 단위 동시점 상관이므로 **핵심 전환 → 최종 KPI까지의 시차(lag)를 반영하지 못합니다.** 최종 KPI 집계 기준(결제일/처리일 등)이 미확정이라면, 시차를 보정하면 상관이 달라질 수 있습니다.
- **그래서 확인할 것**: 시차를 1주·2주·4주로 밀어 상관을 다시 계산하면 어떻게 되는가. (`02_analysis-prompt-cards.md` 카드 3-3 — **[Day 2] 개별 과제**. [Day 1]에는 이 항목을 '미확인'으로 두고 NSM 결정을 잠정으로 남길 수 있습니다)

**근거 B. 구간 A 핵심지표의 지표 정의 문제 (모집단 혼입)**

> **[고객사 자체 근거 — 브리프 3절의 지표 정의 결함 발견을 여기에 채운다]**
> 예: 특정 주의 전환율이 100% 초과, 모집단 혼입 원인과 규모, 기간별 추이의 해석 왜곡.

> **흔한 함정 — 모집단 혼입**
>
> 분자(핵심 전환 완료자)에는 신규 유입과 기존 유저 리터치가 함께 들어가는데 분모(설치자)는 신규만 세면, 전환율이 100%를 넘을 수 있습니다. **분자와 분모가 서로 다른 두 모집단의 비율**이므로 수치 자체가 전환율이 아니고, 기간별 "개선" 추이도 실제 개선인지 리터치 비중 증가의 결과인지 구분할 수 없습니다.

- **NSM 논의에 주는 함의**: 어떤 후보를 고르든, 그 지표를 **어떤 모집단으로 측정할 것인지**를 함께 정의하지 않으면 같은 문제가 반복됩니다. NSM 선정과 지표 정의는 한 세트입니다.

**근거 C. 두 개의 관문 질문** (후보를 2개로 좁힌 뒤 마지막에 던집니다)

1. *"이 지표 하나만 외부인에게 보여줬을 때, 우리가 뭘 하는 회사인지 설명되는가?"*
2. *"이 선행지표가 올라갔을 때 최종 KPI도 같이 올라간 과거 사례가 우리 데이터에 있는가?"* — 없으면 그 선행지표는 아직 **검증되지 않은 가정**입니다.

## 5. 트리 위에서 문제영역을 고르는 방법

골트리가 있으면 문제영역 선정이 "느낌"에서 **"트리 위 노드 선택"**으로 바뀝니다. 순서는 이렇습니다.

1. **가장 약한 선행지표(입력지표)를 식별**합니다 — 볼륨·누수·Gap·비용(CAC) 4렌즈로 봅니다.
2. 그 지표가 걸린 **퍼널 구간을 문제영역으로 선정**합니다.
3. 그 영역을 **문제트리 3depth**로 분해합니다. (→ [Day 2]~[Day 4] 개별 과제. 코치가 [Day 2]에 별도 템플릿을 배포합니다)
4. 가설을 그 영역에 **집중**시킵니다. (→ [Day 5] PSR 워크숍)

**선정 원칙 (코치 기준점)**: 기본적으로 이탈률이 높고, 그 퍼널을 경험하는 고객 트래픽이 많은 구간이 개선 임팩트가 클 확률이 높습니다. 이는 아래 임팩트 4렌즈의 **볼륨(트래픽 규모) × 누수(이탈률)** 두 렌즈가 동시에 불리한 구간을 우선 보라는 의미입니다.

**임팩트 4렌즈** — 문제영역 후보를 평가하는 네 개의 질문

| 렌즈 | 질문 | 데이터 |
|---|---|---|
| **볼륨** | 이 구간을 몇 명이 지나는가 | 퍼널 진입자 수, 지면 PV/UV |
| **누수** | 여기서 몇 %가 빠지는가 | 단계별 이탈률 |
| **Gap** | 벤치마크 대비 몇 배 낮은가 | 벤치마크·인접 세그먼트·경쟁사 |
| **비용** | 이 구간의 트래픽은 얼마짜리인가 | CAC, 광고 유입 비중, [전환 가치 단가] |

> **영역 임팩트 ≈ (그 영역을 경험하는 사용자 수) × (그 영역의 개선 Gap)**
> **Gap 배수 = 벤치마크 전환율 ÷ 현재 전환율** (%p 차이가 아니라 **배수**로 표현합니다)

네 번째 렌즈를 빼먹지 마세요. 광고비를 가장 많이 쓴 트래픽이 도착하는 지점의 전환율이 낮으면 **손실은 두 배**입니다. 매출을 놓치는 동시에 이미 쓴 획득 비용을 태우고 있습니다.
