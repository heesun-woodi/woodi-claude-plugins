# 공통 컨텍스트 브리프 — [고객사명] 실험영역 선정 워크숍 (템플릿)

> 이 문서는 워크숍 준비물 제작·치환에 관여하는 모든 사람(과 에이전트)에게 주입되는 **단일 기준점(SSOT)**이다.
> 여기 적힌 팩트·용어·공식과 어긋나는 내용을 쓰면 안 된다. 충돌 발견 시 산출물에 `⚠️확인필요`로 표기하고 브리프를 따른다.
> **코치 작성 가이드**: `[대괄호]`를 전부 고객사 값으로 채운 뒤에만 킷 문서 치환을 시작한다. 채울 수 없는 칸은 지우지 말고 `미확정`으로 남긴다 — 미확정 목록 자체가 워크숍 안건이 된다.

## 2. 용어·공식 정본 (위반 금지 — KB와 동일)

- **ICE = Impact + Confidence + Ease** (각 1~10점, 총점 최대 30). 곱셈식·평균식 금지.
  - QuickWin 기준: ICE ≥ 21 또는 (ICE ≥ 15 AND Ease ≥ 8)
  - 워크숍 주간의 ICE는 **"그루밍 전 1차(잠정)"** — Sprint 1 그루밍 후 재평가가 정본 절차. 모든 문서에 이 라벨 명시.
- **PSR** = Problem([타겟 세그먼트]+[문제영역/지면/시점]+[고객이 느끼는 문제]) / Solution([핵심가치]+[형태]) / Result([선행지표 1개]+[Baseline→Target])
  - **R = 선행지표** (최종 KPI 아님). 한 문장 원칙: 제3자가 추가 설명 없이 ICE를 매길 수 있어야 한다.
- **문제 Impact 점수 = (트래픽 영향 + 벤치마크 Gap + 정성 심각도) / 3** (각 10점 만점). 이 점수가 ICE의 I 근거값.
- **영역 임팩트 ≈ 경험 사용자 수 × 개선 Gap**. 임팩트 4렌즈 = 볼륨·누수·Gap·비용(CAC). **Gap 배수 = 벤치마크 전환율 ÷ 현재 전환율** (%p 아님).
- **기회손실 3식**: ① 개선 대상 인원 = 트래픽 × (목표−현재) / ② 증분 전환 수 = ① × 잔여 전환율 / ③ 금액 = ② × [전환 가치 단가] × 기간 배수. 3시나리오 = 보수(1/3 지점, 대표값) / 중도(1/2) / 낙관(벤치마크).
- **지표 3층**: Primary 정확히 1개(지면과 가까운 선행지표) / Secondary 2~5개(진단용) / Guardrail. Secondary에 "다음 퍼널 단계"를 넣는 것이 흔한 오설계.
- **현상 vs 문제 판별**: 그 문장에서 솔루션이 자동으로 따라 나오면 문제가 아니라 솔루션 역기술. 고객 언어 = 주어가 사람 + "~못 한다/~모른다/~느낀다".

## 3. 사전 진단 핵심 (인용 가능한 근거 — 고객사별 작성)

> 워크숍 카드들이 "우리 조직의 전례"로 인용하는 재료다. 없으면 해당 카드의 배경 블록을 일반 사례로 대체한다.

- **진단 총평 한 줄**: [예: "실험을 안 하는 조직이 아니라, 근거에 기반해 실험을 설계하는 전체 그림이 없는 조직"]
- **정량 발견** ([기존 데이터 자산] 기준 — 데이터 범위·완전주 기준 최신 시점 명시):
  - [선행지표 → 최종 KPI 상관 등 — 예: ○○→매출 주간 상관 ≈ 0 (n=△△)]
  - [지표 정의 결함 — 예: 전환율 100% 초과 주 존재 → 모집단 혼입]
  - [세그먼트 갭 — 예: OS별·채널별 큰 전환율 격차]
  - [계측 공백 — 예: 미들 퍼널이 주간 관리 지표에 부재]
- **정성 발견** ([조사 자산 명시]): [핵심 발견 3~5줄. 조사 간 모집단이 다르면 "합산 금지, 삼각검증만 허용" 명시]
- **[알려진 데이터 결함]** (백업 경로 카드 B-1의 입력): [오염 기간, 집계 기준 미확정, 하드코딩 배수 등 — 각각 "미검증 가정" 여부 표기]

- [참가자 부재가 있는 구간]의 산출물(문제영역 확정)은 [부재 전 마감일] 내 완료.
- MCP 장애 컨틴전시: 워크숍 초반 15분 내 판별 → 카드 부록 B([기존 데이터 자산] 백업 경로) 전환. 진행안에 이 분기 명시.

## 5. 산출물 규격

- 형식: 마크다운. **노션 이식 전제** — 헤딩/표/토글 가능한 단순 구조, HTML·복잡한 중첩 금지. 표는 6열 이하.
- 언어: 한국어. 고객사 멤버가 직접 읽는 문서 — 존댓말 설명체, 실무 톤(마케팅 문구체 금지).
- **금지**: 코치 내부 판단 혼입(`🔒 내부 메모` 류) / 타 고객사 실명·실수치 — 넣지 않는다(필요하면 「○○ 업종 기업」처럼 업종 자리표시만). 해당 고객사 자신의 수치는 실명 사용 가능.
- 워크숍용 프롬프트 카드는 복붙 실행 가능하게: 코드블록으로 감싸고, `[대괄호 치환 변수]` 명시, 카드마다 "기대 출력"과 "확인할 것 / 의심할 것" 병기.
- 각 문서 상단에 한 줄 용도 설명 + 대상(누가 언제 쓰는지) 명시.
