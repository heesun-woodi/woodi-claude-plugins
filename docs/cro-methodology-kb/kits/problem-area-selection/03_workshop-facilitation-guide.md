# 문제영역 선정 워크숍 진행안 + 기록지

> **용도**: [Day 1] 문제영역 선정 워크숍(블록 2~4) 진행 스크립트 + 그 자리에서 채우는 라이브 기록지. `02_analysis-prompt-cards.md` 구간별 분석 카드의 실행 순서를 `00_client-brief-template.md`(브리프) 4절 "워크숍 운영 캐논"에 맞춰 배열하는 **상위 래퍼**이며, 분석 카드를 대체하지 않습니다.
> **대상**: 진행 — [코치명]. 실습 — [구간 A 담당]·[구간 B 담당] (구간별 담당 — 2인 1조 권장). 참관 — [참관자] (선택).
> **표준판** — 배포 전 `[대괄호]` 전부 치환.

**전제**: 구간 A([구간 A명])·구간 B([구간 B명]) 두 영역은 [Day 1] 이전 킥오프·사전 미팅에서 이미 확정되어 있습니다. 이 워크숍의 목적은 두 구간 중 하나를 고르는 것이 아니라, **각 구간의 문제영역을 데이터 근거로 확정**하고 **북극성 지표(NSM) 논의를 토론 프레임 위에서 진행**하는 것입니다.

**시간 예산의 단일 기준**: `00_client-brief-template.md`(브리프) 4절 "워크숍 운영 캐논". 이 문서의 모든 타임박스는 그 표를 따릅니다.

**워크스페이스**: 이 워크숍의 정본 기록은 **워크숍 시트**(`06_workshop-sheet-spec.md` 스펙으로 생성)입니다 — 클로드 창은 스크래치, 각 카드의 마지막 TSV 블록만 시트에 붙입니다.

## 2. 사전 확인사항

워크숍 시작 5분 전, 코치가 아래를 확인합니다.

- [ ] 참가자 전원이 [분석도구] MCP로 접근 가능한 상태인가
- [ ] **워크숍 시트**: 참가자 전원에게 편집 권한이 공유되어 있는가 / 각 담당이 자기 구간 탭(`2_구간A_분석`·`3_구간B_분석`)을 열어둔 상태인가 / S7·S8 수식 셀과 `7_프롬프트_가이드` 탭의 보호(경고 모드)가 살아 있는가
- [ ] **TSV 붙여넣기 리허설 1회**: 아무 담당이나 `7_프롬프트_가이드`의 0번 프롬프트를 실행해 결과 TSV를 시트에 붙여 셀이 분리되는지 확인한다 (MCP 판별과 병행)
- [ ] 참가자 전원이 `05_participant-ai-guide.md`(클로드 활용 1페이지)와 문제정의 단계 도구(KB 02장) 정성 인풋 카드 사전 열람을 완료했는가 — 안 했다면 블록 2 시작 전 5분간 별도로 읽게 한다
- [ ] **MCP 작동 여부 판별**: 블록 2 시작 직후 15분 안에 실제 쿼리 1건을 돌려 MCP가 정상 작동하는지 확인한다. **실패 시 즉시 `02_analysis-prompt-cards.md` 부록 B([기존 데이터 자산] 백업 경로)로 전환** — 이 판별은 분모 확정 작업과 병행할 수 있다. 전환 여부는 시트 `0_HOME` 데이터 소스 판별 행에 구간별로 남긴다

## 5. 결정 방식 (합의 기준)

1. **항목 단위 합의**: 정의서의 각 항목(목표·선행지표·상관성·문제 근거·영향 사용자 규모·개선 여지·선정 근거)마다 "합의됨 / 보류"를 별도로 표기합니다. 정의서 전체를 한 번에 통과·반려하지 않습니다. 표기는 시트 `5_정의서` 탭의 합의상태 드롭다운(합의됨/보류/논의중)을 **코치가** 조작합니다 — 참가자가 스스로 "합의됨"을 찍지 않습니다.
2. **이견 처리**: 같은 구간 담당 내 이견은 그 자리에서 근거를 다시 확인해 조정합니다. 두 구간 간 우선순위 이견(예: 리소스 배분)은 이 워크숍에서 다루지 않습니다 — 두 구간은 이미 병행 진행이 확정되어 있습니다.
3. **캐스팅보트**: 항목 합의가 끝내 안 되면 [캐스팅보트]가 결정하고, 그 결정 사유를 정의서에 한 줄로 남깁니다.
4. **북극성 지표**: 이번 워크숍에서 결론을 내지 않는 것이 기본값입니다. 논의 내용(찬반 근거)만 기록하고, 최종 결정 시점은 별도로 합의해 정의서 상단에 명시합니다.
5. **보류 항목**: "보류"로 남은 항목은 담당자와 [Day 2]~[Day 4] 중 마감일을 지정합니다. [Day 5] 가설 백로그 워크숍 전까지 모든 항목이 "합의됨"으로 전환되어야 합니다.

> `../../01_problem-area-selection.md` 템플릿 A를 기반으로 이번 워크숍 범위에 맞춰 구성했습니다. 기회손실 금액 환산은 `02_analysis-prompt-cards.md` STEP 4에서 다루므로 이 정의서에는 요약만 담습니다. **문제트리(3depth)는 이 정의서의 범위가 아니며, [Day 2]~[Day 4] 개별 과제로 코치가 [Day 2]에 배포합니다.**

```markdown
# 문제영역 정의서 — [구간 A / 구간 B]

## 0. 기본 정보
- 구간: [구간 A명] 또는 [구간 B명]
- 담당: [이름 2인]
- 작성일 / 확정일:
- 데이터 소스: [[분석도구] MCP 정상 / 02_analysis-prompt-cards.md 부록 B 백업 경로 전환]

## 1. 목표
- 이 구간의 핵심지표: [구간 A = [구간 A 핵심지표] / 구간 B = [구간 B 핵심지표]]
  ※ 구간 B의 '[구간 B 선행지표 후보]'는 핵심지표가 아니라 **고객사가 가정하는 선행지표 후보**입니다 — 2절에 기록
- 분모(당일 확정, 01_goal-tree-template.md 1절 표 참조):
- 관련 퍼널 구간: [단계 나열]
- 북극성 지표(NSM)와의 관계: [합의됨 / 미결 — 논의 요약 한 줄]

## 2. 선행지표
- 이 구간에서 관찰할 선행지표:
- 선택 이유(왜 이 지표가 지면과 가장 가까운가):

## 3. 상관성 — 선행지표가 최종 KPI와 실제로 연결되는가
| 선행지표 | 최종 KPI | 상관관계(자사 데이터) | 판정 |
|---|---|---|---|
| | | | [연결 확인됨 / 연결 미확인 / 반증 데이터 있음] |
- 판정 근거(데이터 출처 포함):
- ⚠️ 브리프 3절([알려진 데이터 결함])의 선행지표-최종 KPI 상관 결과를 반드시 확인한다. 반증 데이터가 있으면 "미확인" 또는 "반증 있음"으로 정직하게 기록할 것 — 낙관적으로 판정하지 않는다.

## 4. 문제 근거 (정성)
- 정성 근거(VOC/인터뷰 최소 1건 — 문제정의 단계 도구(KB 02장) 정성 인풋 카드 우선 활용):
- 이 근거가 3절(상관성)·6절(개선 여지)의 정량 결과와 같은 지점을 가리키는가:

## 5. 영향 사용자 규모
- 이 구간을 통과하는 월간 사용자 수(또는 세션 수):
- 전체 대비 비중:
- 코호트 분해 결과(OS/매체/신규·기존 등):

## 6. 개선 여지
| 지표 | 현재값 | 벤치마크(출처) | Gap(배수) |
|---|---|---|---|
| | | | |
- 벤치마크 소스 우선순위: 자사 인접 세그먼트 > 자사 과거 시점 > 업계 리포트 > 경쟁사 관측치

## 7. 선정 근거 (3줄)
1. 경험 사용자 수:
2. 개선 gap:
3. 전략적 사유(비용/조직 우선순위):

## 완료 판정 체크 (핵심 7개)
- [ ] 전체 지표가 아니라 분해된 단위로 근거를 제시했는가
- [ ] Gap을 %p가 아니라 배수로 표현했는가
- [ ] 선행지표 → 최종 KPI 상관성을 자사 데이터로 확인(또는 미확인이라고 정직하게 기록)했는가
- [ ] 이 영역의 정성 근거(VOC/인터뷰 최소 1건)가 4절에 있는가
- [ ] 벤치마크의 정의(분모)가 우리와 같은지 확인했는가
- [ ] 이 영역의 트래픽 획득 비용 특성(CAC/광고 유입 비중)을 확인했는가
- [ ] 항목별 합의 상태(합의됨/보류)가 모두 표기되었는가
```
