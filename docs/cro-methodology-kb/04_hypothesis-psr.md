# 04. PSR 가설 한 문장 — 10단계 중 [4단계]

> 한 줄 요약: 3단계에서 나온 문제·솔루션·근거를 Problem / Solution / Result 세 요소로 압축해 **다른 사람이 ICE 점수를 매길 수 있는 한 문장**으로 만들고, 그루밍 5단계로 그 문장의 근거를 채운다.

---

## 개념·프레임워크

### 1. PSR이란

가설은 문제(Problem) → 해결책(Solution) → 결과(Result)의 논리적 흐름으로 구성되어야 한다. 세 요소가 한 문장에 모두 보이지 않으면, 그것은 가설이 아니라 아이디어다.

| 요소 | 질문 | 세부 구성 |
|---|---|---|
| **P — Problem** | 어떤 유저가, 어디서, 무슨 문제를 느끼나 | [타겟 세그먼트] + [문제영역/지면/시점] + [고객이 느끼는 문제] |
| **S — Solution** | 고객이 무엇을 얻는가 (형태는 Variant로) | **[솔루션 핵심가치(소구점)]만** (형태는 문장에서 빼고 Variant로) |
| **R — Result** | 어떤 지표를 얼마나 개선하나 | [Result 지표 1개] + [Baseline → **Target(필수)**] |

**PSR을 한 문장으로 쓰는 이유는 단 하나다.** 이 문장을 읽은 제3자(디자이너·개발자·의사결정권자)가 추가 설명 없이 ICE 점수를 매길 수 있어야 하기 때문이다. 점수를 매길 수 없다면 요소가 빠진 것이다.

### 2. 가설 한 문장 공식

**기본 공식**

```
"[문제]를 [솔루션]으로 바꾸면 [Result 지표]가 [YY%] 개선될 것이다"
```

**상세 공식**

```
"[AA]고객의 [BB] 경험을 [CC]으로 바꾸면 [XX]지표가 [YY]% 개선될 것이다"
```

두 공식은 같은 구조의 축약형·전개형이다. 아이데이션 단계에서는 기본 공식으로 빠르게 쓰고, 그루밍을 거치며 상세 공식으로 확장한다.

**확장형(세그먼트·트리거를 명시해야 하는 CRM·타겟팅 실험)**

```
"[영역/시점]에서 [문제]를 느끼는 [세그먼트]에게
 [솔루션 핵심가치]를 제공하면
 [지표]가 [Baseline]에서 [Target] 개선될 것이다"
```

온사이트 A/B 실험은 기본·상세 공식으로 충분하다. 노출 시점과 빈도가 변수인 CRM·푸시·인앱 캠페인은 확장형을 쓴다.

### 3. Result = 최종 KPI가 아니라 선행 반응 지표

**확정 원칙: Result 지표는 최종 KPI가 아니라, 해당 문제영역에서 솔루션이 적용됐을 때 사용자가 반응하면 즉시 변화할 선행 지표로 정의한다.**

왜 이 원칙이 필요한가.

| 이유 | 설명 |
|---|---|
| **인과 거리** | 상세페이지 배너 하나로 최종 매출이 움직였다고 주장하려면 중간의 수많은 단계가 모두 통제되어야 한다. 선행지표는 솔루션과 직접 인접해 있어 인과 해석이 가능하다 |
| **샘플사이즈** | 최종 전환율은 대체로 낮다(1~3%). 낮은 baseline은 필요 표본을 폭증시켜 실험 기간이 90일을 넘긴다. 선행지표는 baseline이 높아 현실적 기간 안에 유의성이 나온다 |
| **학습 해상도** | "매출이 안 올랐다"는 학습이 남지 않는다. "노출은 됐는데 클릭이 안 됐다"는 다음 가설을 낳는다 |
| **부작용 분리** | 최종 KPI를 Result로 잡으면 Guardrail과 구분이 사라진다. 선행지표=Result, 최종 KPI=Guardrail로 역할을 나눠야 판정 규칙이 작동한다 |

**잘못된 Result 설정의 전형**

> "빠른 배송 가능 지역 사용자가 특정 시간대에 앱을 열었을 때 빠른 배송 전용 화면으로 진입시키면 **장바구니 → 구매완료 전환율**이 5% 증가할 것이다"

솔루션은 "진입 화면 변경"인데 지표는 결제 단계다. 솔루션과 지표 사이에 상품 탐색·옵션 선택·장바구니 담기가 모두 끼어 있다. 이 경우 Result는 **상세페이지 → 장바구니 담기 전환율**로 내려야 한다.

**선행지표 → 최종 KPI 연결은 Uplift 시뮬레이션으로 한다.** Result 지표를 n% 개선했을 때 비즈니스 핵심지표가 1개월·12개월 기준 얼마나 증가하는지 추정하는 방식이다(그루밍 2단계에서 수행). 이 시뮬레이션이 있으면 "선행지표를 잡았는데 왜 이게 중요하냐"는 질문에 답할 수 있고, ICE의 Impact 근거가 된다.

### 4. 고객 언어 vs 공급자 언어

Problem은 **고객 입장에서, 고객의 언어로** 써야 한다. 공급자 언어로 쓰인 문제는 현상 기술일 뿐 문제 정의가 아니다.

| ❌ 공급자 언어 (현상) | ✅ 고객 언어 (문제) |
|---|---|
| 프로모션 상품 구매 전환율이 낮다 | 잠재고객은 프로모션 상품을 왜 사야 하는지 모른다 / 그런 상품이 있는지조차 모른다 |
| 결제 완료 전환율이 낮다 | 고객은 결제 직전에 지금 결제할 이유를 못 느낀다 / 가격이 더 내릴까 봐 망설인다 |
| CTA 버튼이 작다 | 사용자가 다음 단계로 넘어갈 버튼을 찾기 어렵다 |
| 회원가입 이탈률이 높다 | 신규 방문자는 가입해서 무엇을 얻는지 알지 못한 채 폼을 마주한다 |

**판별 규칙.** 문장의 주어가 지표(전환율·이탈률)면 공급자 언어다. 주어가 사람(고객은·방문자는·첫구매자는)이고 서술어가 "~못 한다 / ~모른다 / ~느낀다"면 고객 언어다.

고객 언어가 중요한 실질적 이유는 **솔루션의 범위가 달라지기 때문**이다. "전환율이 낮다"에서 나오는 솔루션은 버튼 색 변경에서 멈춘다. "왜 사야 하는지 모른다"에서 나오는 솔루션은 가치 제안, 비교표, 리뷰 노출, 혜택 프레이밍까지 확장된다.

### 5. Good / Bad 가설 예시

#### ❌ Bad 가설

**Bad 1**
> "제품 상세페이지(PDP)에 소구점(USP)을 개선하면 전환율이 증가할 것이다"

- 빠진 것: Solution의 구체적 방법(USP를 어떻게 개선?), Result의 예상 수치, 어떤 전환율인지
- 교정 방향: 어떤 소구점을 어떤 형태로 바꾸는지 명시 + 지표를 특정 구간으로 좁힘 + 목표 수치 부여

**Bad 2**
> "사용자에게 베스트 상품을 강조해서 노출하면 메인 → PDP 전환율이 5% 증가할 것이다"

- 빠진 것: Problem이 모호(어떤 사용자의 어떤 문제인가), "강조"의 구체적 방법 부재
- Result는 지표·수치가 있어 형식은 갖췄으나, P와 S가 비어 ICE 점수를 매길 수 없다

**Bad 3**
> "빠른 배송 가능 지역이 배송지로 설정된 사용자가 당일 주문 마감 직전에 앱을 열었을 경우 빠른 배송 전용 화면으로 진입시키면 장바구니 → 구매완료 전환율이 5% 증가할 것이다"

- P·S는 매우 구체적이나 **Result 지표 설정이 잘못됐다.** 솔루션(진입 화면 변경)과 지표(결제 완료) 사이 거리가 너무 멀다
- 교정: Result를 "상세페이지 → 장바구니 담기 전환율"로 변경

**Bad 4**
> "CTA 버튼 색상을 바꾸면 전환율이 높아질 것이다"

- Problem 자체가 없다. 왜 색상이 문제인지, 누가 무엇을 못 하고 있는지가 없음
- 구체적 수치도 없어 성공/실패 판정이 불가능
- 이 문장은 가설이 아니라 작업 지시다

#### ✅ Good 가설

**Good 1**
> "묶음 할인 대상 상품의 상세페이지(PDP)에서 묶음 할인 영역과 '묶음 담기' 버튼의 가시성을 높이면 PDP → 장바구니 담기 전환율이 5% 증가할 것이다"

| 요소 | 내용 |
|---|---|
| P | 묶음 할인 상품의 PDP를 보는 사용자 (지면 특정) |
| S | 묶음 할인 영역 + 묶음 담기 버튼 가시성 개선 |
| R | PDP → A2C 전환율 +5% (솔루션 바로 다음 행동 = 선행지표) |

**Good 2**
> "신규 사용자가 처음 메인 화면에 진입했을 때 기본 추천 목록 대신 인기 순위 목록을 먼저 노출하면 메인 → PDP 전환율이 5% 증가할 것이다"

| 요소 | 내용 |
|---|---|
| P | 신규 사용자, 첫 메인 진입 시점 (세그먼트 + 시점 특정) |
| S | 처음 보이는 목록을 기본 추천 → 인기 순위로 변경 |
| R | 메인 → PDP 전환율 +5% |

**Good 3 (가상 예시 — 오디오 강의 앱)**
> "오디오 강의 앱에서 첫 무료 강의를 끝까지 들은 비구독자(아직 구독할 이유를 못 느낌)에게 같은 시리즈의 다음 강의 1개를 무료로 열어 주면 두 번째 강의 재생 시작률이 20% 오를 것이다"

| 요소 | 내용 |
|---|---|
| P | 첫 무료 강의를 끝까지 들은 비구독자, 아직 구독할 이유를 못 느끼는 상태까지 적음 |
| S | 같은 시리즈 다음 강의 1개를 무료로 열어 줌 |
| R | 두 번째 강의 재생 시작률 +20% (최종 지표인 구독 전환율보다 앞에서 움직이는 반응 지표) |

이 예시는 선행지표 원칙을 보여준다. 목표는 유료 구독이지만, Result는 "재생 시작률"이다. 무료로 열어 준 강의의 직접 반응이 재생이기 때문이다. 재생 시작률 → 구독 전환율 연결은 Uplift 시뮬레이션으로 별도 추정한다.

**Good 4 (가상 예시 — 여행 예약 앱)**
> "숙소 목록에서 표시 가격과 실제 결제 금액이 다를까 봐 망설이는 방문자에게 세금·수수료를 포함한 총액을 목록 카드에서 먼저 보여주면 숙소 상세 진입률이 12% 개선될 것이다"

| 요소 | 내용 |
|---|---|
| P | 숙소 목록 방문자, 결제 금액을 몰라 상세 열기를 미룸 |
| S | 세금·수수료 포함 총액을 목록 카드에서 선제 노출 |
| R | 숙소 **상세 진입률** +12% — 예약 완료율이 아님 |

R이 "예약 완료율"이 아니라 "상세 진입률"인 점이 핵심이다. 목록 카드의 직접 반응은 진입이지 완료가 아니다. 완료는 결제 단계 자체의 문제이므로 별도 가설의 영역이다.

### 6. 가설 그루밍 5단계

**목적:** 목표 가설의 근거를 탄탄히 해 ICE 점수(특히 Confidence)를 높이고, 스프린트 열차에 탈 우선순위라는 명분을 만든다. 이것이 "random A/B가 아니라 더 빠르고 확률 높은 길"의 실체다.

| 단계 | 무엇을 하나 | 산출물 | 올라가는 ICE 항목 |
|---|---|---|---|
| **① Problem Definition** | 고객 언어로 문제 재정의 | 고객 언어 문제 문장 | (전 항목의 전제) |
| **② Problem Validation** | 진짜 문제 + 비싼 문제 근거 확보 | 정성·정량 근거 + Uplift 시뮬레이션 | **Impact ↑** |
| **③ Solution Description** | 대안 솔루션 2개 이상 아이데이션 | 대안 솔루션 목록 | Ease ↑ (더 쉬운 대안 발견 시) |
| **④ Solution Rationale** | 솔루션이 통할 근거 확보 | 근거 유형별 레퍼런스 | **Confidence ↑** |
| **⑤ Result / 목표수치** | Result 지표 확정 + 향상 목표 설정 | Baseline → Target | Impact ↑ (목표 근거 품질) |

#### ① Problem Definition — 고객 언어로

고객이 느끼는 문제를 해결해야 한다. 가설을 정의할 때는 문제를 겪고 있는 **고객의 경험에서부터** 시작한다.

작성 팁 — 데이터로 진짜 문제 찾기:

| 데이터 | 무엇을 보나 |
|---|---|
| 정량 | 트래픽은 많은데 이탈이 심한 영역 / 트래픽은 적은데 전환율이 좋은 영역 / 기획 의도와 다르게 사용자가 행동하는 영역 |
| 정성 | 실제 사용자가 어려움·불편을 느끼는 영역과 그 이유 (인터뷰, UT, 사용자 빙의 자체 UT) |

#### ② Problem Validation — 진짜 문제이고 비싼 문제인가

**진짜 문제에 대한 근거**

| 유형 | 확보 방법 |
|---|---|
| 정성 | UT / 인터뷰 / VOC — 실제로 그 문제를 느끼는지 관찰. CS로 많이 인입되는 문제인가 |
| 정량 | 해당 퍼널의 현재 전환율이 얼마나 못하고 있는지 |
| 정량 | 벤치마크 지표 비교 — 산업 평균, 경쟁사, 과거의 우리 |
| 정량 | 코호트 분석 — 해당 지표를 다른 고객군과 비교 |
| 정량 | 전체 타겟 고객 중 해당 문제를 겪는 고객 비중 |
| 정량 | 대상 지면·타겟 기준 일 UV (Impact의 트래픽 근거) |

**비싼 문제에 대한 근거 — Uplift 시뮬레이션**

가설 지표를 n% 개선했을 때 비즈니스 핵심지표가 1개월·12개월 기준 얼마나 증가할지 추정한다. 보수·중도·낙관 3시나리오로 만드는 것이 표준이다.

| 시나리오 | Result 지표 개선 | 월간 선행 결과 증분 | 연간 최종 KPI 증분 |
|---|---|---|---|
| 보수 | Baseline → 최소 개선 | | |
| 중도 | Baseline → 중간 개선 | | |
| 낙관 (실험 목표) | Baseline → 목표치 | | |

이 표가 있으면 "이 실험을 안 하면 잃는 돈"을 숫자로 말할 수 있다. 의사결정권자 설득에서 가장 강력하게 작동하는 산출물이다.

#### ③ Solution Description — 대안 2개 이상

문제를 정의하고 검증하는 과정에서 새로 떠오른 아이디어나 솔루션이 있다면 가설 리스트에 추가한다. **현재 가설의 솔루션만큼이나 문제를 적절히 해결할 수 있는 새로운 솔루션을 2개 이상 아이데이션한다.**

대안이 필요한 실질적 이유: 첫 솔루션이 Ease에서 막혔을 때(개발 2주 이상) 대체재가 없으면 그 문제 자체가 백로그에서 사라진다. 대안이 있으면 문제를 살린 채로 솔루션만 갈아탈 수 있다.

#### ④ Solution Rationale — 솔루션이 성공할 근거

Solution이 이 Problem을 해결하는 데 얼마나 효과적이고 검증된 솔루션인가.

| 근거 유형 | 확보 방법 |
|---|---|
| 경쟁사 UX | 얼마나 많은 경쟁사 또는 업계 1위가 쓰고 있는지 조사 |
| 지식 레퍼런스 | 실험 플랫폼 벤더의 성공 사례, 공개 케이스 스터디 |
| UT | 솔루션 시안을 사용자에게 보여주고 반응 관찰 |
| 과거 경험 | 담당자가 과거에 어디서든 해봤던 결과 데이터 |
| 학술 근거 | 행동경제학·소비심리학·인지과학 논문 및 적용 전술의 원리 |

Rationale을 찾는 과정에서도 새로운 솔루션이 떠오르면 추가한다. (③과 ④는 실무에서 왕복한다)

#### ⑤ Result — Primary Metric & 향상 목표

**Result 지표는 1개.** 솔루션이 직접 영향을 주는 선행 반응 지표를 고른다.

**향상 목표(목표 수치) 설정법 3가지**

| 방법 | 언제 쓰나 | 특징 |
|---|---|---|
| **신규 — 업계 벤치마크 서칭** | 새 기능이라 자사 데이터가 없을 때 | 목표 감을 빨리 잡고 내부 설득이 쉬움. 일반 지표는 구하기 쉬우나 specific한 데이터는 어려움 |
| **개선 — MDE 기반** | 기존 지면 개선일 때 | 실험 영역 트래픽 기반으로 MDE(통계적으로 유의하게 감지 가능한 최소 변화량)를 산정. 통계적으로 의미 있는 최소 기준을 정할 수 있고, 매출 시뮬레이션까지 하면 수지타산 계산 가능 |
| **기타 — 내부 데이터 Gap** | 위 둘이 어려울 때 | 동일 영역 과거 데이터, 유사 경험의 다른 영역 데이터, 해당 지표가 높은 타겟 코호트와의 Gap. 적당한 수준은 정할 수 있으나 정확도·설득력 낮음 |

**Gap 기반 목표 설정 예시(가상 수치):** 오디오 강의 앱의 무료 강의 청취자 → 구독 전환율이 4%이고 업계 범위가 3~9%라면, 같은 지표가 높은 코호트(강의를 2개 이상 들은 사용자, 7%)의 수준을 목표로 잡는다. 이런 실험이 쌓이면 자사 벤치마크가 생긴다.

### 7. 그루밍이 ICE를 어떻게 끌어올리는가

그루밍은 가설을 바꾸는 작업이 아니라, **같은 가설의 점수를 올리는 작업**이다.

| 그루밍 활동 | 근거 확보 | ICE 변화 |
|---|---|---|
| 퍼널 분석으로 해당 구간 이탈률 확인 | "이 문제를 겪는 사용자가 월 N명" | Impact 근거 확보 |
| 벤치마크 대비 Gap 계산 | "업계 중앙값 대비 10배 낮음" | Impact ↑ |
| Uplift 시뮬레이션 | "개선 시 연간 X억 증분" | Impact ↑↑ |
| 경쟁사 3사 스크린샷 확보 | "상위 3사 모두 채택" | Confidence 5 → 8 |
| 자사 과거 유사 실험 결과 인용 | "동일 지면 실험에서 +N% 검증" | Confidence 8 → 10 |
| 솔루션을 MVP로 축소 재설계 | "개발 없이 실험 툴로 구현 가능" | Ease 3 → 8 |

**Ease 최적화 원칙.** 그루밍 단계에서 누가 봐도 솔루션이 너무 어렵다고 판단되면, MVP 관점에서 다시 살펴보고 **가설의 목적에 집중해** 솔루션을 재설계한다. 구현 난이도와 QA 난이도가 상대적으로 낮은 화면을 실험 대상으로 잡는 것도 Ease를 올리는 방법이다.

주의: Ease를 올리려고 솔루션을 축소하다가 가설이 검증하려던 것 자체가 사라지면 안 된다. "Must have"(가설 검증에 반드시 필요)와 "Won't have"(빼도 검증 가능)를 구분한 뒤 후자만 뺀다.

## 절차

### Step 1. 3단계 산출물에서 P·S·R 재료 추출

| 요소 | 어디서 오나 |
|---|---|
| P | 2단계 문제 정의(고객 언어) + BIAS 태그 + 세그먼트 |
| S | 3단계 솔루션 카드의 접근 방식 + 적용 전술 + 구현 형태 |
| R | 3단계에서 정한 "솔루션의 직접 반응"에 해당하는 선행지표 |

### Step 2. 기본 공식으로 초안 작성

한 문장으로 쓴다. 이 시점에는 수치가 비어 있어도 된다.

### Step 3. 셀프 체크 — 제3자 ICE 테스트

작성한 문장을 팀원에게 보여주고 추가 설명 없이 I/C/E 점수를 매겨보게 한다. "누구를 대상으로?", "어떻게 바꾼다는 거야?", "어느 지표?" 질문이 나오면 해당 요소가 빠진 것이다.

### Step 4. Result 지표 적정성 검증

- Result가 최종 KPI인가? → 선행지표로 내린다
- 솔루션과 지표 사이에 다른 사용자 행동이 2개 이상 끼어 있는가? → 지표를 솔루션 쪽으로 당긴다
- 이 지표는 현재 측정되고 있는가? → 측정 불가면 7단계 세팅 의존성으로 표시

### Step 5. 그루밍 5단계 수행

①~⑤를 순서대로 채운다. 시간이 부족하면 ②(Impact 근거)와 ④(Confidence 근거)를 우선한다. 이 둘이 ICE 점수를 가장 크게 움직인다.

### Step 6. 상세 공식으로 확장 + 목표 수치 확정

Baseline을 실제 데이터로 채우고, 향상 목표 설정법 3가지 중 하나로 Target을 정한다. 목표 수치의 산출 근거를 한 줄로 남긴다.

### Step 7. 5단계(ICE 스코어링)로 이관

완성된 PSR 문장 + 그루밍 근거를 백로그에 등록한다.

### 체크리스트 — 가설 완성도

**PSR 형식 (그루밍 리뷰 5단계 기준)**

- [ ] "P를 S로 바꾸면 R이 개선될 것이다" 구조인가
- [ ] 독립변수(솔루션)와 종속변수(지표)의 인과관계가 명확한가
- [ ] 결과에 구체적 % 또는 수치가 포함되어 있는가
- [ ] 문제 주체가 명시되어 있는가 ("고객은…", "신규 방문자는…")
- [ ] 언제·어디서·무엇을 하다가 문제를 겪는지 구체적인가
- [ ] 공급자 언어가 아닌 고객 언어인가
- [ ] **S가 "고객이 무엇을 얻는가"(가치)로 끝나는가** — 형태(문구·UI·트리거)가 문장에 들어와 있지 않은가

**Result 지표**

- [ ] Result가 최종 KPI가 아니라 선행 반응 지표인가
- [ ] 솔루션과 지표 사이에 다른 사용자 행동이 끼어 있지 않은가
- [ ] Baseline이 실제 데이터로 채워졌는가 (추정이면 "추정" 표시)
- [ ] **Target이 채워져 있고** 설정 근거(벤치마크/MDE/내부 Gap)가 명시되었는가 — 빈칸이면 Impact·Confidence가 산출되지 않는다
- [ ] 선행지표 → 최종 KPI 연결이 Uplift 시뮬레이션으로 추정되었는가

**그루밍**

- [ ] 정성 근거 1개 이상, 정량 근거 1개 이상 있는가
- [ ] 대안 솔루션이 2개 이상 있는가
- [ ] Solution Rationale 근거가 1개 이상(런칭 직전이면 3개 이상) 있는가
- [ ] Counter Rationale(실패 가능성)을 검토했는가

**최종 관문**

- [ ] 이 문장만 읽고 제3자가 I/C/E 점수를 매길 수 있는가

## 워크드 예시

### 예시 1. 가상 예시 — 도서 구독 앱, 검색 결과 화면의 구독자

> 설명을 위해 지어낸 가상 예시다. 업종·수치·발화 모두 실제 사례가 아니다.

**Bad(그루밍 전)**
> "검색 결과의 클릭률이 낮다"

공급자 언어 + 솔루션 없음 + 수치 없음.

**그루밍 ① Problem Definition**
> "책을 검색한 구독자는 결과 목록에서 어떤 책을 내 플랜으로 바로 읽을 수 있는지 구분하지 못해, 상세를 열어 보기 전에 다시 검색하거나 나간다"

**그루밍 ② Problem Validation**

| 유형 | 근거 |
|---|---|
| 정량 | 검색 결과 → 책 상세 진입률이 탐색 경로 중 최저 구간 |
| 정량 | 플랜에 포함되지 않은 책이 섞인 검색 결과에서 재검색·이탈이 집중 |
| 정성 | 자체 UT에서 "이 책은 추가로 결제해야 하나요?"라는 질문 반복 |
| Uplift | 상세 진입률 개선 시 읽기 시작 수 증분을 3시나리오로 추정 |

**그루밍 ③ Solution Description (대안 2개 이상)**
- 현재안: 검색 결과 카드에 「구독으로 바로 읽기」 표시를 붙이고 상세 바로가기를 둔다
- 대안 A: 검색 결과 상단에 「내 플랜에서 읽을 수 있는 책만 보기」 필터를 둔다
- 대안 B: 플랜에 포함되지 않은 책을 결과 하단으로 정렬한다

**그루밍 ④ Solution Rationale**
- 경쟁사 UX: 동종 구독 서비스 다수가 목록 카드에 이용 가능 여부를 표시
- 행동경제학: Framing Effect — "추가 결제 없음"을 카드에서 바로 확인하게 해 망설임을 줄인다
- Counter Rationale: 표시가 카드 정보를 늘려 목록 훑기 속도가 떨어지면 오히려 진입이 줄 수 있음 → 검색 결과 스크롤 깊이를 Secondary로 관찰

**그루밍 ⑤ Result**
- 지표: 검색 결과 → 책 상세 진입률 (선행 반응 지표)
- Baseline → Target: 44% → 50% (가상 수치)
- 설정 방법: 내부 Gap — 플랜 포함 도서만 나온 검색 결과에서의 동일 지표 수준

**완성 가설**
> "책을 검색한 구독자에게 검색 결과에서 내 플랜으로 바로 읽을 수 있는 책인지 알려주면, 검색 결과 → 책 상세 진입률이 44% → 50%로 증가할 것이다"

Result가 "완독률"이나 "구독 유지율"이 아니라 "상세 진입률"인 점에 주목한다. 표시의 직접 반응은 진입이다.

### 예시 2. 자사 — 블로그 ATF 가치 제안 배너

자사 블로그를 소재로 한 예시이며 수치는 설명용 가상값이다. 실험설계서 수준으로 완성된 가설의 형태를 보여주기 위한 예시다.

**PSR 한 문장**
> "블로그 ATF에 가치 제안이 없어 페이지 목적을 즉시 파악하지 못하는 방문자에게, '데이터 기반 그로스 전략, 실전에서 검증한 인사이트'라는 VP 배너를 베스트 컨텐츠 상단에 추가하면, 블로그 체류시간이 15% 증가할 것이다"

**P — Problem**
> 블로그 ATF 영역(0~700px)에는 GNB, 서브탭, 브레드크럼, "베스트 컨텐츠" 섹션 제목, 피처드 아티클 1개 + 카드 3개가 배치되어 있다. 블로그의 대상 독자(마케터/PM), 콘텐츠 주제(데이터 분석·CRO·그로스), 구독/재방문 이유를 설명하는 가치 제안 요소가 전혀 없다. 방문자는 이 블로그가 나에게 어떤 가치가 있는지 인지하지 못한 채 스크롤 전에 이탈한다. — **BIAS Block 단계 실패**

**S — Solution**
> "베스트 컨텐츠" 제목 위에 VP 배너를 삽입한다. Variant A는 VP 텍스트만 추가하는 점진적 변경, Variant B는 VP + 인라인 뉴스레터 구독 CTA를 포함하는 급진적 변경. 적용 전술은 Pattern Interrupt(단조로운 브레드크럼→제목 흐름을 깸) + Framing Effect(일반 회사 블로그 → 실전 검증 인사이트 허브로 재프레이밍).

**R — Result**
> Primary: 블로그 글 클릭률(카드 → 개별 글 진입), Baseline ~12%(측정 필요) → Target +15% 상대 개선
> Guardrail: 블로그 이탈률, 페이지 로딩 속도

**Rationale 요약**
- 경쟁사/업계: HubSpot·Intercom·Drift 등 B2B SaaS 블로그 모두 ATF에 VP 헤드라인 + 구독 CTA 배치. NNGroup 연구 — 사용자는 평균 10~20초 내에 페이지 가치를 판단
- 행동과학: Pattern Interrupt + Framing Effect
- 과거 실험: 동일 블로그 VP 실험 미진행. 유사 B2B 블로그 사례에서 ATF VP 추가 시 평균 10~20% 체류시간 증가 보고(가상 수치)

**ICE (합산식)**: Impact 9 + Confidence 7 + Ease 8 = **24 / 30** → QuickWin (ICE ≥ 21)

> 원본 설계서에는 `(9+7+8)/3 = 8.0`으로 기재되어 있으나, 정본 합산식으로 환산해 24점으로 표기한다. 자세한 배경은 05 챕터 각주 참조.

### 예시 3. 자사 — 블로그 하단 맥락 기반 CTA

두 개의 문제를 하나의 실험으로 동시 해결하고, 두 Variant로 효과를 분리 측정한 사례다.

**PSR 한 문장**
> "블로그 본문을 읽은 사용자에게 기존 블로그 하단 영역을 '범용 CTA' 또는 '인지 단계·솔루션별 맞춤 CTA'로 제공하면, 블로그 → CTA 클릭률이 0.25% → 1.5%(6배)로 개선될 것이다. 특히 2축 개인화(Variant B)가 단순 범용 CTA(Variant A) 대비 추가 +20~40% 개선될 것이다"

**P — Problem (2개 동시)**
- 문제 #1 (Block + Act): 블로그 글을 읽은 사용자가 "마켓핏랩 팀과 대화하고 싶다"는 동기가 생겨도 행동으로 옮길 CTA 자체가 없다
- 문제 #2 (Interpret): 상단 GNB CTA가 있어도 글 주제와 맥락이 단절되어 "이 글의 내용을 실제로 어떻게 적용할지"에 대한 답이 느껴지지 않는다

**Problem Validation 요약**

| 검증 차원 | 근거 |
|---|---|
| 영향 사용자 규모 | 블로그 UV 4,800명/월 (사이트 전체의 ~45%) — Mixpanel 30일 |
| 퍼널 실측 | 블로그 방문 4,800 → CTA 클릭 12건(0.25%) → 데모 제출 3건(25%). 이탈률 99.75% |
| 해석 | 2→3단계 전환율 25%는 양호. 병목은 1→2 구간의 CTA 노출/인지 |
| 벤치마크 Gap | B2B 블로그 CTA 클릭률 중앙값 2.5~3.0%(가상 벤치마크) 대비 10배 낮음 |
| 정성 심각도 | CRO Checklist Fail 86%(6/7), BIAS Block 9/10, Act 9/10, Interpret 8/10 |
| Uplift 시뮬레이션 | 보수 0.5% → 연 2.25억 / 중도 1.0% → 연 6.75억 / 낙관 1.5% → 연 11.25억 |

**R — Result**
- Primary: 블로그 → CTA 클릭률, 0.25% → 1.5%
- 선행지표인 이유: 솔루션(CTA 삽입)의 직접 반응이 클릭이다. 데모 제출·계약은 Secondary·비즈니스 지표로 분리

**ICE (합산식)**: Impact 10 + Confidence 8 + Ease 7 = **25 / 30** → QuickWin (ICE ≥ 21)

이 사례가 보여주는 것은 **그루밍의 밀도가 Impact 10점을 만든다**는 점이다. 트래픽 영향 규모 10 / 벤치마크 Gap 10 / 정성 심각도 10 — 세 근거가 모두 실측으로 채워져 있어 점수 방어가 가능하다.

## 코칭 활용 포인트

### 세션 운영

- **워크샵 서사는 "나쁜 가설 → 무엇이 빠졌나 → 좋은 가설" 3단 구성으로 짠다.** 좋은 가설을 먼저 보여주면 "당연한 얘기"로 흘러듣는다. 나쁜 가설 3개를 먼저 주고 "빠진 것"을 표로 채우게 하면 참여도와 체득률이 크게 다르다. 표는 [나쁜 가설 / 빠진 것: Problem·Solution·Result] 3열로 만든다.
- **참가자 본인의 가설을 재료로 쓴다.** 예시로 배운 다음, 각자 백로그에서 가설 1개를 가져와 P·S·R로 분해하게 한다. 대부분 S나 R이 비어 있고, 그 공백을 스스로 발견하는 순간이 세션의 전환점이다.
- **Result 지표 논쟁에 시간을 배분한다.** 세션에서 가장 논쟁이 붙는 지점이 "Result를 매출로 잡으면 안 되나요"다. 논쟁을 회피하지 말고, 샘플사이즈 계산을 즉석에서 보여준다. baseline 1%와 15%로 각각 계산하면 기간 차이가 즉시 드러난다.
- **그루밍은 별도 세션으로 분리한다.** 가설 작성 세션과 그루밍 세션을 같은 날 하면 그루밍이 형식적으로 끝난다. 가설 작성 후 1주일 데이터 확보 기간을 주고, 다음 세션에서 근거를 들고 오게 한다.
- **Uplift 시뮬레이션 템플릿을 미리 채워서 배포한다.** 수식이 들어간 시트를 백지로 주면 세션의 절반이 엑셀 작업으로 사라진다. 숫자만 넣으면 3시나리오가 계산되는 형태로 준비한다.

### 흔한 수강자 질문

**Q. Result를 매출·최종 전환율로 잡으면 안 되나요?**
안 된다기보다 실험이 성립하지 않는다. 최종 지표는 baseline이 낮아 필요 표본이 폭증하고(기간 90일 초과), 솔루션과의 인과 거리가 멀어 결과 해석이 불가능하다. 최종 KPI는 Guardrail로 두고 지켜본다. 선행지표 → 최종 KPI 연결은 Uplift 시뮬레이션이 담당한다.

**Q. Baseline 데이터가 없으면 어떻게 하나요?**
"측정 필요"로 표시하고 추정치를 괄호로 넣은 뒤 가설을 진행시킨다. 단, 6단계 실험 설계 전까지는 반드시 실측해야 한다. Baseline 없이는 MDE도 샘플사이즈도 계산되지 않는다. Baseline 측정 자체가 7단계 세팅 의존성이 되는 경우도 흔하다.

**Q. 목표 수치를 얼마로 잡아야 하나요?**
신규 기능이면 업계 벤치마크, 기존 지면 개선이면 MDE 기반이 원칙이다. 다만 실무에서는 "달성 가능해 보이는 보수적 목표"를 잡는 편이 낫다. 업계 중앙값의 60% 수준을 목표로 두는 식이다. 목표를 과하게 잡으면 개선이 있었는데도 실패로 판정된다.

**Q. 고객 언어로 쓰라는데 우리는 고객을 만나본 적이 없습니다.**
그것 자체가 이 가설의 Confidence를 낮추는 요인이다. 최소 개입으로는 CS 인입 로그와 앱스토어 리뷰에서 고객 문장을 그대로 가져오는 방법이 있다. 그다음 스프린트에서 UT 5명을 붙인다.

**Q. 대안 솔루션 2개는 왜 강제인가요?**
첫 솔루션이 Ease에서 막히면(개발 2주 이상) 문제 자체가 백로그에서 사라지기 때문이다. 대안이 있으면 문제를 살린 채 솔루션만 갈아탄다. 또한 대안이 있어야 스프린트 플래닝에서 "왜 이걸 골랐나"에 답할 수 있다.

### 흔한 실수

| 실수 | 교정 |
|---|---|
| 지표는 있는데 문제가 없음 | "CTA 색상을 바꾸면 전환율이 오른다" 유형. Problem을 고객 언어로 먼저 쓴 뒤 되돌아온다 |
| 솔루션이 "개선한다"에서 멈춤 | "어떻게(How)"까지 적는다. UI 형태·문구·트리거 시점 |
| Result가 최종 KPI | 선행 반응 지표로 내린다. 최종 KPI는 Guardrail 또는 Uplift 시뮬레이션의 대상 |
| 수치가 없음 | 성공/실패 판정이 불가능하다. 추정이라도 넣고 근거를 표시한다 |
| 그루밍을 "문장 다듬기"로 이해 | 그루밍은 근거 확보 활동이다. 문장은 그대로여도 근거가 붙으면 ICE가 올라간다 |
| Uplift 시뮬레이션을 낙관 시나리오 하나만 작성 | 3시나리오(보수·중도·낙관)를 만든다. 보수 시나리오가 설득력을 만든다 |
| 세그먼트를 "전체 사용자"로 방치 | 세그먼트가 넓으면 효과가 희석된다. 문제를 실제로 겪는 사용자군으로 좁힌다 |
