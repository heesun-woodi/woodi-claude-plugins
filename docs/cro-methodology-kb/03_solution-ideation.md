# 03. 솔루션 아이데이션 + Rationale — 10단계 중 [3단계]

> 한 줄 요약: 2단계에서 우선순위가 정해진 문제를 입력으로 받아, 행동경제학 전술로 솔루션을 발산하고 → 각 솔루션의 표현형(Variant)을 나누고 → "이게 왜 통할 것인가"의 근거(Rationale)를 붙여, 4단계 PSR 가설로 넘길 재료를 완성한다.

---

## 개념·프레임워크

### 1. 이 단계의 입출력

| 구분 | 내용 |
|---|---|
| 입력 | 2단계 산출물 — 고객 언어로 정의된 문제 목록 + 각 문제의 BIAS 단계 태그 + 문제 Impact 점수 + 우선순위 1군 |
| 처리 | 문제 → 전술 선정 → 솔루션 발산(문제당 2개 이상) → Variant 발산(단일 축) → Rationale 확보 |
| 출력 | 솔루션 카드 N장 (Target Bottleneck / Applied Tactic / Solution / Variant 표 / Rationale) |
| 다음 단계 | 4단계에서 PSR 한 문장으로 압축, 5단계에서 ICE 스코어링 |

핵심 원칙 3가지.

1. **문제의 BIAS 단계가 전술을 결정한다.** 아이디어 회의에서 떠오른 순서대로 적는 게 아니라, "이 문제는 Block 실패다 → Block 전술 4종 중에서 고른다"로 좁힌다. Block 문제에 Social Proof를 붙이는 것은 단계 불일치이며, 그루밍 리뷰에서 Fail 처리된다.
2. **하나의 문제에 솔루션은 2개 이상.** 첫 아이디어가 최선일 확률은 낮다. 문제를 검증하는 과정에서 떠오른 대안을 반드시 가설 리스트에 추가한다.
3. **Solution과 Variant는 다르다.** 솔루션은 "무엇을 해결하는가", Variant는 "그 솔루션을 어떤 형태로 표현하는가". 이 둘을 섞으면 실험 결과 해석이 불가능해진다.

### 2. 왜 행동경제학 전술로 발산하는가

사용자의 뇌는 에너지를 아끼는 인지적 구두쇠(System 1, 무의식·직관)로 작동한다. 대부분의 이탈은 "제품이 나빠서"가 아니라 "뇌가 정보를 차단·오해·회피·망각해서" 발생한다. 따라서 솔루션은 UI를 예쁘게 만드는 작업이 아니라, **System 1의 특정 반응을 의도적으로 유발하는 설계**다.

전술 라이브러리를 쓰는 실질적 이점은 세 가지다.

- **발산의 품질 하한선을 보장한다.** 담당자 개인의 아이디어 총량에 의존하지 않는다.
- **Rationale이 자동으로 따라온다.** 전술 자체가 검증된 행동경제학 원리이므로 5단계 ICE의 Confidence 근거로 바로 쓰인다.
- **실험 간 학습이 누적된다.** "우리 서비스에서 Loss Aversion은 잘 먹히고 Decoy는 안 먹힌다" 같은 조직 자산이 쌓인다.

### 3. 행동경제학 전술 라이브러리 (12종)

BIAS 4단계별로 정리한다. 문제의 BIAS 태그와 같은 단계의 전술을 1순위로 검토한다.

#### Block (차단) — "뇌는 무관하거나 복잡하면 무시한다"

| # | 전술 | 정의 | 적용 예 |
|---|---|---|---|
| ① | **Cocktail Party Effect**<br>(칵테일 파티 효과) | 사용자의 이름·지역·관심사·유입 검색어·현재 상황을 직접 언급해 "내 이야기"로 인식시켜 주의를 끈다 | 유입 검색어를 히어로 헤드라인에 반영("'{검색어}' 찾으셨나요?"), 지역 기반 배송 가능 문구, 세그먼트 호칭("6개월 이상 사용 중이신 분께") |
| ② | **Pattern Interrupt**<br>(패턴 파괴) | 예상 밖의 움직임·대비 색상·질문형 헤드라인으로 무시 본능(Banner Blindness)을 깬다 | 배너처럼 생긴 영역을 본문 인라인 카드로 전환, 정적 이미지 → 짧은 루프 모션, 단조로운 목록 흐름 사이에 대비되는 패널 삽입 |
| ③ | **Curiosity Gap**<br>(궁금증 유발) | 질문형·미완성 헤드라인으로 정보 공백을 만들어, 뇌가 답을 찾기 위해 읽게 만든다 | "왜 3명 중 1명은 첫 주문에서 멈출까?", "이 3가지를 놓치면 할인이 사라집니다" — 답이 바로 아래 본문/CTA에 있어야 함 |
| ④ | **Visual Cueing**<br>(시선 유도) | 인물의 시선 방향·손가락·화살표·여백 대비로 CTA에 시선을 강제 이동시킨다 | 모델의 시선을 CTA 쪽으로 향하게 크롭, CTA 직전에 방향 아이콘 배치, CTA 주변 여백 확대 |

> Curiosity Gap은 통합 과정에서 회수된 전술이다. 질문형 헤드라인을 Pattern Interrupt에 묶어 쓰던 문서가 있으나, "무시 본능을 깬다"(Pattern Interrupt)와 "정보 공백으로 읽게 만든다"(Curiosity Gap)는 작동 원리가 다르므로 별도 전술로 유지한다. 단, Curiosity Gap은 답을 주지 않으면 낚시로 인식되어 Store 단계 손상을 유발하므로 반드시 답을 같은 화면에 둔다.

#### Interpret (해석) — "뇌는 익숙하고 유리한 대로 해석한다"

| # | 전술 | 정의 | 적용 예 |
|---|---|---|---|
| ⑤ | **Framing Effect**<br>(프레이밍) | "비용"이 아니라 "투자" 또는 더 작은 단위로 재정의해 저항감을 낮춘다 | "월 3만원" → "하루 1,000원(커피 한 잔 값)", "구독료" → "1회 상담 비용보다 저렴", 일반 블로그 → "실전에서 검증한 인사이트 허브" |
| ⑥ | **Labor Illusion**<br>(노동의 환상) | 처리 과정을 시각화해 "나를 위해 일하는 중"으로 느끼게 하여 결과의 가치를 높인다 | "최저가 47곳 비교 중…" 진행 애니메이션, 추천 알고리즘의 계산 단계 노출, 심사 진행 상황 단계 표시 |
| ⑦ | **Loss Aversion**<br>(손실 회피) | 얻는 혜택보다 "지금 떠나면 잃는 것"을 강조한다. 동일 크기의 이득보다 손실이 심리적으로 크게 작동 | "장바구니 쿠폰이 3시간 뒤 소멸됩니다", "지금 나가면 적용된 할인 12,000원이 사라져요", 남은 재고 수 표기 |

#### Act (행동) — "뇌는 귀찮거나 두려우면 미룬다"

| # | 전술 | 정의 | 적용 예 |
|---|---|---|---|
| ⑧ | **Decoy Effect**<br>(미끼 효과) | 팔고 싶은 옵션을 상대적으로 돋보이게 만드는 매력 없는 옵션을 옆에 배치한다 | 3개 요금제 중 중간 옵션을 비합리적으로 설계해 상위 옵션을 합리적으로 보이게, 단품 vs 세트 가격 대비 노출 |
| ⑨ | **Social Proof**<br>(사회적 증거) | 타인의 행동을 구체적 숫자로 보여 확신을 준다 | "현재 1,203명이 보는 중", "재구매율 1위", "이미 900개 팀이 쓰고 있어요", 최근 구매 알림 토스트 |
| ⑩ | **Goal Gradient**<br>(목표 가속화) | 진행바를 보여주되 시작부터 일부가 채워진 상태로 제시해 완주율을 높인다 | 5단계 가입 폼에서 1단계 진입 시 이미 20% 채워진 진행바, 스탬프 10개 중 2개 선지급, 콘텐츠 소비 완료 지점에 다음 단계 제시 |

#### Store (기억) — "뇌는 감정으로 기억한다"

| # | 전술 | 정의 | 적용 예 |
|---|---|---|---|
| ⑪ | **Peak-End Rule**<br>(피크엔드 법칙) | 경험의 정점과 마지막 순간에 가장 큰 시각적 보상을 배치한다. 사용자는 평균이 아니라 정점과 끝을 기억 | 결제 완료 화면의 축하 애니메이션, 제출 완료 시 개인화된 다음 액션 카드, 첫 배송 완료 알림의 특별 문구 |
| ⑫ | **Cognitive Dissonance 해소**<br>(인지 부조화 해소) | 사용자의 선택을 지지하는 문구로 구매 후 불안(Buyer's Remorse)을 제거한다 | "합리적인 선택을 하셨어요 — 같은 조건 대비 18% 절약", 주문 완료 후 "이 상품을 고른 분들의 재구매율 82%" |

**전술 조합.** 하나의 Variant에 2~3개 전술을 겹쳐 쓰는 것은 허용되지만, 그러면 "무엇이 효과를 냈는지" 분리 측정이 불가능해진다. 전술 효과 자체를 학습하고 싶다면 단일 전술로, 지표 개선이 급하면 조합으로 간다. 조합했을 때는 결과 보고서에 "전술 분리 미검증"을 명시한다.

### 4. 문제 유형 → 전술 매핑 테이블

진단에서 발견된 문제 유형에 따라 아래 전술을 우선 적용한다. 1순위가 리소스·브랜드 제약으로 불가능할 때 2순위로 내려간다.

#### Block 단계 문제 → 전술 매핑

| 문제 유형 | 1순위 전술 | 2순위 전술 | 예시 상황 |
|---|---|---|---|
| 가치 제안이 불명확함 | Pattern Interrupt | Visual Cueing | 첫 화면에서 뭘 파는지 모름 |
| 정보가 무시당함 | Cocktail Party Effect | Pattern Interrupt | 배너/혜택이 눈에 안 띔 |
| 본문을 읽지 않고 이탈 | Curiosity Gap | Pattern Interrupt | 스크롤 없이 나감 |
| 인지 과부하 | Visual Cueing | — | 선택지가 너무 많음 |
| CTA가 눈에 안 띔 | Visual Cueing | Pattern Interrupt | 버튼을 못 찾음 |

#### Interpret 단계 문제 → 전술 매핑

| 문제 유형 | 1순위 전술 | 2순위 전술 | 예시 상황 |
|---|---|---|---|
| 가격 저항 | Framing Effect | Loss Aversion | 비싸다고 느낌 |
| 혜택 이해 부족 | Framing Effect | Labor Illusion | 왜 사야 하는지 모름 |
| 가치 인식 부족 | Labor Illusion | Framing Effect | 서비스 가치를 못 느낌 |
| 손실 인식 부족 | Loss Aversion | Framing Effect | 지금 안 사도 된다고 느낌 |

#### Act 단계 문제 → 전술 매핑

| 문제 유형 | 1순위 전술 | 2순위 전술 | 예시 상황 |
|---|---|---|---|
| 결정 미룸/망설임 | Social Proof | Goal Gradient | 나중에 사야지 |
| 선택 장애 | Decoy Effect | Social Proof | 어떤 옵션이 좋은지 모름 |
| 신뢰 부족 | Social Proof | — | 이 브랜드 믿어도 되나 |
| 진행 포기 | Goal Gradient | Social Proof | 과정이 길어서 포기 |
| 긴급성 부재 | Loss Aversion | Social Proof | 굳이 오늘 안 사도 됨 |

#### Store 단계 문제 → 전술 매핑

| 문제 유형 | 1순위 전술 | 2순위 전술 | 예시 상황 |
|---|---|---|---|
| 경험 기억 안 남음 | Peak-End Rule | — | 구매 후 특별함 없음 |
| 구매 후 불안 | Cognitive Dissonance 해소 | Peak-End Rule | 잘 산 건지 걱정 |
| 재방문 동기 없음 | Peak-End Rule | Cognitive Dissonance 해소 | 다시 올 이유 없음 |

### 5. Solution vs Variant — 발산의 두 층위

| 층위 | 질문 | 결과물 | 개수 기준 |
|---|---|---|---|
| **Solution** | 이 문제를 어떤 접근으로 해결할 것인가 | 접근 방식 서술 | 문제당 2개 이상 |
| **Variant** | 그 접근을 어떤 형태로 구현할 것인가 | Control + 처치 2개 이상 | 단일 축으로 변형 |

같은 문제에 대한 3가지 층위 예시(예):

| 구분 | 예시 1 | 예시 2 | 예시 3 |
|---|---|---|---|
| Problem | 마감된 수업을 본 사용자가 대기 신청 방법을 찾지 못한다 | 대기 신청 버튼이 눈에 잘 띄지 않는다 | 대기 신청 버튼이 눈에 잘 띄지 않는다 |
| Solution | 시간표를 보는 내내 대기 신청 진입점이 보이도록 마감 표시 옆에 붙인다 | 대기 신청 버튼의 가시성을 높인다 | 대기 신청 버튼의 문구를 구체적으로 바꿔 눈에 띄게 한다 |
| Variant (구현 형태) | ① 시간표 칸 안 버튼 ② 하단 고정 바 ③ 상단 안내 띠 | ① 문구 ② 컬러 ③ 위치 | ① 문구안1 ② 문구안2 ③ 문구안3 |

예시 2가 흔한 실패 패턴이다. 문구·컬러·위치를 동시에 바꾼 3개 Variant를 돌리면, 어느 것이 이겨도 "왜 이겼는지"를 답할 수 없다. 예시 3처럼 축을 하나로 고정해야 학습이 남는다.

### 6. Variant 발산 원칙 — 단일 축 변형

가설을 검증할 때 모든 축을 한꺼번에 바꾸지 않는다. **그 가설을 가장 효과적으로 검증하는 단일 축 1개만 골라 변형하고, 나머지는 고정한다.**

**Variation 구분 축**

- 인바운드(온사이트·인앱): ① 핵심가치(대표 문구 + 이미지) ② 문구(표현) ③ 이미지 ④ CTA ⑤ CTA 클릭 후 랜딩 URL
- 아웃바운드(앱푸시·SMS·이메일): ① 핵심가치 ② 문구 ③ 이미지(SMS 제외) ④ CTA ⑤ 랜딩 URL

**축 선택 가이드 — 가설이 무엇을 검증하는가**

| 검증하려는 것 | 변형 축 |
|---|---|
| 어떤 가치가 통하는지 | ① 핵심가치 |
| 같은 가치의 말투·표현 | ② 문구 |
| 비주얼 효과 | ③ 이미지 |
| 행동 유도 문구 | ④ CTA |
| 랜딩 목적지 | ⑤ URL |

핵심가치 자체를 검증하는 가설이라면 핵심가치는 고정하고(① 축 사용 안 함), 전달 방식(②~⑤) 중 가장 적합한 1개로 변형한다.

**모든 변형 공통 — 절대 불변 (어기면 실험 오염)**

- 캠페인 가설이 해결하는 문제
- 타겟 세그먼트
- Metric (특히 Primary·Guardrail)
- 노출 시점·노출 횟수 (트리거·빈도)

**점진 vs 급진.** Variant 2개를 만들 때 하나는 점진적 변화(텍스트만 추가, 기존 톤 유지), 하나는 급진적 변화(배경 패널 + CTA까지 포함)로 설계하면 "최소 개입으로 충분한가, 더 큰 개입이 필요한가"를 동시에 답할 수 있다. 이 구조는 다음 스프린트의 구현 비용 의사결정에 직접 쓰인다.

**MVP 관점 축소.** 발산한 Variant가 개발 의존성이 크면, 5단계 Ease 점수가 떨어져 스프린트에 못 탄다. 아래 4문항으로 축소한다.

1. 이 Variant는 고객의 어떤 구체적 행동(Action)을 유도하는가
2. 이 기능이 고객의 어떤 Pain Point를 해결하는가
3. 가설 검증에 반드시 필요한(Must have) 요소는 무엇이고, 빼도(Won't have) 검증이 되는 요소는 무엇인가
4. 개발팀 도움 없이(혹은 최소화하여) 실험 툴로 구현 가능한가

3번에서 걸러지는 것들이 대체로 "디자인 욕심"(과한 이미지, 부가 설명, 추가 혜택 배너)이다. 빼도 가설이 검증되면 뺀다.

### 7. Solution Rationale — 이 솔루션이 잘될 근거

Rationale은 5단계 ICE의 **Confidence 점수의 근거값**이다. Rationale이 없으면 Confidence는 1~3점을 넘을 수 없고, 그 가설은 스프린트에 타지 못한다.

| 근거 유형 | 확보 방법 | Confidence 기여 |
|---|---|---|
| **경쟁사 UX** | 업계 1위 또는 다수 경쟁사가 같은 패턴을 쓰는지 조사. 스크린샷으로 증거 남김 | 다수 채택 = 높음 |
| **지식 레퍼런스** | 실험 플랫폼 벤더의 성공 사례집, 공개 케이스 스터디, 업계 벤치마크 리포트 | 수치 있는 케이스 = 중~높음 |
| **행동경제학 근거** | 적용한 전술의 원리와 대표 연구. 소비심리학·인지과학 논문 | 이론만 있으면 중간 |
| **자사 과거 실험** | 같은 지면 또는 유사 지면에서 과거 실험 결과 데이터. 실패 실험도 근거가 됨 | 자사 데이터 = 가장 높음 |
| **UT/정성** | 솔루션 시안을 사용자에게 보여주고 반응 관찰. 5명이면 충분 | 직접 관찰 = 높음 |
| **담당자 과거 경험** | 담당자가 이전 조직·다른 지면에서 해본 결과 데이터 | 기억 수준이면 낮음 |

**정량 근거 확보 방법**

- 자사 퍼널 데이터에서 해당 구간의 현재 전환율과 이탈률
- 업계 벤치마크 대비 Gap 배수 계산 (예: 현재 0.25% vs 업계 중앙값 2.5% = 10배 낮음)
- 유사 실험의 개선율 (예: 개인화된 CTA는 일반 대비 +202% — Whitehat SEO 2025 인용)
- 자사 상위 코호트와의 Gap (같은 지표를 잘하는 사용자군은 무엇이 다른가)

**정성 근거 확보 방법**

- UT 5명 — 솔루션 시안 노출 후 첫 반응과 발화 기록
- VOC·CS 인입 로그에서 같은 불편을 표현한 문장 수집
- 사용자 빙의 자체 UT — 팀원이 타겟 세그먼트로 가장해 직접 플로우 통과
- 경쟁사 리뷰·커뮤니티에서 같은 문제 언급 빈도

**Counter Rationale.** 실험 준비 완료 단계에서는 "실패 가능성"도 함께 적는다. 이 솔루션이 안 통할 시나리오와 그때 무너질 지표(Guardrail 후보)를 한 줄씩 쓴다. Counter Rationale이 없는 설계서는 그루밍 리뷰에서 Critical 처리된다(자세한 기준은 05 챕터).

## 절차

### Step 1. 입력 점검

2단계 산출물을 확인한다. 없으면 3단계를 시작하지 않는다.

- 고객 언어로 쓰인 문제 문장 (공급자 언어면 되돌린다)
- 각 문제의 BIAS 단계 태그
- 문제 Impact 점수 + 우선순위 1군 목록
- 대상 화면 스크린샷 또는 실제 플로우 기록

### Step 2. 병목 단계 확인

우선순위 1군 문제 중 가장 앞 단계(Block > Interpret > Act > Store)의 문제부터 착수한다. 앞 단계 실패가 더 치명적이며, 뒤 단계를 아무리 고쳐도 앞에서 차단되면 효과가 나오지 않는다.

### Step 3. 전술 선정

매핑 테이블에서 해당 문제 유형의 1순위 전술을 선정한다. 문제 단계와 전술 단계가 일치하는지 확인한다.

### Step 4. 솔루션 발산 (문제당 2개 이상)

선정한 전술을 적용해 "기존 화면(Control)을 어떻게 수정할 것인가"를 구체적으로 서술한다. 이때 문제를 검증하며 떠오른 다른 대안도 함께 적는다. 여기서 나온 대안들은 즉시 실험하지 않더라도 백로그에 넣는다.

### Step 5. Variant 발산 (단일 축)

가장 유망한 솔루션 1개를 골라, 단일 축을 정하고 Control + 처치 2개 이상으로 나눈다. 불변 기준(문제·타겟·Metric·트리거) 4개가 모든 Variant에서 동일한지 확인한다.

### Step 6. Rationale 확보

Variant마다 근거 유형 표를 채운다. 최소 1개 유형은 반드시 있어야 하며, 실험 준비 완료 단계라면 3개 유형 이상을 권장한다. 정량 근거(벤치마크 Gap, 유사 실험 개선율)를 최소 1개 포함시킨다.

### Step 7. 출력 정리

솔루션 카드 형식으로 정리해 4단계(PSR 가설화)로 넘긴다.

### 체크리스트 — 3단계 완료 판정

**전술·솔루션**

- [ ] 모든 솔루션에 BIAS 전술이 명시되어 있는가
- [ ] 전술의 BIAS 단계와 문제의 BIAS 단계가 일치하는가 (Block 문제에 Social Proof만 = Fail)
- [ ] 문제당 솔루션이 2개 이상인가
- [ ] 솔루션이 "개선한다"가 아니라 "어떻게(How)"까지 서술되었는가

**Variant**

- [ ] Control 외 처치 Variant가 2개 이상인가
- [ ] 처치 Variant들이 단일 축으로만 다른가
- [ ] 불변 기준 4개(문제·타겟·Metric·트리거)가 모든 Variant에서 동일한가
- [ ] Variant마다 System 1 공략 포인트가 한 문장으로 적혔는가
- [ ] MVP 관점에서 뺄 수 있는 요소를 점검했는가

**Rationale**

- [ ] 근거 유형이 1개 이상(실험 준비 완료 단계면 3개 이상) 있는가
- [ ] 정량 근거(벤치마크 Gap 또는 유사 실험 개선율)가 최소 1개 있는가
- [ ] 각 근거에 출처(URL·문서명·데이터 조회 조건)가 붙어 있는가
- [ ] Counter Rationale(실패 시나리오)을 검토했는가

## 워크드 예시

> 예시 1·2는 설명을 위해 지어낸 가상 예시이고(업종·수치·발화 모두 실제 사례가 아니다), 예시 3은 자사 블로그를 소재로 한 예시다(수치는 설명용 가상값).

### 예시 1. 중고 거래 앱 — 상품 상세의 판매자 신뢰 부족 (Act 단계)

**입력 (2단계 산출물)**

| 항목 | 내용 |
|---|---|
| 문제(고객 언어) | "처음 거래하는 사용자는 이 판매자를 믿어도 되는지 확신이 없어, 상품 상세에서 채팅을 시작하지 못한다" |
| BIAS 태그 | Act — 신뢰 부족 |
| 문제 Impact | 8 / 10 (첫 거래 사용자가 상세 트래픽의 다수, 상세 → 채팅 구간 이탈이 퍼널 최대) |
| 정성 근거 | 인터뷰에서 "사기일까 봐 판매자 프로필을 따로 찾아봤다"는 발화 반복 |

**Step 3 — 전술 선정.** Act 단계 "신뢰 부족" → 1순위 Social Proof (2순위 없음).

**Step 4 — 솔루션 발산 (2개)**

- 솔루션 1: 이 판매자와 거래한 사람들의 최근 후기를 상세 화면 안에서 바로 보이게 한다 (Social Proof — 동료 사용자 증거)
- 솔루션 2: 본인 인증·누적 거래 수 같은 플랫폼 인증 표시를 판매자 이름 옆에 둔다 (Social Proof — 권위 증거)

두 솔루션 모두 Social Proof지만 **증거의 출처**가 다르다(또래 vs 권위). 이 차이 자체가 검증 가치가 있으므로 두 솔루션을 한 실험의 두 처치군으로 배치한다.

**Step 5 — Variant 구성.** 단일 축 = ① 핵심가치(어떤 종류의 신뢰 증거가 통하는가).

| 구분 | 솔루션 | 노출 요소 | System 1 공략 포인트 |
|---|---|---|---|
| Control | 현재 상세 그대로 | 후기는 판매자 프로필에 들어가야 보임 | 확인 비용이 커서 신뢰 검증 자체가 일어나지 않음 |
| 처치 A | 거래 후기 미리보기 | 최근 거래 후기 2개를 가격 아래에 노출 | "나 같은 사람이 이미 거래했다" → 판단 위임으로 불안 감소 |
| 처치 B | 플랫폼 인증 표시 | 본인 인증·거래 횟수 배지를 판매자 이름 옆에 노출 | "플랫폼이 확인했다" → 권위에 기댄 위험 회피 완화 |

불변: 문제(첫 거래 사용자 신뢰 부족) / 타겟(첫 거래 사용자) / Primary Metric(상품 상세 → 채팅 시작 전환율) / 트리거(상품 상세 진입 시).

**Step 6 — Rationale**

| 근거 유형 | 내용 |
|---|---|
| 행동과학 원리 | Social Proof — 불확실 상황에서 타인의 행동을 판단 기준으로 삼음 |
| 경쟁사/업계 사례 | 거래 플랫폼 상위 3곳 모두 상세 화면에서 판매자 신뢰 정보를 바로 보여줌 |
| 자사 과거 실험 | 판매자 응답 속도 표시 실험에서 채팅 시작률이 소폭 올랐던 기록 → 판매자 정보가 행동을 움직인다는 근거 |
| 정량 벤치마크 Gap | 첫 거래 사용자의 채팅 시작률이 거래 경험 사용자의 절반 수준 |
| Counter Rationale | 후기 미리보기가 상품 상태·거래 방법 정보를 아래로 밀면 오히려 문의가 줄 수 있음 → 스크롤 깊이·상품 상태 영역 노출률을 Secondary로 관찰 |

**학습으로 이어진 결과.** 또래 증거와 권위 증거는 사용자의 거래 경험에 따라 반응이 갈리기 쉽다. 전체 평균만 보면 둘 다 미미해 보일 수 있으므로, 설계 단계에서 「첫 거래 여부」로 세그먼트 분석 계획을 미리 넣어둔다.

### 예시 2. B2B SaaS 무료체험 — 가격 페이지 방문자의 체험 시작 동기 부재 (Block 단계)

**입력.** 문제: "가격 페이지에 온 방문자는 이 도구가 우리 팀에 왜 필요한지 답을 찾지 못한 채 떠난다." BIAS: Block(자기 관련성·가치 제안 부재).

**전술 선정.** Block "가치 제안이 불명확함" → 1순위 Pattern Interrupt, 2순위 Visual Cueing. 다만 이 문제는 "무엇을 말할 것인가"가 미정이므로, 먼저 ① 핵심가치 축을 검증한다.

**Variant 구성 (단일 축 = ① 핵심가치)**

| 구분 | 솔루션 | 핵심 소구 메시지 | System 1 공략 포인트 |
|---|---|---|---|
| Control | 현재 가격 페이지 그대로 | 플랜별 기능 비교표만 있음 | 우리 팀에 필요한 이유가 보이지 않아 판단 자체를 미룸 |
| 처치 1 | 시간 절감 헤드라인 | "주간 보고 작성 시간을 줄여 준다" | 당장 줄어드는 수고 → 즉각적인 효용으로 해석 |
| 처치 2 | 협업 품질 헤드라인 | "팀 전체가 같은 숫자를 보고 일한다" | 팀이 일하는 방식과 맞닿음 → 관여도 상승 |

**후속 실험으로의 연결.** 처치 2만 유의하게 이겼다면 다음 질문은 "협업 가치를 어떤 증거로 보여줄 때 더 잘 통하는가"로 좁혀진다. 이때는 처치 1을 빼고, 협업 가치 안에서 다시 단일 축(고객 팀의 사용 장면 vs 권한·보안 관리 설명)으로 2-Variant를 구성한다. 3단계는 한 번 하고 끝나는 단계가 아니라, 결과 학습이 다음 3단계의 입력이 되는 순환 구조다.

### 예시 3. 자사 — 블로그 하단 CTA 부재

자사 블로그를 소재로 한 예시이며 수치는 설명용 가상값이다.

- **문제(Block + Act):** 블로그 글을 읽은 사용자가 "다음 행동"으로 넘어갈 문이 없다. CTA가 DOM에 존재하지 않아 클릭 자체가 불가능하다.
- **적용 전술:** Goal Gradient(콘텐츠 소비 완료 시점에 자연스러운 다음 단계 제시) + Framing Effect(범용 CTA를 주제 맞춤 문구로 재프레이밍) + Social Proof("여러 기업이 마켓핏랩과 함께 성장했습니다")
- **Variant 구성:** Control(기존 유지) / Variant A(범용 CTA 카드) / Variant B(인지 단계 × 솔루션 대분류 2축 맞춤 CTA)
- **설계 의도:** A로 "CTA 추가 자체의 효과", B로 "개인화 추가 효과"를 분리 측정. 두 축을 한 Variant에 섞지 않고 A/B로 나눈 것이 핵심.
- **Rationale:** 개인화된 CTA는 일반 CTA 대비 +202% 전환 개선(Whitehat SEO 2025) / B2B 블로그 CTA 클릭률 중앙값 2.5~3.0%(가상 벤치마크) 대비 현재 0.25% = 10배 낮음 / HubSpot·Intercom 블로그는 본문 하단 Primary CTA가 표준 패턴

## 코칭 활용 포인트

### 세션 운영

- **전술 라이브러리는 인쇄해서 책상에 둔다.** 아이데이션 세션에서 참가자가 12종 표를 손에 들고 있는 것과 아닌 것의 산출물 차이가 크다. 화면 공유로만 보여주면 안 본다.
- **문제 카드 → 전술 카드 매칭 게임으로 진행한다.** 2단계 산출물인 문제 문장을 포스트잇에 적어 벽에 붙이고, 참가자가 12종 전술 카드를 골라 붙이게 한다. 단계 불일치가 눈에 보여 자연스럽게 교정된다.
- **"단일 축" 원칙은 실패 사례로 가르친다.** 문구·컬러·위치를 동시에 바꾼 Variant를 먼저 보여주고 "이게 이기면 뭘 배웁니까?"를 물으면 대부분 스스로 답을 찾는다. 원칙을 먼저 말하면 잔소리로 들린다.
- **Rationale 찾기에 15분 타임박스를 준다.** 경쟁사 3곳 스크린샷 + 벤치마크 수치 1개면 충분하다. 완벽한 근거를 찾으려다 아이데이션이 멈추는 게 더 큰 손해다.

### 흔한 수강자 질문

**Q. 전술을 여러 개 겹쳐도 되나요?**
된다. 다만 무엇이 효과를 냈는지 분리 측정이 불가능해진다. 지표 개선이 급하면 조합, 전술 자체를 학습하고 싶으면 단일. 조합했다면 결과 보고서에 "전술 분리 미검증"을 명시한다.

**Q. 우리 브랜드는 희소성·긴급성 문구를 못 씁니다.**
브랜드 가이드가 특정 전술을 막는 것은 흔하다. 그럴 때는 매핑 테이블의 2순위로 내려간다. "긴급성 부재" 문제라면 Loss Aversion 대신 Social Proof로. 전술이 막힌 것이지 문제가 사라진 것은 아니다.

**Q. Variant를 몇 개까지 만들어야 하나요?**
Control + 처치 2개가 기본이다. 처치가 3개를 넘으면 그룹당 샘플이 부족해져 기간이 폭발한다. 6단계 샘플사이즈 계산에서 자동으로 걸리므로, 발산 단계에서는 넉넉히 만들고 설계 단계에서 잘라낸다.

**Q. 경쟁사가 아무도 안 하는 솔루션인데요.**
Confidence가 낮게 나오는 것이 정상이다. 낮은 Confidence 자체가 문제는 아니고, 낮은 Confidence를 인지하지 못한 채 높은 우선순위를 주장하는 것이 문제다. 대신 UT 5명으로 정성 근거를 빠르게 확보하면 Confidence를 올릴 수 있다.

### 흔한 실수

| 실수 | 교정 |
|---|---|
| 문제 없이 솔루션부터 시작 | 2단계 산출물이 없으면 3단계를 시작하지 않는다. "이거 해보고 싶어요"는 가설이 아니다 |
| 단계 불일치 전술 적용 | Block 문제(안 보임)에 Social Proof(신뢰 보강)를 붙이는 사례가 가장 많다. 안 보이는 것에 내용을 더해도 안 보인다 |
| 솔루션 1개만 만들고 넘어감 | 대안 2개 이상 규칙을 강제한다. 대안이 있어야 ICE 비교가 되고, 첫 안이 Ease에서 막힐 때 대체재가 있다 |
| Variant를 여러 축으로 변형 | 단일 축 원칙. 축이 여러 개면 별도 가설로 쪼갠다 |
| Rationale에 "고객에게 좋을 것 같아서" | 출처가 붙지 않은 문장은 근거가 아니다. 최소 경쟁사 스크린샷 1장 |
| Curiosity Gap을 낚시로 사용 | 질문의 답이 같은 화면에 없으면 Store 단계가 손상된다. 클릭률은 오르고 이탈률도 오른다 |
